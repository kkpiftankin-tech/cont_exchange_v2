# Маршрутизация задач и вызов субагентов

Цель — минимально достаточная глубина: не пропустить существенное и не тратить
контекст на лишнее. Сначала классифицируй задачу, затем выбирай исполнителей.
Обоснование и цифры — см. `incoming-docs/` (конспект «Золотая середина в вызове
агентов Claude Code»).

## 1. Класс изменения — определи до начала работы и назови в плане

| Класс | Признак | Маршрут |
|---|---|---|
| S | diff описывается одной фразой; не затронуты контракты, схемы БД, формулы, денежные поля, ADR | делай сам, без субагентов |
| M | меняется поведение внутри существующей фичи F-XX; контракты и схемы прежние | 1–2 профильных агента по триггерам §2 |
| L | новый или изменённый контракт, таблица, формула, инвариант, ADR | мини-конвейер только по затронутым уровням (см. §11.1 [CLAUDE.md](../../CLAUDE.md)) |
| XL | новая фича F-XX | `sdlc-coordinator` + полный SDLC, только по явной просьбе пользователя или через `/create-feature` |

Сомневаешься между соседними классами — бери меньший и эскалируй по §2.
Docs-first (`.claude/rules/docs-as-code.md`) применяй полностью к L и XL. Для S и M
обнови только затронутые документы: карточку вычисления `docs/04-domain/calculations/CALC-*`
(если она есть у величины), `feature.yaml`, журнал `docs/feedback/`.

## 3. Правила делегирования

- **Триггер из §2 сработал → вызови агента сейчас, не спрашивай
  разрешения.** «Не вызывай агентов для полноты» (ниже) относится к
  необязательным, инициативным вызовам — она не отменяет и не смягчает
  обязательные триггеры §2. Если money-path/security/contract триггер
  обнаружен, у тебя есть ровно два допустимых хода: (а) вызвать
  соответствующего агента, или (б) явно и конкретно объяснить пользователю,
  почему проверка не нужна именно сейчас (docs-only diff, чистый revert,
  агент уже отработал в этой сессии по этому же diff). «Спросить
  пользователя, что делать» — **не третий вариант**: это уклонение от
  обязательного минимума, который и существует для того, чтобы не зависеть
  от того, вспомнит ли кто-то его руками запустить (см. `money_path_guard.py`
  — он потому и реализован как блокирующий Stop-хук, а не напоминание).
- Субагент нужен, когда работа изолируема: много чтения при коротком выводе,
  независимая проверка, особые ограничения инструментов (read-only ревью).
  Последовательные шаги с общим контекстом, правку одного файла и точечный
  поиск (`Grep`) делай сам, в главном диалоге.
- Не вызывай агентов «для полноты». В плане для каждого вызова укажи: зачем,
  какие файлы передать, что вернуть и в каком объёме (до 30 строк на агента).
- Поручение агенту: цель, пути к файлам, формат ответа, границы (что НЕ делать).
- Независимые проверки разных слоёв — параллельно (один вызов Agent с
  несколькими блоками), зависимые — последовательно.
- `code-reviewer` и `security-reviewer` сообщают только о дефектах корректности
  и нарушениях требований; стилистику — не более одной строки, необязательно.
- `sdlc-coordinator` — только для класса XL или по прямой просьбе пользователя
  начать/продолжить фичу F-XX целиком. Он не пишет код и не вызывает других
  агентов сам (нет инструмента `Agent`) — он возвращает план, который исполняет
  главный диалог.
- `docs-ingestion-engineer` — только по явной просьбе обработать входящий
  документ (`incoming-docs/*.md`), не для правок docs/ во время обычной работы
  над кодом.
- **Находка ревью/анализа не остаётся только в ответе агента.**
  `code-reviewer`, `trading-domain-specialist`, `security-reviewer`,
  `solution-architect` — read-only (без `Edit`/`Write`), поэтому не могут
  записать свою находку сами. Если их отчёт указывает на: (а) вопрос, который
  должен решать эксперт/владелец, а не инженер — допиши `OQ-*` в
  `docs/02-system/features/F-XX/open-questions.md` по шаблону
  (`docs/00-methodology/artifact-templates.md` "Open Questions Template"),
  создав файл, если его ещё нет; (б) инженерный долг без нужды в
  экспертном решении — допиши в `docs/00-methodology/known-gaps.md`
  «Конкретные долги». Сделай это ДО конца хода, не только в чате — иначе
  находка существует только в транскрипте и исчезает из поля зрения.
  После — `python3 tools/expert_review_report.py --write`, чтобы сводный
  отчёт (`docs/traceability/expert-review-report.md`) отражал текущее
  состояние.
- Перед просьбой «проверь в браузере» / «посмотри на дев-стенде» — сначала
  `/rebuild-service <сервис>` для затронутых сервисов (навык сам проверяет
  журнал сборки), иначе показываешь пользователю старый бинарник.
