# /experiment — автоформирование выжимки прогона для эксперта

Назначение: закрыть требование владельца «нужна **генерация** документов в
отдельном каталоге для анализа экспертом по трейдингу» — причём документов,
которые эксперт реально может читать без знания внутренней модели CE.
Журнал не пишется руками — каркас выжимки формируется из **живых данных
dev**, человек добавляет только «Вывод» и, если нужно, «Вопросы для эксперта».

**Правило языка (2026-10-27, обязательное).** Основной текст выжимки — только
термины алготрейдинга: P&L, позиция/риск, исполнение, волатильность, спред,
базис, проскальзывание, издержки хеджа. Запрещены в основном тексте (можно
только в блоке `[для инженера]` внизу файла — см.
`docs/experiments/_template.md`): имена ENV-флагов (`CE_...`, `VENUES_...`),
номера ADR как единственное объяснение, внутренние обозначения (`W·c`, `γ_A`,
«узел», «причина N»), SQL/таблицы/имена колонок. Если нужно сослаться на
конкретную правку — опиши её смысл словами, флаг/ADR — в скобках как
техническая деталь, не как главное слово.

Вход: `$ARGUMENTS` — свободный текст **на языке трейдинга**. Выдели из него
(или спроси кратко, если неясно): **гипотезу** прогона (что проверяем в
терминах поведения рынка/риска, не «проверить флаг X»), **что менялось**
(как изменилось поведение системы словами — «арбитражёр перестал выходить на
открытый рынок», не `CE_ARB_MARKET_HEDGE=0`), **окно** SQL (деф `6 hours`),
**id** (деф `ГГГГ-ММ-ДД-ЧЧММ`). Если пользователь дал в `$ARGUMENTS` только
системное имя — переформулируй в `HYP`/`CHANGE` на языке трейдинга сам, но
сохрани техническое соответствие в скобках. «Вывод»/решение по умолчанию
оставь «(заполнить вручную)», если пользователь не дал.

## Шаг 1. Синхронизировать генератор на dev

Генератор `Testing/ce_experiment_summary.sh` читает живой dev (docker/psql). На
dev синхронизируй **только** этот скрипт (НЕ `.env-example` — память
[dev-env-file-is-envexample]):

```bash
rsync -a Testing/ce_experiment_summary.sh nik@ubuntu-dev:/home/nik/cont_exchange_v2/Testing/
```

## Шаг 2. Прогнать генератор на dev, захватить вывод

```bash
ssh nik@ubuntu-dev "cd /home/nik/cont_exchange_v2 && \
  RUN_ID='<id>' RUN_DATE='<дата>' WINDOW='<окно>' \
  HYP='<гипотеза>' CHANGE='<что менялось>' DECISION='<вывод или (заполнить вручную)>' \
  bash Testing/ce_experiment_summary.sh"
```

Вывод состоит из markdown-выжимки и последней строки `JOURNAL_ROW: | … |`.

## Шаг 3. Разложить вывод в репозиторий (локально)

1. **Выжимка** — всё, КРОМЕ строки `JOURNAL_ROW:`, запиши в
   `docs/experiments/EXP-<id>.md` (Write).
2. **Строка журнала** — содержимое после `JOURNAL_ROW: ` (начинается с `| `)
   допиши последней строкой таблицы в `docs/experiments/journal.md` (Edit:
   добавь после последней существующей `| …` строки).

Генератор на dev — журнал/файлы НЕ трогает (журнал живёт в локальном репо);
раскладку делает этот скилл.

3. **Индекс для эксперта.** `python3 tools/experiments_index.py --write` —
   обновляет таблицу прогонов в `docs/experiments/README.md` (новый
   `EXP-<id>.md` должен в ней появиться). Открытые вопросы (шаг 5) этот
   индекс подхватит автоматически при следующем запуске — после шага 5
   запусти его ещё раз.

## Шаг 4. Доложить и предложить «Вывод»

Сообщи пользователю на языке трейдинга (не «W·c нарушен», а «найдена
незахеджированная скрытая позиция»): путь к `EXP-<id>.md`, ключевые цифры по
P&L/риску/исполнению, что раздел «Вывод» ждёт его решения (принять/отклонить
гипотезу, следующее действие). Если пользователь дал вывод в `$ARGUMENTS` — он
уже вписан.

## Шаг 5. Сформировать вопросы для эксперта (если есть)

Прочитай получившийся `EXP-<id>.md` целиком, не только цифры. Если «Проверки
целостности» нарушены, в «Что пошло не так» есть реальная аномалия, или
вывод неочевиден без решения о допустимом риске/экономической политике —
сформулируй 0–3 коротких концептуальных вопроса **на языке трейдинга**
(пример: «Приемлемо ли, что при тихом рынке переводчик и арбитражёр на одной
бирже торгуют друг против друга вместо рынка — это съедает маржу или это
нормальный побочный эффект модели?» — НЕ «правильно ли T vs A нетто по
venue»). Не выдумывай вопрос, если прогон его не породил — пустой список
значит пустой список.

Для каждого вопроса:

1. Определи фичу (`F-XX`, обычно F-18 для CE-экспериментов).
2. Допиши `OQ-FXX-NN` в `docs/02-system/features/F-XX-.../open-questions.md`
   по шаблону `docs/00-methodology/artifact-templates.md` → "Open Questions
   Template" (создай файл, если его у фичи ещё нет). `Адресат:` — обычно
   «владелец» (экономическая/продуктовая политика) или `trading-domain-specialist`
   (если нужна доменная экспертиза, а не решение владельца).
3. В `EXP-<id>.md` в разделе «Вопросы для эксперта по трейдингу» замени
   «(заполнить вручную...)» на краткую формулировку со ссылкой на `OQ-*`.
4. `python3 tools/expert_review_report.py --write`, чтобы сводный отчёт
   (`docs/traceability/expert-review-report.md`) подхватил новые вопросы.
5. `python3 tools/experiments_index.py --write` — повторно (после шага 3),
   чтобы таблица вопросов в `docs/experiments/README.md` тоже подхватила
   новые `OQ-*`.

Доложи пользователю отдельно: сколько вопросов заведено и куда (пути), или
явно скажи «вопросов эксперту нет» — не оставляй находку только в чате
(`.claude/rules/agent-routing.md` §3).

## Шаг 6. Спросить про коммит

Спроси, коммитить ли выжимку + журнал (+ новые/обновлённые `open-questions.md`,
если шаг 5 что-то завёл) — коммит только по явной просьбе.

## Замечания

- Генератор даёт **каркас** на языке трейдинга (P&L, риск, позиции, исполнение
  — pending-поля для ещё не инструментированного помечены честно, без
  выдумывания цифр); системные имена (флаги, `W·c`, `γ_A`) — только в блоке
  `[для инженера]` внизу файла. Глубокий анализ (перцентили волатильности,
  модели) — по-прежнему вручную в тот же `EXP-<id>.md`, если нужен; «текста
  немного» — правило каталога.
- `docs/feedback/` — ДРУГОЙ канал (замечания с фронта/CLI, `inbox.md`→`/triage`),
  к экспертному журналу отношения не имеет. Не путать.
- Связано: навык `rebuild-service` (перед прогоном убедись, что затронутые сервисы
  пересобраны), `docs/experiments/README.md`.
