# /triage — замечания → маршрут → исполнение

Вход: `$ARGUMENTS` — путь к файлу замечаний (по умолчанию `docs/feedback/inbox.md`)
или сам текст замечания. Скриншоты приходят вложениями к сообщению. Правила
классов и триггеров — [`.claude/rules/agent-routing.md`](../../rules/agent-routing.md).

## Шаг 1. Нормализуй

Для каждого замечания заполни: id `FB-<ГГГГ-ММ-ДД>-NN`, экран (маршрут в
`frontend/web/src/pages/`), элемент, что видно, что ожидалось, важность
(блокер / важно / косметика). Ожидание формулируй проверяемо: число, текст,
состояние. Для чисел указывай входные значения, если они видны на экране.
Неясное замечание не угадывай — задай один уточняющий вопрос пользователю.

## Шаг 2. Найди место в иерархии (сам, без субагентов)

Пройди путь элемента сверху вниз, пока не станет ясен слой причины:

страница `frontend/web/src/pages/<Page>/` → клиент API `frontend/web/src/api/`
→ маршрут `frontend/api/server.js` (BFF) или `cpp/gateway/` → контракт
`contracts/proto/fob/` → сервис `cpp/<service>/` → функция.

Если элемент — вычисляемое число (PnL, VWAP, gap, fill ratio и т.п.), сначала
проверь `docs/04-domain/calculations/README.md`: если для величины уже есть
карточка `CALC-*`, сверь путь числа и формулу с ней — это обычно закрывает
триаж без единого субагента. Если карточки нет, посмотри
`docs/04-domain/business-rules.md` и при необходимости заведи карточку по
шаблону `docs/04-domain/calculations/CALC-TEMPLATE.md` как часть исполнения.

`Explore` вызывай, только если поиск требует просмотра более 10 файлов.

## Шаг 3. Классифицируй и выбери агентов

Для каждого замечания: слой, класс (S/M/L/XL), сработавшие триггеры и агенты —
каждый агент с причиной в одну строку. Агент без причины в план не попадает.

## Шаг 4. Покажи план и дождись подтверждения

Таблица: `id | суть | слой | класс | агенты | файлы | как проверим`.
Итог: число вызовов агентов и что будет сделано без них. Спроси подтверждение;
если разумно — предложи вариант глубже и вариант проще.

## Шаг 5. Исполни

- **S** — правь сам и проверь (сборка, тест или скриншот).
- **M и L** — вызывай только агентов из плана; каждому передай id замечания,
  пути к файлам и формат ответа (до 30 строк). Независимые замечания разных
  слоёв — параллельно (один вызов Agent, несколько блоков).
- **XL** — остановись и предложи `sdlc-coordinator` / `/create-feature` с
  выводами триажа вместо немедленного исполнения.
- Перед просьбой «проверь в браузере» выполни `/rebuild-service` для
  затронутых сервисов.

## Шаг 6. Журнал и документация

Допиши `docs/feedback/FB-<ГГГГ-ММ-ДД>.md` (шаблон —
`docs/feedback/inbox.md`): таблица замечаний с классом, агентами, изменёнными
файлами, обновлёнными документами и статусом.

Если изменилось вычисление — обнови его карточку `CALC-*`: формула, пример,
код, тест, статус (`implemented` / `planned` / `drift`).
