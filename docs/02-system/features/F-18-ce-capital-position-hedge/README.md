# F-18 (v2) — Виртуальные контрагенты CE: переводчики/арбитражёры, знаковая позиция агента и хедж по полосе ±q

> **Статус:** draft (docs-first). Код — после полной doc-цепочки (ADR-061 → feature → UC → sequences → contracts → data → tasks). **v2 заменяет v1** («CE Capital, Net Position & Position-Based Hedge», ADR-054). UC-F18-01..03 — superseded, сохранены для истории.

## Зачем

В v1 биржа держала капитал `K` и целевые остатки `target`, а хедж эмиттился по НЕТТО-позиции `pos_a = h_a − target_a`. Практика показала, что это переусложнено: понятия склада, целей и плечей запаса не нужны, а хедж по каждому такту порождает слишком много внешних заявок и не интернализует встречный клиентский поток.

v2 моделирует биржу как ДИЛЕРА через двух виртуальных контрагентов:

1. **Переводчики** (`Q_BIN`, `Q_KRK`) — маркет-мейкер: меняет на ОДНОЙ площадке актив на деньги.
2. **Арбитражёры** (`T_BTC`, `T_USD`) — перевозят ОДИН актив между площадками (логистика: тариф + срок, без цены).

У каждого агента позиция `c_j` **стартует с нуля**, знаковая, может быть отрицательной. Пока `|c_j| ≤ q_j` (полоса интернализации), наружу не уходит ни одна заявка — такт меняет только внутреннюю позицию агента, не владение биржи. Ни склада, ни целей, ни плечей запаса. Прибыль/невязка оседает на **счёте дома** (house).

## Что изменилось против v1

| | v1 (ADR-054/057) | v2 (ADR-061) |
|---|---|---|
| агенты | переводчики, арбитражёры, **плечи запаса (STOCK)** | только переводчики и арбитражёры |
| узлы | площадки **плюс склад** | только площадки (`актив@площадка`) |
| позиция | `владение − target`, per-asset агрегат | накопленный неисполненный поток **агента** `c_j`, знаковый |
| стартовая позиция | ненулевой разложенный капитал | **ноль** у каждого агента |
| `target` | настройка казначейства | **отсутствует как понятие** |
| `committed` | отдельно от позиции | это **и есть** позиция |
| эмиссия заявок | каждый такт по `|pos_a|>θ_a` | **только** при выходе за полосу `±q` |
| куда падает прибыль | на капитал/денежное плечо | на **счёт дома** (не агент) |
| сдвиг якоря | `ρ(Q−Q*) + ρ·committed` | `ρ·c_j` — одно слагаемое |

## Такт агентов A0–A8 (кратко)

- **A0. Вход.** Мгновенный снимок обоих стаканов. Встречный клиентский поток: клиент купил BTC → биржа отдала актив НЕМЕДЛЕННО (владение меняется сразу) и получила намерение выкупить обратно (хедж — отложенное намерение в позиции переводчика).
- **A1. Три числа кривой.** Якорь `m = 1000·ln(mid/P₀)`, консервативный наклон `α = θ·min V/d`, полка `c = комиссия + ½·|ln(ask/bid)|·1000`.
- **A2. Сдвиг якоря.** `σ*_j = m_j + ρ_j · c_j` — единственное слагаемое, от собственной позиции агента (`ρ_Q=0,004`, `ρ_T=0,002`).
- **A3. Граф баланса `W`.** Строка — узел `актив@площадка`, столбец — намерение агента (±1). Ранг `V·A−1`, независимых кругов `(V−1)(A−1)`. Столбец **house** — единственная ненулевая клетка в узле нумерария, восстанавливает ядро.
- **A4. Клиринг.** `max_f Σ[−σ*_j·f_j − c_j·|f_j| − f_j²/(2α_j)]` при `W·f=0`; закрытая форма (квадрат) сверяется с OSQP.
- **A5. Проверки.** Узловой баланс `|Wf|<1e-6`, согласие решателей, исполнимость (объём ≤95% остатка узла-источника).
- **A6. Накопление.** `c_j ← c_j + f_j`. Наружу не идёт ничего. Позиция может стать отрицательной (обещание продать раньше, чем актив доехал).
- **A7. Полоса (эмиссия).** Если свободная часть позиции (сверх покрытого `in_flight`) внутри `|c_j| ≤ q_j` — ничего; иначе отправить наружу `(|c_j|−q_j)·sign(c_j)` и пометить отправленное `in_flight`. **Позицию `c_j` в момент эмиссии НЕ трогаем** (решение владельца 2026-09-15).
- **A8. Подтверждения.** Приходы перевозов; исполнения (в т.ч. частичные): меняют `qty[asset@venue]`, `realized` **И уменьшают `c_j` и `in_flight` на `fq`**; таймауты снимают неисполненный остаток с `in_flight` (позицию не меняют). После полного исполнения `|c_j| = q_j` точно.

## Полоса как механизм эмиссии (A7)

$$
\text{если } |c_j| \le q_j:\ \text{ничего};\qquad
\text{иначе (A7): отправить } E=(|c_j|-q_j)\cdot\operatorname{sign}(c_j),\quad
\text{in\_flight} \mathrel{+}= E.
$$

$$
\text{A8, по исполнению } fq:\quad
c_j \mathrel{-}= \operatorname{sign}\cdot fq,\qquad
\text{in\_flight} \mathrel{-}= fq.
$$

Позицию `c_j` уменьшаем **по факту исполнения** (A8), а не в момент эмиссии (решение владельца 2026-09-15): при эмиссии отправленное лишь помечается `in_flight` (защита от повторной отправки). После полного исполнения `|c_j| = q_j`.

Две полосы с разным экономическим смыслом:

| Полоса | Значение | Смысл |
|---|---|---|
| `q_translator` | 18 | риск незахеджированного запаса |
| `q_arbitrageur` | 30 | размер партии перевоза (рыночного риска нет) |

## Инвариант владения и `Z_a`

Владение биржи по каждому активу меняют **РОВНО две вещи**: сделка с клиентом и исполнение на площадке. **Клиринг, накопление позиций, перевозы и таймауты владение НЕ меняют никогда.**

$$
\text{владение}_a = \sum_{\text{площадки}} qty[a@\text{площадка}] + \sum \text{in\_transit}[a],
\qquad Z_a = \text{владение}_a(t) - \text{владение}_a(0).
$$

Старт с нуля. Без встречного клиентского потока `Z_a ≡ 0` (проверяется property-тестом).

## Счёт дома (house)

House — переменная-невязка, восстанавливающая ядро `W` (в натуральных единицах `det W = (p_Kraken − p_Binance)/1000` вырождается при равных ценах). Забирает арб-прибыль (`= разница цен`). House — **НЕ агент**: нет якоря/наклона/полки/полосы, заявок не порождает. Остаток по нумерарию сметается в house.

## Эффект полосы (30 тактов)

| | с полосой q=18/30 | без полосы q=0 |
|---|---:|---:|
| внешних заявок | 31 | 80 |
| издержки хеджа | 182,73 USD | 495,06 USD |
| спред с клиентов | 465,93 | 465,93 |
| **итог** | **+203,18** | **−246,03** |

Полоса даёт **−63% издержек хеджа**. **Оговорка:** без встречного клиентского потока полоса УХУДШАЕТ результат (гасить нечего) — это не универсальный выигрыш, а механизм интернализации встречного потока.

## Тип участника AGENT

`party_type = AGENT` — отдельный от `CLIENT`/`HOUSE` тип участника в ledger. Позиция агента знаковая; резерв-чек (неотрицательность, как у CLIENT) к AGENT **не применяется** (несовместимые инварианты). House — `party_type = HOUSE`.
