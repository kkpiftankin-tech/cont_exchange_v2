## A0 — Вход: снимок обоих стаканов

### AC-F18v2-01 — единый снимок такта, stale-исключение площадки

- **Given** такт триггерится оконным снимком обоих стаканов (Binance, Kraken) с единым `batch_id`;
- **And** у одной из площадок снимок старше `venue_stale_ms` (stale-порог);
- **When** market-data формирует вход такта (A0);
- **Then** внутри такта снимок не меняется (все дальнейшие шаги A1–A8 читают один и тот же `batch_id`);
- **And** stale-площадка **исключается** из клиринг-инпута, такт **продолжается** по оставшимся узлам (не FAILED).
- **Тесты:** `E2E Testing/f18v2_ce_tact_e2e.sh` (A0..A8, шаг «up» с единым снапшотом); фильтр тонких/stale-venue — прецедент `2e4c86b2`. *(Отдельного `CHK` на A0 в плане тестов нет — покрытие через E2E; см. open-questions при появлении golden.)*
- **Статус:** ❌ planned.

## A1 — Три числа кривой агента

### AC-F18v2-02 — якорь m, наклон α, полка c

- **Given** снимок стакана площадки (mid, ask, bid, глубина `V`, шаг `d`, комиссия);
- **When** для каждого переводчика/арбитражёра строится кривая из трёх чисел (A1);
- **Then** якорь `m = 1000·ln(mid/P₀)`;
- **And** консервативный наклон `α = θ·min V/d` (эталон Binance: `θ=0,50`, `α = 0,50·71,971 = 35,986`, tol 1e-3), линия `α·d` не выше ломаной книги;
- **And** полка `c = комиссия + ½·|ln(ask/bid)|·1000`;
- **And** кривая непрерывна на `m±c` (`f(m±c)=0`, без скачка).
- **Тесты:** `CHK-01` (`AnchorFromMid`), `CHK-02` (`SlopeMinorant`), `CHK-03` (`ShelfFromFeeSpread`), `CHK-04..07` (куски/непрерывность) — `three_numbers_test`, U1/U2.
- **Статус:** ❌ planned (A1 уже корректен в коде v1 — переносится под флаг).

## A2 — Сдвиг якоря от собственной позиции

### AC-F18v2-03 — σ* = m + ρ·c, ровно одно слагаемое

- **Given** агент с собственной знаковой позицией `c_j` (видимой до накопления такта) и коэффициентом `ρ_j` (`ρ_Q=0,004` переводчик, `ρ_T=0,002` маршрут);
- **When** выполняется сдвиг якоря (A2);
- **Then** `σ*_j = m_j + ρ_j · c_j` — **единственное** слагаемое;
- **And** **нет** второго члена `ρ(Q−Q*)` и **нет** отдельного target/committed-слагаемого (проверка `c_j=+5`, `ρ_Q=0,004` → `σ*=m+0,02`).
- **Тесты:** `CHK-08` (`three_numbers_test::AnchorShiftSingleTerm`), `INV-7`, U3.
- **Статус:** ❌ planned (в текущем коде сдвиг якоря **отсутствует** — см. review §10, live-gap).

## A3 — Граф баланса W + столбец house

### AC-F18v2-04 — структура W и восстановление ядра house-столбцом

- **Given** узлы `актив@площадка` (`V` площадок × `A` активов) и намерения агентов (столбцы ±1);
- **When** собирается матрица баланса `W` + столбец house (A3);
- **Then** `rank(W) = V·A − 1`;
- **And** число независимых кругов (правое ядро) = `(V−1)(A−1)`;
- **And** левое ядро одномерно, базис `(1,…,1)` (свобода нумерария);
- **And** столбец **house** — единственная ненулевая клетка в узле нумерария, восстанавливает ядро (делает `W` обратимой).
- **Тесты:** `CHK-16..22` (ранг, ядра, счёт агентов), `CHK-25` (`HouseColumnRestoresKernel`) — `w_structure_test`, `INV-4`, U4.
- **Статус:** ❌ planned.

## A4 — Клиринг

### AC-F18v2-05 — целевая функция и совпадение closed-form с OSQP

- **Given** собранный граф `W`, сдвинутые якоря `σ*_j`, наклоны `α_j`, полки `c_j`;
- **When** выполняется клиринг (A4);
- **Then** максимизируется `Σ[ −σ*_j·f_j − c_j·|f_j| − f_j²/(2α_j) ]` при `W·f = 0`;
- **And** закрытая форма (`λ*`, три ветви `S<−C` / `S>+C` / `|S|≤C`) совпадает с OSQP в пределах **1e-9** на квадратном случае (2 площадки × 2 актива, 4 агента);
- **And** соблюдена комплементарность `x₊·x₋ = 0` (`INV-2`, tol 1e-12).
- **Тесты:** `CHK-12/13` (ветви closed-form), `CHK-14` (`ClosedFormVsOsqp`, 1e-9), комплементарность — `vector_qp_pi_test`, U6/U8; контракт-маппер `cpp/matching/tests/transport/agent_delta_mapper_test.cpp`.
- **Статус:** ❌ planned.

## A5 — Проверки перед действием

### AC-F18v2-06 — гейт активации эмиссии (иначе FAILED)

- **Given** результат клиринга такта;
- **When** выполняются проверки перед действием (A5);
- **Then** эмиссия активируется **только если** одновременно: `|Wf| < 1e-6` **И** закрытая форма == OSQP **И** объём заявки ≤ **95%** остатка узла-источника;
- **And** иначе такт помечается **FAILED**, заявки **не** эмитятся, публикуется `risk.alerts`, трасса помечена `failed`;
- **And** пустой круг (`|S| ≤ C`, круг убыточен) → нулевой поток по нему, такт продолжается (не ошибка).
- **Тесты:** `CHK-15` (`NodeBalance` `|Wf|<1e-6`), `CHK-14` (согласие решателей), `DeadZoneNoFlow` (`|S|≤C`) — `vector_qp_pi_test`, U8/U9; негативный N-1.
- **Статус:** ❌ planned.

## A6 — Накопление позиции

### AC-F18v2-07 — c_j += f_j без внешней заявки и без мутации владения

- **Given** прошедший проверки поток `f_j` такта;
- **When** выполняется накопление (A6);
- **Then** `c_j ← c_j + f_j` (полный шаг), **ни одной** внешней заявки наружу не порождается;
- **And** позиция может уйти в отрицательную зону (эталонный минимум 30-тактового прогона `≈ −18000` тыс.); требование `c ≥ 0` допускает только `c = 0` (нет оборота);
- **And** накопленная позиция лежит в ядре баланса `W·c = 0`;
- **And** владение узлов этим шагом **не** меняется (property-тест).
- **Тесты:** `CHK-28` (`Accumulation`), `CHK-29` (`KernelPreserved`, `INV-3`), `CHK-30/31` (отрицательная позиция), `CHK-39` (`OwnershipInvariant`) — `agent_band_test`, U10; `cpp/ledger/tests/app/ce_agent_position_apply_test.cpp`.
- **Статус:** ❌ planned.

## A7 — Полоса ±q (эмиссия)

### AC-F18v2-08 — эмиссия строго при |c_j|>q_j, размер по стоимости, после |c_j|=q_j точно

- **Given** агент с накопленной позицией `c_j` и полосой `q_j`;
- **When** проверяется полоса (A7);
- **Then** заявка эмиттится **строго когда** `|c_j| > q_j`;
- **And** размер = `(|c_j| − q_j)·sign(c_j)` по стоимости, переведён в `qty` итеративным walk по книге (`qty ← излишек·1000/walk(qty)`, сходимость за 2–3 итерации);
- **And** после эмиссии `|c_j_new| = q_j` **точно** (не `≤` с допуском); пример `c=25, q=18` → наружу `7`, после `c=18`.
- **Тесты:** `CHK-32` (`EmissionThreshold`), `CHK-33` (`EmissionExactBand`, `INV-6`), `CHK-35/36` (sizing/сходимость) — `agent_band_test`, U11/U12; `cpp/matching/tests/domain/ce_band_emission_test.cpp`.
- **Статус:** ❌ planned (A7-полоса в текущем коде **отсутствует**).

### AC-F18v2-09 — разные полосы по типу агента (q_translator=18, q_arbitrageur=30)

- **Given** переводчики и арбитражёры с конфигурируемыми per-agent-kind полосами;
- **When** применяется полоса (A7);
- **Then** у переводчика `q_translator = 18` (env `CE_AGENT_BAND_Q_TRANSLATOR`), у арбитражёра `q_arbitrageur = 30` (env `CE_AGENT_BAND_Q_ARBITRAGEUR`) — **не** общая константа;
- **And** переводчик не эмитит при `|c| ≤ 18`, даже если превысил бы условный `30`.
- **Тесты:** `CHK-45` (`TranslatorBandQ18`), `CHK-46` (`ArbitrageurBandQ30`), `CHK-47` (`BandTypesNotMixed`) — `agent_band_test`, U14.
- **Статус:** ❌ planned.

### AC-F18v2-10 — in_flight и декремент c_j в момент эмиссии (не по confirm)

- **Given** заявка сверх полосы, готовая к отправке;
- **When** заявка эмиттится наружу (A7);
- **Then** заявка помечается `in_flight`;
- **And** `c_j` уменьшается **в момент эмиссии** (не по confirm) — ровно на отправленное;
- **And** повторная отправка того же излишка невозможна (нет двойной эмиссии).
- **Тесты:** `CHK-34` (`EmissionReducesPosition`), `IT-CE-V2-06` (таймаут `in_flight` без re-send), U11; `E2E` шаг «нет повторной отправки».
- **Статус:** ❌ planned (декремент — при эмиссии A7, не при исполнении A8; см. review §9).

## A8 — Подтверждения / таймаут

### AC-F18v2-11 — таймаут: возврат остатка по плановой цене

- **Given** эмитированная `in_flight` заявка, не исполненная к дедлайну;
- **When** срабатывает таймаут (A8);
- **Then** неисполненный остаток возвращается в `c_j` по **ПЛАНОВОЙ** цене (цене эмиссии), не по марке на момент таймаута;
- **And** `realized` начисляется только от исполненной доли; поздний филл после таймаута возврат **не** двоит.
- **Тесты:** `CHK-37` (`TimeoutReturnsAtPlannedPrice`, `INV-8`), `IT-CE-V2-05/06` (возврат остатка / TTL) , U13.
- **Статус:** ❌ planned (жёсткий пререквизит `CE_AGENT_A8` для `CE_AGENT_BAND`; security MEDIUM-7).

### AC-F18v2-12 — confirm: меняет только qty[asset@venue] и realized, позицию не трогает

- **Given** `ExecutionReport` (fill / partial) по эмитированной заявке;
- **When** ledger применяет confirm (A8);
- **Then** меняется **только** `qty[asset@venue]` узла и `realized = fq·(марка − px_факт)/1000·sgn`;
- **And** позицию агента `c_j` confirm **не** трогает (она уже уменьшена в A7).
- **Тесты:** `CHK-38` (`HouseProfitOnFact`, `INV-9`), `IT-CE-V2-04/05` — `agent_band_test` + Kafka round-trip, U13; `cpp/ledger/tests/app/ce_agent_position_apply_test.cpp`.
- **Статус:** ❌ planned.

## Инвариант владения и Z_a

### AC-F18v2-13 — владение меняют ровно две вещи; Z_a≡0 без клиентского потока

- **Given** прогон из N тактов **без** встречного клиентского потока;
- **When** идут клиринг, накопление позиций, перевозы и таймауты;
- **Then** владение `владение_a(t) = Σqty[a@venue] + Σin_transit[a]` меняется **ровно двумя** событиями: сделка с клиентом и исполнение на площадке;
- **And** клиринг / накопление / перевоз / таймаут владение **не** мутируют никогда;
- **And** property-тест: N тактов без клиентского потока ⇒ `Z_a ≡ 0` для всех активов.
- **Тесты:** `CHK-39` (`OwnershipInvariant`, `INV-1`), `E2E Testing/f18v2_ce_tact_e2e.sh` (Z_a≡0), `cpp/risk/tests/app/ownership_invariant_test.cpp`, U13/U14.
- **Статус:** ❌ planned.

### AC-F18v2-14 — Z_a = владение(t) − владение(0); target удалён (breaking)

- **Given** модель v2 без понятия target;
- **When** вычисляется индикатор изменения владения;
- **Then** `Z_a = владение_a(t) − владение_a(0)` (старт с нуля);
- **And** `ExchangeNOP.target` **удалён** — breaking change, за флагом до миграции клиентов контракта;
- **And** consumer `AgentDelta` получает сообщение **без** поля `target`.
- **Тесты:** `IT-CE-V2-01` (`target` отсутствует, breaking), `IT-CE-V2-08` (backward-compat `AgentDelta` vs `AssetDelta`), `cpp/risk/tests/app/ownership_invariant_test.cpp`.
- **Статус:** ❌ planned.

## Счёт дома (house)

### AC-F18v2-15 — house не агент; сходимость стоимостного баланса

- **Given** остаток по узлу нумерария после клиринга;
- **When** формируется счёт дома (house);
- **Then** house — **не** агент: без якоря, наклона, полки, полосы; заявок **не** эмиттит;
- **And** остаток по нумерарию сметается в house (арб-прибыль `= p_Kraken − p_Binance`);
- **And** в стоимостных единицах баланс такта сходится ровно (double-entry, `party_type = HOUSE`).
- **Тесты:** `CHK-25` (`HouseColumnRestoresKernel`), `CHK-26` (`HouseSingleNonzeroCell`), `CHK-27` (`HouseTakesArbProfit`) — `w_structure_test`, U5; `CHK-38` (признание на факте).
- **Статус:** ❌ planned.

## Тип участника AGENT

### AC-F18v2-16 — party_type=AGENT, знаковая позиция, без резерв-чека

- **Given** участник ledger с `party_type = AGENT` (отдельный от `CLIENT`/`HOUSE`);
- **When** ledger применяет позицию агента;
- **Then** позиция агента **знаковая** (может быть отрицательной);
- **And** резерв-чек (неотрицательность, как у CLIENT) к AGENT **не** применяется (несовместимые инварианты);
- **And** позиция ключуется по `(agent_id, asset, venue)` и переживает рестарт (PG `ce_agent_position`, не in-memory).
- **Тесты:** `cpp/ledger/tests/app/ce_agent_position_apply_test.cpp`, `IT-CE-V2-02` (`GetAgentPositions`, персистентность + идемпотентный реплей), U10.
- **Статус:** ❌ planned (требует ADR-063; см. open-questions).

## Перевоз (арбитражёр)

### AC-F18v2-17 — сущность перевоза и приход по eta

- **Given** арбитражёр перевозит один актив между площадками;
- **When** формируется перевоз (Э5, `CE_TRANSFER_AGENT`);
- **Then** перевоз — сущность `{asset, src, dst, qty, eta, tariff, status}`;
- **And** приход учитывается на узле назначения при `eta ≤ t` (state machine `in_transit → delivered/timed_out → returned`);
- **And** `qty ≤ 95%` остатка узла-источника перед отправкой, иначе перевоз урезается/откладывается;
- **And** `in_transit[a]` учтён в `владение_a` (перевоз владение не создаёт и не уничтожает).
- **Тесты:** `IT-CE-V2-07` (`ce.transfers`, приход на узел по eta), Э5.
- **Статус:** ❌ planned.

## Эффект полосы

### AC-F18v2-18 — измеримый эффект полосы (−63%) с оговоркой

- **Given** фиксированный 30-тактовый прогон;
- **When** сравниваются полоса `q=18/30` и `q=0` при встречном клиентском потоке (`Z≠0`);
- **Then** число внешних заявок и издержки хеджа с полосой **строго меньше** (ориентир: 31 vs 80 заявок; издержки `182,73` vs `495,06` USD; итог `+203,18` vs `−246,03`; `−63%` издержек);
- **And** **оговорка**: без встречного клиентского потока (`Z≡0`) полоса **ухудшает** результат (гасить нечего) — документируется как ожидаемое, **не** FAIL.
- **Тесты:** `CHK-40..44` (`Band30_*`), `CHK-48` (`BandHurtsWithoutClientFlow`), `E2E Testing/f18v2_band_vs_no_band_30_ticks.sh`, `E2E Testing/f18v2_no_client_flow_e2e.sh`, U14.
- **Статус:** ❌ planned (golden `square_bands.py` отсутствует — калибровка допусков по факту ingestion).
