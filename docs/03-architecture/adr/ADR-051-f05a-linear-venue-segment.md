# ADR-051 — Линейный сегмент ликвидности венью (модель A)

> **Решение владельца (2026-08-28):** ликвидность стороны биржи представляется
> **ОДНОЙ линейной функцией** `p(q) = a + b·q` и даёт **один** flow-сегмент на
> `(venue, pair, side)` с реальным наклоном `b`, а не лестницей из сотен точечных
> сегментов (по одному на точку `q_grid`).

## Контекст

Текущая цепочка: F-11 отдаёт кривую венью как дискретную лестницу
`SideLiquidityCurve { q_grid[], p_of_q[] }` → `curve_to_levels` делает **уровень на
каждую точку сетки** → `Vectorize` — **сегмент на уровень**. Итог: 135–300 сегментов
на сторону венью, а кривизна `d_hl = dhl_fraction · P_eff` (фикс. доля 1 %), **не**
реальный наклон кривой. Это LOB-лестничная модель.

Постановка (владелец, academic IN-012: `p = m·q̇ + a`) требует **линейную функцию
ликвидности** на сторону венью. В QP-ядре линейность уже поддержана: маргинальная
полезность сегмента `= pH − (dHL/q)·x` — прямая; `D = diag(dHL/q)` — её наклон. Нужно
лишь **свернуть сторону венью в один сегмент с реальным наклоном**, а не в лестницу.

Конфликт: R-F05A-002 («No synthetic pair book») требует **per-level** provenance
(`source_order_id` на каждый level). Модель A агрегирует сторону → provenance
становится **per-venue-side**. Это осознанная замена (см. ниже).

## Решение

Для каждой стороны кривой `(venue, pair, side)` строить **один** `VectorFlowSegment`:

- **Anchor-цена** `P_eff = a = p_of_q[0]` (лучшая маргинальная цена, top-of-book) —
  в ней выражается `w_i` (bid: `w = e_X − a·e_Y`; ask: `w = −e_X + a·e_Y`).
- **Ёмкость** `q_max = q_grid[last]` (полная глубина стороны).
- **Наклон → кривизна:** `d_hl = |p_of_q[last] − p_of_q[0]|` — ценовой диапазон по всей
  глубине (= `|b|·q_max`). Тогда `D = d_hl / q_max = |b|` — **реальный** наклон
  price-impact кривой венью (а не фикс. доля).
- **Provenance:** `venue_id`, `pair`, `side` сохраняются; `source_order_id =
  "venue|pair|side|linear"` (агрегат стороны).
- Вырожденные случаи: пустая сторона / `q_max≤0` / неконечные → сторона пропускается.

За флагом **`F05A_LINEAR_SEGMENTS_ENABLED`** (default off; on в dev). off → прежняя
per-level лестница (модель B, для сравнения/rollback). Композируется с ADR-050:
оконный агрегатор скармливает эти линейные сегменты `Vectorize` над общим basis.

### Поправка к R-F05A-002

При включённой модели A правило «каждый external level — отдельный столбец `W`»
заменяется на «каждая **сторона кривой венью** — отдельный столбец `W` (линейный
сегмент с наклоном `b`)». Инвариант «No synthetic pair book» сохраняется (сегмент
привязан к реальной `(venue, pair, side)`, синтетическая пара-книга не создаётся).
Трассировка — до `(venue, pair, side)`, а не до отдельного level.

## Альтернативы

- **(B) Per-level с реальным наклоном** — оставить сегмент на level, но брать `d_hl`
  из локального `p_of_q`, а не фикс. долю. Точнее по форме кривой, но сотни сегментов
  на венью и лишняя дискретизация; отвергнуто владельцем в пользу A.
- **(C) Оставить как есть** (фикс. `dhl_fraction`, лестница) — не отражает реальный
  price-impact, не соответствует постановке. Отвергнуто.

## Последствия

**Положительные**
- Модель ликвидности венью = линейная функция с **реальным наклоном** (постановка).
- Резко меньше сегментов: сторона венью = 1 сегмент (было 135–300) → чище QP, быстрее.
- `d_hl` интерпретируем: диапазон проскальзывания по всей глубине стороны.

**Требуют внимания**
- Provenance грубее: до `(venue, pair, side)`, не до level (поправка R-F05A-002).
- Линеаризация теряет нелинейность/выпуклость кривой (F-11 L2 может быть выпуклой) —
  для линейной модели это by design; при необходимости — piecewise-linear (future).
- `ExternalOrderLevel` получает поле `d_hl_override` (0 = policy) — `Vectorize`
  использует его вместо `dhl_fraction·P_eff`.

## Обратимость

Высокая: флаг `F05A_LINEAR_SEGMENTS_ENABLED` (default off) → мгновенный откат к
per-level. Аддитивное поле `d_hl_override` не ломает существующий путь.
