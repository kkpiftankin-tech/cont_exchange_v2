# ADR-052 — Двусторонняя кривда венью (academic signed clearing)

> **Решение владельца (2026-08-28):** кривая ликвидности венью — **ОДНА**
> двусторонняя (`p(q̇) = m·q̇ + a`, `q̇` знаковая: покупка `q̇>0` / продажа `q̇<0`,
> якорь `a = mid`), один сегмент на `(venue, pair)` со знаковым `x`, а не два
> односторонних (bid+ask).

## Контекст

Постановка имеет два уровня (сверка IN-012/entities.md vs IN-014/proto):
- **Математика клиринга (academic §5.1.1, `entities.md:148-150` «−a·q̇ — signed
  external anchor»):** одна двусторонняя кривая, знаковая `q̇`, `a=mid`, клиринг
  `Σq̇=0`, `p*=a*`.
- **Контракт (IN-014):** две односторонние (bid/ask), `0≤x≤q`, направление в знаке `w`.

ADR-051 дал линейный сегмент **на сторону** (2/венью). Владелец требует канонику:
**одна кривда/венью** со знаковым потоком.

**Ключевой результат (обоснование выбора формы).** Наивное слияние сторон с реальной
ценой в `w` (`w=e_X−P·e_Y`) и точным `Wx=0` даёт **`x=0` всегда**: для 2 венью баланс
по base И по quote при разных `mid` форсирует `x=0`. Поэтому нужна academic-форма, где
цена-якорь `a` уходит в **целевую**, а `w` — чистое направление.

## Решение

**Academic QP (модель C):**

    min_x  Σ_i [ ½·m_i·x_i² + a_i·x_i ]   s.t.   W·x = 0,   x_min ≤ x ≤ x_max

- `w_i` — **чистое направление** пары (`e_X − e_Y`), а НЕ `e_X − P·e_Y`.
- `a_i = mid_i` (якорь = mid венью) — в целевой (линейный член).
- `m_i` — наклон кривой (price-impact); `P = diag(m_i)`, `q_vec = a` (standard-form OSQP).
- Знаковый box: `x_min = −Q_bid`, `x_max = +Q_ask` (продажа/покупка).
- **Клиринговая цена `p*` = двойственная переменная баланса** (не `pi[base]/pi[quote]`,
  т.к. `w` нормирован). `x_i = (p* − a_i)/m_i` (закрытая форма academic §5.1.1).

Реализация — **market_data** (один двусторонний сегмент/венью: mid, m, `x_min/x_max`,
pure-direction `w`) + **matching** (`vector_qp_solver`: academic AssembleProblem —
`P=diag(m)`, `q=a`, знаковый box; `p*` из дуальной). За флагом
**`F05A_TWO_SIDED_ENABLED`** (default off; on в dev). Композируется с ADR-050 окном.

**Валидация (гейт корректности):** unit-тест против academic closed-form — 2 венью с
`(a1,m1),(a2,m2)` → `x_i=(p*−a_i)/m_i`, `p*=(Σa/m)/(Σ1/m)`. Ловит ошибки математики
локально в сборке (до деплоя).

### Поправка провенанса

Сегмент привязан к `(venue, pair)` (обе стороны). Провенанс до level/side теряется
(vs R-F05A-002/ADR-051); синтетическая пара-книга не создаётся.

## Альтернативы

- **A/B (ADR-051, per-side линейный)** — 2 сегмента/венью; не «одна кривая».
- **Value-conserving two-sided (цена в `w`, surplus)** — физичнее, но `x=0` под точным
  `Wx=0` (арбитраж уходит в surplus/ADR-047, сложнее); отвергнуто в пользу academic-каноники.
- **C (принято)** — academic signed: одна кривда, знаковый `x`, closed-form-проверяемо.

## Последствия

- Одна кривая/венью (каноника постановки); знаковый `x` (покупка/продажа на одной кривой).
- Кросс-venue и треугольный арбитраж → **ненулевой** `x` при разных mid.
- `vector_qp_solver` получает academic-ветку (P=diag(m), q=+a, знаковый box); proto
  `VectorFlowSegment` += `q_min`. Клиринговая цена — из дуальной `p*` (UI-адаптация).
- Провенанс грубее (venue, не level).

## Обратимость

Флаг `F05A_TWO_SIDED_ENABLED` (default off) → откат к ADR-051/per-side. Поле `q_min`
аддитивно. Academic-ветка не трогает F1-путь при выключенном флаге.
