# ADR-055 — Виртуальные контрагенты CE как агенты

> **Решение владельца (2026-09-10, `CE_virtual_counterparties.md` §1–5).** Виртуальный
> контрагент (ВК) — это **строка клиринга, за которой стоит сама биржа**, а не клиент.
> Типов ВК ровно два: **переводчик** (translator) и **связка-арбитражёр** (link).
> Никакого «зеркального правила»: поток агента `f_e` — это и есть инструкция на
> исполнение в собственном знаке биржи.

## Контекст

Режим «без клиентов»: внешняя ликвидность приходит стаканами площадок, и биржа сама
выступает контрагентом. Прежняя формулировка (ADR-052) даёт одну двустороннюю кривую
на `(venue, pair)`, но не различает роли (торговля в книге площадки vs физический
перевод монет между площадками vs изменение собственного остатка). `CE_virtual_counterparties.md`
уточняет: ролей ровно две, и обе описываются **одной** кривой, различаясь лишь числами
`α` (глубина) и `c` (мёртвая зона).

Из документа (проверяемое следствие §7): без плеча запаса `Σ_j f(quote a@j) ≡ 0`, то
есть позиция биржи тождественно ноль по построению — это делает метрику NOP измерением
инварианта, а не риска. Поэтому роль «STOCK» (собственный остаток) — не украшение, а
условие работоспособности переводчиков.

## Решение

**Единая кривая агента с мёртвой зоной (Ф1):**

    f_e(σ) = α_e · sign(σ*_e − σ_e) · max(0, |σ*_e − σ_e| − c_e)

- `σ_e` — курс клиринга на ребре агента (разность потенциалов узлов, ADR-056);
- `σ*_e` — якорь (для QUOTE `= mid` площадки; для TRANSFER/STOCK — паритет 0, сдвинутый
  на давление собственного остатка `−ρ·(Q−Q*)`);
- `α_e` — глубина (для QUOTE `= θ·минорант_книги`; для TRANSFER/STOCK `= W/(γσ²τ)`);
- `c_e` — мёртвая зона (QUOTE: комиссия+полуспред; TRANSFER: тариф ввода/вывода+плата за
  время в пути; STOCK: полоса риск-аппетита);
- **мёртвая зона — ВНУТРИ кривой**, а не фильтр после клиринга (иначе выброшенная нога
  рвёт баланс — `CE_virtual_counterparties.md` §2.1).

**Три плеча агентов:**

| Плечо | Ребро | Владелец | Смысл |
|---|---|---|---|
| `QUOTE` | `BTC@j ↔ USDT@j` | переводчик площадки `j` | сделка в книге `j` |
| `TRANSFER` | `X@j ↔ X@k` | связка-арбитражёр | физический перевод валюты |
| `STOCK` | `X@j ↔ X@__book__` | переводчик узла `j` | изменение собственного остатка |

Переводчик = QUOTE + STOCK плечи; связка = TRANSFER. Третьего типа агента не заводим:
запас — это STOCK-плечо переводчика.

**Знаковое соглашение (§5):** поток `f_e` пишется «из первого узла ребра во второй» в
собственном знаке биржи; `f>0`/`f<0` → SELL/BUY (QUOTE), вывод/депозит (TRANSFER),
списание/пополнение остатка (STOCK). Никакого зеркала клиента.

**Закрытая форма прибыли (Ф2), как гейт корректности:**

    PnL = ½ · Σ_e α_e · (|d_e| − c_e)²₊,   d_e = σ*_e − σ_e

**Реализация:** `market_data` строит агентов из снапшотов (новый `agent_builder`,
ADR-056 П-2) → сегменты; `matching` эмиттит потоки. За флагом (композируется с
`F05A_TWO_SIDED_ENABLED`/ADR-052; default off).

## Альтернативы

- **ADR-052 as-is (одна кривая/венью, без ролей)** — не отделяет перевод от торговли,
  запас невозможен → позиция ≡ 0 (§7). Отвергнуто как неполное.
- **ВК = зеркало клиентской книги** (прежняя формулировка) — вводит фиктивную сущность и
  «зеркальное правило»; заменено на «поток агента = инструкция».
- **Отдельный агент казначейства** — избыточно; запас = STOCK-плечо переводчика.

## Последствия

- Появляется доменная сущность «агент» с типом/плечом/`(α,c,σ*)`; контракт `agent.proto`
  расширяется (ADR-056 сборка сегментов, ADR-057 позиция).
- Прибыль такта проверяема закрытой формой (регресс-гейт как в ADR-052).
- Требуется STOCK-плечо → снятие `Wx=0` жёсткого (ADR-056) — иначе роль мертва.

## Обратимость

За флагом; при выключении — откат к ADR-052 (одна кривая/венью, без ролей и запаса).
`agent.proto` аддитивен. Эталон — Python `agents_vc.py`/`agents_sim.py` (golden-тесты).

## Conflict Notes (F-18 v2, 2026-09-15)

> Ревизия по [`CE_algorithm_v2.md`](../../../incoming-docs/2026-09-15-CE_algorithm_v2.md).
> См. [ADR-061](ADR-061-ce-v2-agent-position-band-hedge.md) (`proposed`). Тело ADR-055 не
> переписывается; `status` остаётся `accepted`, во `related` добавляется ADR-061.

**STOCK-плечо убрано; переводчик = только QUOTE-плечо.** v2 оставляет ровно два типа
агента — переводчик (QUOTE) и связка-арбитражёр (TRANSFER). Исходный контекст этого ADR
(«без STOCK `Σ_j f(quote a@j) ≡ 0`, позиция биржи ≡ 0») больше не применим: в v2 позицию
переводчика двигают клиентский встречный поток (A0) и собственное накопление `c ← c + f`,
а не собственный остаток STOCK. Замыкание ранга/баланса теперь делает **счёт дома**
(house-столбец в узле нумерария, см. ревизию [ADR-056](ADR-056-ce-node-graph-clearing.md)),
а не STOCK.

- Таблица «Три плеча агентов» сокращается до **QUOTE** (переводчик) и **TRANSFER**
  (арбитражёр); строка `STOCK` и формулировка «Переводчик = QUOTE + STOCK» — выводятся
  из эксплуатации.
- `agent_builder` перестаёт эмитить STOCK-сегменты; `CE_STOCK_ALPHA/C_*` выводятся из
  эксплуатации за флагом `CE_V2_GRAPH` (все флаги v2 default OFF).
- **Обратимость:** дёшево — STOCK-путь удаляется за флагом, восстановим из git; значимых
  персистентных STOCK-балансов в проде нет.
