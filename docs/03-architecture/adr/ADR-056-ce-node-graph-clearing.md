# ADR-056 — Граф узлов CE и снятие жёсткого Wx=0

> **Решение владельца (2026-09-10, `CE_algorithm_spec.md` §1,3; `CE_virtual_counterparties.md` §3,7).** Единица клиринга — **узел «валюта@площадка»** (`BTC@Binance`, `USDT@OKX`), а не актив. Баланс `Wx=0` (сумма потоков в каждый узел равна нулю) требуется только по узлам площадок; узлы собственной книги (`asset@__book__`) из ограничений исключены и несут цену-марку `μ` в линейном члене. Это снимает запрет «позиция биржи запрещена по построению».

## Контекст

Клиринг F-05A строит базис из активов (`BuildAssetBasis`, [vectorize.hpp](../../../cpp/market_data/src/domain/vectorize.hpp)) и задаёт баланс `Wx=0` жёстким равенством по всем строкам ([vector_qp_solver.cpp:56-58](../../../cpp/matching/src/domain/vector_qp_solver.cpp#L56-L58)). Следствие (§7 источника, проверено): суммарный поток по котировочным рёбрам тождественно ноль, то есть изменение позиции биржи ноль. Позиция может появиться только если у переводчика есть собственный остаток на площадке (STOCK-плечо, ADR-055), а он требует свободного узла книги — чего жёсткий `Wx=0` не допускает.

Кроме того, биткойн на Binance и на Kraken — разные вещи (перевод стоит денег и времени), поэтому базис активов теряет географию ликвидности, и арбитраж «находится» там, где его нет.

## Решение

- **Базис узлов** `BuildNodeBasis`: узлы `asset@venue` плюс по одному узлу книги `asset@__book__` на актив; порядок стабильный (сортировка по строке-ключу). Формат ключа `"ASSET@VENUE"` фиксируется в этом ADR, чтобы BFF мог его разбирать. Поле `AssetBasis.Entry.asset` наполняется значением вида `"BTC@Binance"` (контракт аддитивен).
- **Матрица баланса `W`**: строка на каждый балансируемый узел (только площадки), столбец на сегмент кривой. Узлы книги строк не получают — отсюда свобода позиции.
- **Цена узла книги** входит в линейный член как марка `μ_a = Σ_j α_j·m_{a,j} / Σ_j α_j` (средневзвешенная по глубине средняя цена). Марка — это вход, а не выход; её ошибка даёт систематический дрейф позиции (диагностический сигнал, ADR-057).
- **Снятие Wx=0 (шаг 2):** по узловым строкам книги ставится бокс запаса (`l = −q_запас`, `u = +q_запас`) с квадратичной ценой использования запаса; узлы площадок остаются жёсткими (`l = u = 0`).
- **`pi` = цены узлов** (двойственные переменные строк `W`); уже присутствует в [VectorClearingResult.pi](../../../cpp/matching/src/domain/vector_qp_solver.hpp#L117) (вопреки анализу источника — см. Conflict Note ниже).

**Реализация:** `market_data` (`BuildNodeBasis`, сегменты по рёбрам узлов) плюс `matching`.

**Поправка (2026-09-10, Срез 1):** CE-клиринг реализован как отдельный выпуклый Newton-движок [`domain/ce_agent_clearing.hpp`](../../../cpp/matching/src/domain/ce_agent_clearing.hpp) (минимизация `Φ(x) = Σ ½·α·((|d|−c)₊)²` методом active-set Newton; узлы книги свободны, узлы площадок балансируются), а не через OSQP-ветку `AssembleProblem`. Причина: движок доказанно воспроизводит Python-эталон до 1e-6 без внешних зависимостей и без риска рассинхрона с academic-формой ADR-052. OSQP (`vector_qp_solver`) остаётся для путей F1/two-sided (ADR-048/052) без изменений. Математически это эквивалентно боксовой формулировке; отличается только движок.

## Conflict Note (источник vs код)

Источник (`CE_algorithm_spec.md` Р-5/Р-7, §13) утверждает, что `matching` не собирается и поля `solve.pi` нет. На HEAD `1e8bf6f` это неверно: `pi` есть (vector_qp_solver.hpp:117), конструктор с пятью аргументами и `two_sided` (139-143), `matching` собран, событие `ce.position.delta` работает сквозным потоком. В коде правится только базис и снятие `Wx=0`, а не «5 ошибок компиляции».

## Альтернативы

- **Базис активов плюс мягкий surplus (ADR-047).** Отклонено: не даёт узловой географии и STOCK.
- **Отдельный «казначейский» солвер поверх клиринга.** Отклонено: двойной проход и рассинхрон, хуже единого QP по узлам.

## Последствия

- `vector_liquidity.proto`: появляется `NodeBasis` и формат ключа; сегмент получает `agent_id`; сборка QP меняется (ADR-048 дополнен).
- Позиция биржи становится наблюдаемой величиной (вход в ADR-057), а не нулём.
- Цены узлов `p*` берутся из двойственных переменных; в UI — матрица «валюта × площадка» плюс строка марки.

## Обратимость

За флагом: при выключении — базис активов и жёсткий `Wx=0` (ADR-052/048), позиция ноль. `NodeBasis` и `agent_id` аддитивны. Эталон — Python `agents_vc.py` (совпадение до 1e-9).

## Conflict Notes (F-18 v2, 2026-09-15)

Ревизия по [CE_algorithm_v2.md](../../../incoming-docs/2026-09-15-CE_algorithm_v2.md); подробности — в [ADR-061](ADR-061-ce-v2-agent-position-band-hedge.md) (`proposed`). Тело ADR-056 не переписывается, `status` остаётся `accepted`, во `related` добавлен ADR-061.

**Узел книги и марка `μ` убраны; вместо них — столбец «счёт дома».** Текущее решение вводит по одному свободному узлу `asset@__book__` на актив с боксовой релаксацией баланса, чтобы дать STOCK-плечу разрядку. Поскольку STOCK убран (ревизия [ADR-055](ADR-055-ce-virtual-counterparties-agents.md)), механизм свободного узла на актив избыточен: v2 заменяет его одним столбцом «счёт дома» (строка-невязка, которая балансирует книгу и забирает арбитражную прибыль; не агент) в узле **нумерария** (опорный узел-деньги, относительно которого меряются все цены).

- `BuildNodeBasis` v2: узлы — только `asset@venue` (per-asset узлы `asset@__book__` убираются). Строгое равенство `Wf=0` возвращается по всем узлам площадок (боксовая релаксация строк книги отменяется).
- Ранг и фиксируемость восстанавливает единственный столбец «счёт дома» — единичный вектор в узле нумерария (не по одному на актив); это переменная-невязка, а не агент. Забирает арбитражную прибыль (равную разнице цен площадок).
- Марка `μ` как вход линейного члена узла книги больше не нужна; цена дома фиксируется той же конвенцией закрепления нумерария (`π[USD@Binance] = 0`).
- **Именование ключа** — отдельный зарезервированный псевдо-узел (например `HOUSE@<numeraire_venue>`), а не переиспользование суффикса `@__book__`, чтобы не ломать существующие парсеры формата `"ASSET@VENUE"` (BFF и фронт).
- **Обратимость:** средняя — пересборка `BuildNodeBasis` и QP-сборки за флагом `CE_V2_GRAPH` (по умолчанию выключено); при зарезервированном ключе (не `@__book__`) переход по формату аддитивно-совместим.
