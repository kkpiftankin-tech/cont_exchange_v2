# ADR-058 — committed/in-flight вместо cooldown

> **Решение владельца (2026-09-10, `CE_algorithm_spec.md` §A6,A8,Р-10; `CE_virtual_counterparties.md` §6).**
> Между решением клиринга и подтверждением исполнения проходит время. Защита от повторной
> отправки — **состояние `committed` по агенту** (отправлено, не подтверждено), а не
> таймер `CE_HEDGE_COOLDOWN_MS`. Клиринг считает свободное = `qty − committed`.

## Контекст

Сейчас роль «не отправить дважды» играет таймер
[`CE_HEDGE_COOLDOWN_MS`](../../../cpp/risk/src/app/risk_uc.cpp) (Р-10): если площадка
отвечает дольше кулдауна, тот же хедж уйдёт снова; если быстрее — эмиссия задержится
искусственно. Задача не решается временем — она решается учётом уже обещанного объёма.
Пересчёт №1 (§A6) фиксирует `committed`, пересчёт №2 (§A8) — факт по `execution.reports`.

## Решение

- Таблица PG `agent_state(agent_id, committed, assigned_last, updated_at)`.
- `matching` при эмиссии: `committed_e += |f_e|` в одной транзакции с публикацией
  поручений (idempotent по `batch_id`).
- Клиринг следующего такта видит `свободное = qty − committed` и корректирует якорь:
  `σ* −= ρ·committed` (§A2).
- Снятие: `execution.reports`/timeout/cancel уменьшают `committed`; отменённые/просроченные
  возвращают остаток и шлют `risk.alerts`.
- `CE_HEDGE_COOLDOWN_MS` удаляется.

**Реализация:** `matching` (запись `committed` в PG в транзакции с эмиссией), `ledger`/`risk`
(снятие по `execution.reports`), удаление cooldown-ветки в `risk_uc`.

## Альтернативы

- **Cooldown-таймер (текущий)** — не покрывает медленные/быстрые площадки; гонки. Отвергнут.
- **Идемпотентность только по `intent_id` без `committed`** — не даёт клирингу знать
  занятый объём, повторно назначает ту же ногу. Недостаточно.

## Последствия

- Новая PG-таблица + транзакционная граница «эмиссия ⇄ committed».
- Тест-регресс двойной отправки (§7): два такта подряд без подтверждений — суммарный
  назначенный объём по агенту ≤ `capacity`.
- Уровень агента позиции (ADR-057) получает реальный источник.

## Обратимость

Флагом `CE_COMMITTED_STATE_ENABLED`: при выключении — прежний cooldown. Таблица аддитивна;
при откате не читается.

## Conflict Notes (F-18 v2, 2026-09-15)

> Ревизия по [`CE_algorithm_v2.md`](../../../incoming-docs/2026-09-15-CE_algorithm_v2.md).
> См. [ADR-061](ADR-061-ce-v2-agent-position-band-hedge.md) (`proposed`). Тело ADR-058 не
> переписывается; `status` остаётся `accepted`, во `related` добавляется ADR-061.

**`committed` сохраняется как поле `in_flight`; полоса `±q` + таймаут заменяют cooldown-логику.**
Этот ADR ввёл отдельное поле `agent_state.committed`, снимаемое исполнением, как защиту от
повторной эмиссии. v2 вводит знаковую позицию `c_j` (A6: `c ← c + f`), но **committed НЕ
исчезает** — переезжает в поле `ce_agent_position.in_flight` со смыслом «отправлено наружу,
ещё не исполнено» (**решение владельца 2026-09-15**, см. Conflict Note в ADR-061). A7 эмитирует
избыток `(|c_j| − q_j)` и **наращивает `in_flight`** (позицию `c_j` при эмиссии НЕ трогает);
позиция и `in_flight` уменьшаются **по факту исполнения** (A8); таймаут снимает неисполненный
остаток с `in_flight`, позицию не меняя. Понятия `target` больше нет; `committed` живёт как
`in_flight`.

- Отдельная таблица `agent_state(committed)` выводится из эксплуатации; ответственность
  за позицию → `ce_agent_position.position`, за committed → `ce_agent_position.in_flight`
  (ADR-061). **Транзакционная гарантия** ADR-058 («`committed += |f|` в одной транзакции с
  публикацией поручений, идемпотентно по `batch_id`») сохраняется — переносится на запись
  `in_flight` при эмиссии A7.
- **Полоса `±q` (A7) как механизм интернализации заменяет ту роль, которую нёс
  `CE_HEDGE_COOLDOWN_MS`**: удержание объёма внутри `|c_j| ≤ q_j` гасит встречный клиентский
  поток без выхода наружу; сам `CE_HEDGE_COOLDOWN_MS` уже удалён решением этого ADR — v2 это
  подтверждает, cooldown не возвращается.
- `assigned_last` из ADR-058, если нужен, переносится в per-batch снапшот `clearing_trace`
  (ADR-059), а не в отдельно персистируемое состояние.
- **Обратимость:** дёшево — тот же транзакционный паттерн записи, только реформа таблицы за
  флагами v2 (default OFF); регресс-тест «двойная отправка» из ADR-058 применим дословно к
  слитому полю `position`.
