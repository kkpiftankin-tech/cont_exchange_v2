# ADR-058 — committed/in-flight вместо cooldown

> **Решение владельца (2026-09-10, `CE_algorithm_spec.md` §A6,A8,Р-10; `CE_virtual_counterparties.md` §6).** Между решением клиринга и подтверждением исполнения проходит время. Защита от повторной отправки — это **состояние `committed` по агенту** (отправлено, но не подтверждено), а не таймер `CE_HEDGE_COOLDOWN_MS`. Клиринг считает свободный объём как `qty − committed`.

## Контекст

Сейчас роль «не отправить дважды» играет таймер [`CE_HEDGE_COOLDOWN_MS`](../../../cpp/risk/src/app/risk_uc.cpp) (Р-10): если площадка отвечает дольше кулдауна, тот же хедж уйдёт снова; если быстрее — эмиссия задержится искусственно. Задача не решается временем — она решается учётом уже обещанного объёма. Пересчёт №1 (§A6) фиксирует `committed`, пересчёт №2 (§A8) — факт по `execution.reports`.

## Решение

- Таблица PG `agent_state(agent_id, committed, assigned_last, updated_at)`.
- `matching` при эмиссии наращивает `committed_e += |f_e|` в одной транзакции с публикацией поручений (идемпотентно по `batch_id`).
- Клиринг следующего такта видит свободный объём `qty − committed` и корректирует якорь: `σ* −= ρ·committed` (§A2).
- Снятие: `execution.reports`/timeout/cancel уменьшают `committed`; отменённые/просроченные возвращают остаток и шлют `risk.alerts`.
- Таймер `CE_HEDGE_COOLDOWN_MS` удаляется.

**Реализация:** `matching` (запись `committed` в PG в транзакции с эмиссией), `ledger`/`risk` (снятие по `execution.reports`), удаление cooldown-ветки в `risk_uc`.

## Альтернативы

- **Cooldown-таймер (текущий).** Отклонено: не покрывает медленные/быстрые площадки, даёт гонки.
- **Идемпотентность только по `intent_id` без `committed`.** Отклонено: не даёт клирингу знать занятый объём, повторно назначает ту же ногу.

## Последствия

- Новая PG-таблица плюс транзакционная граница «эмиссия ⇄ committed».
- Тест-регресс двойной отправки (§7): два такта подряд без подтверждений — суммарный назначенный объём по агенту не превышает `capacity`.
- Уровень агента в позиции (ADR-057) получает реальный источник данных.

## Обратимость

За флагом `CE_COMMITTED_STATE_ENABLED`: при выключении — прежний cooldown. Таблица аддитивна, при откате не читается.

## Conflict Notes (F-18 v2, 2026-09-15)

Ревизия по [CE_algorithm_v2.md](../../../incoming-docs/2026-09-15-CE_algorithm_v2.md); подробности — в [ADR-061](ADR-061-ce-v2-agent-position-band-hedge.md) (`proposed`). Тело ADR-058 не переписывается, `status` остаётся `accepted`, во `related` добавлен ADR-061.

**`committed` сохраняется как поле `in_flight`; полоса `±q` плюс таймаут заменяют cooldown-логику.** Этот ADR ввёл отдельное поле `agent_state.committed`, снимаемое исполнением, как защиту от повторной эмиссии. v2 вводит знаковую позицию `c_j` (накопление `c ← c + f`), но `committed` **не исчезает** — переезжает в поле `ce_agent_position.in_flight` со смыслом «отправлено наружу, ещё не исполнено» (решение владельца 2026-09-15, см. раздел «Конфликт со спекой» в ADR-061). Эмиссия (A7) наращивает `in_flight` (позицию `c_j` при эмиссии не трогает); позиция и `in_flight` уменьшаются по факту исполнения (A8); таймаут снимает неисполненный остаток с `in_flight`, позицию не меняя. Понятия `target` больше нет; `committed` живёт как `in_flight`.

- Отдельная таблица `agent_state(committed)` выводится из эксплуатации; ответственность за позицию переходит в `ce_agent_position.position`, за committed — в `ce_agent_position.in_flight` (ADR-061). Транзакционная гарантия ADR-058 («`committed += |f|` в одной транзакции с публикацией поручений, идемпотентно по `batch_id`») сохраняется — переносится на запись `in_flight` при эмиссии.
- **Полоса `±q` как механизм интернализации** заменяет ту роль, которую нёс `CE_HEDGE_COOLDOWN_MS`: удержание объёма внутри `|c_j| ≤ q_j` гасит встречный клиентский поток без выхода наружу. Сам таймер уже удалён решением этого ADR — v2 это подтверждает, cooldown не возвращается.
- `assigned_last` из ADR-058, если нужен, переносится в снапшот такта `clearing_trace` (ADR-059), а не в отдельно персистируемое состояние.
- **Обратимость:** дёшево — тот же транзакционный паттерн записи, только реформа таблицы за флагами v2 (по умолчанию выключено); регресс-тест «двойная отправка» из ADR-058 применим дословно.
