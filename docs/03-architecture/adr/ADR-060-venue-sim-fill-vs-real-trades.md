# ADR-060 — sim-исполнение по ленте реальных сделок

> **Решение владельца (2026-09-14).** venues работает в режиме `multi_real` (реальные
> стаканы binance/okx/kraken/coinbase). Симулятор ИСПОЛНЕНИЯ заявок должен использовать
> реальные исполненные публичные сделки: sim-заявка исполняется по цене реально
> исполнившейся публичной сделки; если цена sim-SELL выше реально исполненной сделки —
> заявка НЕ исполняется; частичное исполнение имитируется объёмами (min sim/real).

## Контекст

`cex_ws_rest_adapter` в режиме `simulate_orders` наивно закрывал любую заявку **целиком по
её же `limit_price`** (`MakeSimulatedOrderResult`). Это давало нереалистичную картину:
позиция биржи двигалась «идеально» независимо от реальной ликвидности и цены, а при
реальных арбитражных ценах (okx≈binance) отсутствие расхождения не проявлялось в фактах
исполнения. Реальная лента публичных сделок (`trades`/`aggTrade`/`match`) уже приходит в
адаптер (`apply_ws_trade_event_locked`), но использовалась только для volume/VWAP.

## Решение

Матчить sim-заявку против **недавних реальных публичных сделок** символа:

- Лента: буфер `recent_trades{price, qty, ts}` на символ (окно `VENUES_SIM_TRADE_WINDOW_MS`,
  по умолчанию 10s; ёмкость `sim_trade_buf_cap`). Пополняется из `apply_ws_trade_event_locked`
  (цена из `p`/`price`).
- Правило пересечения: **SELL@P** исполняется сделками `price ≥ P`; **BUY@P** — сделками
  `price ≤ P` (если цена sim-заявки «хуже» реальной сделки — пересечения нет).
- Объём: `filled = min(target, Σ пересёкшего реального объёма)`; объём сделок в буфере
  **потребляется** по мере матчинга (дефицит реального объёма ⇒ частичный филл).
- Цена: `average_price = VWAP` реально пересёкших сделок (не `limit_price`).
- Нет пересечения ⇒ `filled=0`, статус `NEW` — заявка «висит» и переэмитится следующим
  тактом клиринга (CE пересчитывает потребность от обновлённой позиции).

Флаг `VENUES_SIM_MATCH_REAL_TRADES` (по умолчанию OFF — старое поведение сохранено для
тестов/обратной совместимости; ON на dev). Реализация — `cex_ws_rest_adapter`
(`ApplyRealTradeFillLocked`, перезапись результата в sim-пути `SendOrder`).

## Последствия

- Факты исполнения (`execution.venue`) отражают реальную цену/объём/частичность → позиция
  и `committed`-декремент (ADR-057) двигаются по факту, а не по плану.
- Частичные и нулевые филлы штатны: ledger `apply_execution_report` идемпотентен и двигает
  `venue_balances_` только на `delta_qty>0`; committed снимается ровно на исполненное.
- Реалистичность зависит от подписки на канал `trades` по всем торгуемым символам
  (BTC/ETH/SOL). Символы без ленты сделок не будут исполняться (заявки «висят») — это
  корректно отражает отсутствие ликвидности.
- DEX/AMM (uniswap) — вне охвата (нет публичной ленты сделок того же вида); там остаётся
  прежний sim-путь.

## Альтернативы

- **Мгновенный филл по limit_price** (было) — нереалистично, скрывает ликвидность и цену.
- **Полноценная книга покоящихся заявок с асинхронным матчингом** — избыточно: CE
  переэмитит потребность каждый такт, поэтому окно недавних сделок достаточно (MVP).

## Обратимость

Полная: флаг `VENUES_SIM_MATCH_REAL_TRADES=0` возвращает прежний мгновенный филл. Буфер
ленты аддитивен к `SymbolBookState`.
