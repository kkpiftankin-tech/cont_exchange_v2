# ADR-061 — Модель позиции CE v2: агент с нуля, полоса ±q, счёт дома

> **Статус: `proposed`.** Это предложение решения; перевод в `accepted` — прерогатива
> владельца после подтверждения развилок §2 плана `CE-v2-agents-rework` и единого гейта
> §13 сводки [`F-18-v2-agents-review-summary.md`](../../implementation-plan/F-18-v2-agents-review-summary.md).
> До `accepted` реализация Э1 не открывается (CLAUDE.md §0a, no-code-before-docs).

> **Источник (владелец, 2026-09-15, [`CE_algorithm_v2.md`](../../../incoming-docs/2026-09-15-CE_algorithm_v2.md)).**
> Агенты — только **переводчики** и **арбитражёры**. Позиция каждого стартует с нуля,
> может быть отрицательной, и пока `|c_j| ≤ q_j`, наружу не уходит ни одной заявки. Ни
> склада, ни целевых остатков, ни плеч запаса.

## Контекст

ADR-057 определил **трёхуровневую** позицию (агент / узел / актив) с инвентарным
`target`: `Z_a = Σ_venue qty + in_transit + committed − Σ target`. Ненулевую позицию
переводчика в той модели порождало **STOCK-плечо** (ADR-055: «без STOCK `Σ_j f(quote a@j) ≡ 0`,
позиция биржи тождественно ноль»), а свободный узел книги `asset@__book__` (ADR-056) давал
STOCK разрядку. Защиту от повторной эмиссии нёс отдельный `committed` (ADR-058).

`CE_algorithm_v2.md` меняет модель целиком:

- агентов ровно два — **переводчик** (`Q_*`, маркет-мейкер на одной площадке, плечо QUOTE)
  и **арбитражёр** (`T_*`, перевоз одного актива между площадками, плечо TRANSFER);
  **STOCK-плечо убрано**, «плеч запаса» больше нет;
- узлы — **только площадки** (`asset@venue`); узел склада/книги убран;
- **позиция агента `c_j`** — единственное число уровня «агент»: знаковая, старт **ноль**,
  копится `c ← c + f` каждый такт клиринга (A6), **без вычитания target** — понятия `target`
  больше нет; отрицательная позиция обязательна (`W·c=0`, базис ядра `(+1,−1,+1,+1)` даёт одну
  противоположную компоненту; требование `c≥0` даёт только `c=0` — нет оборота; в прогоне
  источника наблюдался минимум `−18,000` тыс.);
- **позицию агента двигают встречные потоки клиринга** — **(а)** клиентский встречный поток
  (A0), когда клиенты есть, и **(б)** встречные потоки **агентов-переводчиков и арбитражёров
  между разными внешними площадками** (собственное накопление клиринга, A6). **Уточнение
  владельца (2026-09-15): клиентов может не быть — тогда клиентского встречного потока (A0)
  нет, и позицию `c_j` двигают именно межплощадочные встречные потоки переводчиков и
  арбитражёров.** Позицию **не** двигает собственный остаток STOCK (его в v2 нет). Неподвижным
  без клиентов и исполнения остаётся **владение `Z`** (`Z ≡ 0`, INV-1), **а не** позиция
  агента `c_j`, которая может копиться межплощадочными встречными потоками агентов;
- наружу эмитируется **только при выходе за полосу** `|c_j| > q_j` (A7), и эмиссия
  **уменьшает** `c_j` на отправленное — отдельного `committed` не нужно;
- **реальное владение** `Z_a = владение_a(t) − владение_a(0)` меняют **ровно две вещи**:
  клиентская сделка и подтверждённое исполнение на площадке (A8). Клиринг, накопление
  позиций и перевозы владение **не трогают никогда**; без клиентского потока `Z ≡ 0`;
- прибыль (арбитражный остаток `= разница цен площадок`) падает на **счёт дома**, а не
  на агент: house — переменная-невязка в узле нумерария, без якоря/наклона/полки/полосы,
  заявок не порождает;
- **A8-таймаут** возвращает неисполненный остаток в позицию по **плановой** цене (не по
  факту) — разрыв план/факт остаётся отдельной величиной качества исполнения.

Текущий HEAD (`d4900700`) ближе к v2, чем к прежнему прототипу: Newton-движок
`ce_agent_clearing` (ADR-056 «Поправка, Срез 1») даёт `π`/узловые потенциалы напрямую,
`ce.position.delta` публикуется e2e. Это делает миграцию точечной (переработка графа,
накопления, эмиссии), а не переписыванием солвера. При этом код-ревизия (сводка §10)
показала: якорный сдвиг `σ*=m+ρ·c` в коде **отсутствует** (не «двухслагаемый», как думали),
а `AssetDelta.venue` **отбрасывается** консюмером (live bug) — обе правки входят в объём v2.

## Решение

1. **Позиция агента `c_j`** — единственное число уровня «агент»: знаковая, старт `0`,
   `c ← c + f` каждый такт клиринга (A6), **без вычитания `target`**. `target`, STOCK-плечо,
   узел книги — как понятия удаляются.
2. **Якорь — одно слагаемое:** `σ*_j = m_j + ρ_j · c_j` (вместо `ρ(Q−Q*) + ρ·committed`).
   `ρ_Q = 0,004` для переводчика, `ρ_T = 0,002` для арбитражёра. A2 видит собственную
   позицию агента **до** A6 (после подтверждений и клиентской сделки, до накопления клиринга).
3. **Владение** (`qty`/holdings) меняют **только** (а) сделка с клиентом и (б) подтверждённое
   исполнение на площадке (A8). Клиринг, накопление `c`, перевозы — не трогают.
   `Z_a = владение_a(t) − владение_a(0)`; старт с нуля; без клиентского потока `Z ≡ 0`.
   **Позицию агента `c_j`** двигают **встречные потоки клиринга** — (а) клиентский встречный
   поток (A0), когда клиенты есть, и (б) встречные потоки **переводчиков и арбитражёров между
   разными внешними площадками** (собственное накопление клиринга, A6). **Клиентов может не
   быть** — тогда клиентского потока (A0) нет, но `c_j` продолжают двигать межплощадочные
   встречные потоки агентов. STOCK-остаток позицию **не** двигает (его нет). **Инвариант
   INV-CE-A0:** неподвижным без клиентов и исполнения остаётся **владение `Z`** (`Z ≡ 0`),
   **а не** позиция `c_j` (проверяемо тестом; см. `F-18-v2-test-plan`).
4. **Полоса `±q_j`** (A7): наружу отправляется только избыток `(|c_j| − q_j)·sign(c_j)`, и
   на столько же **сразу уменьшается** `c_j` (иначе повторная отправка). Заявка в `in_flight`;
   по A8-таймауту неисполненный остаток **возвращается** в `c_j` по **плановой** цене (A8.3).
   Две полосы по смыслу: переводчик `q_translator = 18` (риск незахеджированного запаса),
   арбитражёр `q_arbitrageur = 30` (размер партии перевоза, рыночного риска нет). Размер
   заявки — по стоимости (`qty ← излишек·1000/walk(qty)`, 2–3 итерации), тип — по экспозиции.
5. **Счёт дома** — **не агент**: без якоря/наклона/полки/полосы, заявок не порождает.
   Единственная ненулевая клетка в узле **нумерария** (`USD@Binance`) — переменная-невязка,
   восстанавливает ранг `W = V·A−1` и забирает арбитражную прибыль (`= разница цен площадок`,
   в натуральных `det W = (p_Kraken − p_Binance)/1000`, вырождается при равных ценах).
   Остаток сметается в нумерарий. Ключ house — отдельный зарезервированный псевдо-узел
   (не переиспользование суффикса `@__book__`), чтобы не ломать парсеров формата `"ASSET@VENUE"`.
6. **Тип участника AGENT** — третий `party_type` (CLIENT / HOUSE / AGENT), не подтип клиента.
   У AGENT нет неотрицательности, нет резерва/release, позиция знаковая; резерв-чек — только
   для CLIENT (архитектурно оформляется отдельным ADR-063, здесь фиксируется как инвариант).
7. **Персистентность:** `ce_agent_position(agent_id, asset, venue) → position (signed),
   updated_at, last_batch_id` в PG (владелец — `ledger`, §17 CLAUDE.md), upsert с guard по
   `last_batch_id`. Ответственность прежней `agent_state.committed` (ADR-058) переходит сюда.

**Флаги реализации (все default OFF, снимаются независимо; план Э1–Э5):**

| Флаг | Этап | Что включает |
|---|---|---|
| `CE_V2_GRAPH` | Э1 | граф только площадок + house-столбец; убраны STOCK/book-узел |
| `CE_AGENT_POS` | Э2 | позиция агента `c_j` с нуля, знаковая, `c←c+f`; якорь `σ*=m+ρ·c` |
| `CE_AGENT_BAND` | Э3 | эмиссия только при `|c_j|>q_j`; `c_j` уменьшается на отправленное |
| `CE_AGENT_A8` | Э4 | подтверждения/таймауты: возврат остатка в `c_j` по плановой цене |
| `CE_TRANSFER_AGENT` | Э5 | арбитражёр как перевоз (`ce.transfers`, state machine перевоза) |

Зависимость: `CE_AGENT_A8` (Э4, возврат остатка) — **жёсткий пререквизит** включения
`CE_AGENT_BAND` (security MEDIUM-7): без него отвергнутая/просроченная band-заявка
оставляет `c_j` заниженной. Э4 — не follow-up, а предусловие Э3 в проде.

## Альтернативы

1. **Сохранить ADR-057 (target = seed + STOCK) и добавить полосу поверх.** Отклонено:
   два конкурирующих механизма возврата к нулю (`θ` от target и `q` от нуля) дают
   неоднозначный стимул и противоречат явному «target отсутствует как понятие» из v2.
2. **Смоделировать AGENT как CLIENT с разрешённым отрицательным балансом.** Отклонено:
   ломает инварианты CLIENT (§8.2 CLAUDE.md — неотрицательность, резерв-чек,
   идемпотентность заказа); нужен отдельный `party_type` (ADR-063).
3. **Оставить STOCK-плечо ради обратной совместимости NOP-метрики.** Отклонено: v2 прямо
   убирает склад; дублирование механизма, который теперь закрывает счёт дома, — источник
   рассинхрона.
4. **Оставить `committed` отдельной теневой копией позиции ради аудита.** Отклонено:
   воспроизводит «два источника истины», ради устранения которой писался ADR-058; аудит
   закрывает `clearing_trace` (ADR-059) без дублирования поля.
5. **Полное удаление файла ADR-057 вместо supersede.** Отклонено: документы — immutable
   исторический след; ADR-057 остаётся в репозитории со статусом «superseded by ADR-061».

## Последствия

- Одно число на агента вместо триады `qty/target/committed` — проще ментальная модель,
  меньше конфиг-поверхности (`CE_TARGET_*`/`CE_STOCK_*` вычищаются).
- Прямое соответствие Python-эталону `ce_tick_v2.py` (27 проверок) — снижает модельный
  дрейф, дважды фиксировавшийся (Conflict Note ADR-056).
- Счёт дома даёт проверяемый инвариант ранга `W = V·A−1` и ядра `(V−1)(A−1)` (тест из A1/A3 v2).
- **Supersedes ADR-057**: трёхуровневая target-модель заменяется одноуровневой знаковой
  позицией + house-невязкой. ADR-057 переводится в `superseded by ADR-061` (файл сохраняется).
- **Revises ADR-055 / ADR-056 / ADR-058** (append-ревизии в тех же файлах, дата 2026-09-15):
  ADR-055 — убрано STOCK-плечо; ADR-056 — house-столбец вместо book-узла; ADR-058 —
  `committed` сливается с позицией, полоса заменяет cooldown.
- **Breaking-контракты** (координированный контракт-PR, CLAUDE.md §11.3, отдельно от кода):
  `risk.proto ExchangeNOP` (убирается `target`), `treasury.proto AssetDelta → AgentDelta`
  (`agent_id`, `agent_kind`), новый `ce.transfers` (Э5). Потребители/фронт мигрируют вместе.
- **Live bug под правку в объёме v2:** `AssetDelta.venue` отбрасывается консюмером
  (`kafka_consumers.cpp`), `ce_committed_` ключуется только по asset — узловой разрез
  не сходится; ключ позиции переходит на `(agent_id, asset, venue)`.
- Временное сосуществование двух моделей `Z_a` (target-based и zero-based) в переходный
  период — **обязательно за флагом**, не подменять молча (CLAUDE.md conflict-rule).
- Операторам явно сообщить: агенты — обещания дилерского клиринга, а не собственная
  директивная книга биржи; семантика «вернуть к настроенному нейтральному инвентарю»
  (ADR-054 target=seed) уходит.

## Обратимость

Средне-дёшево, откат безопасен:

- **Все 5 флагов default OFF**, снимаются независимо; при выключенных флагах поведение
  идентично текущему (target-модель ADR-057, cooldown/committed ADR-058).
- **`git revert` безопасен**: новые таблицы/поля аддитивны (`ce_agent_position` — новая
  таблица; `ce_capital`/`ce_position` не трогаются); реверт коммита возвращает прежний путь.
- **Старый `ce_committed_`-путь сохраняется** на время миграции (не удаляется в тех же
  PR, что вводят `ce_agent_position`) — переключение только флагом, данные не теряются.
- Для breaking-контрактов (`risk.proto`/`treasury.proto`) рекомендуется переходное окно с
  `deprecated`-полем `target` (как ADR-057 делал для money-path план≠факт), не жёсткое
  удаление сразу — тогда откат не требует реверта уже раскатанного контракта.
