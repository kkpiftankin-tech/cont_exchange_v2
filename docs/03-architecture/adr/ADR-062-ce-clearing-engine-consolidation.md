# ADR-062 — Консолидация движков клиринга CE

> **Статус `proposed`.** Открытый вопрос из гейта §13 сводки [F-18-v2-agents-review-summary](../../implementation-plan/F-18-v2-agents-review-summary.md); решение за владельцем. До `accepted` действует статус-кво (два движка сосуществуют).

## Контекст

Сейчас в проекте два независимых решателя клиринга (движок — код, который по кривым агентов и матрице баланса `W` считает равновесные потоки `f`):

- **Newton-движок** [`ce_agent_clearing`](../../../cpp/matching/src/domain/ce_agent_clearing.hpp) — активмножественный (active-set) метод Ньютона: минимизирует `Φ(x) = Σ ½·α·((|d|−c)₊)²` напрямую, узловые потенциалы `x` (они же цены узлов `π`) выдаёт без внешних зависимостей. Введён для CE-агентов (ADR-056, «Поправка, Срез 1»), доказанно совпадает с Python-эталоном до 1e-6.
- **OSQP-движок** [`vector_qp_solver`](../../../cpp/matching/src/domain/vector_qp_solver.hpp) — обёртка над библиотекой OSQP (внешний квадратичный солвер): используется на путях F-05A two-sided и F1 (ADR-048/052).

Оба живут в `matching` и решают близкие по форме задачи. Дублирование двух математически эквивалентных движков — это две поверхности для багов, два места для правок и риск рассинхрона результатов (у CE это уже фиксировалось как модельный дрейф — Conflict Note ADR-056). Вопрос: свести к одному движку или осознанно оставить оба.

## Решение

**Предлагается (на подтверждение владельцу): сделать `ce_agent_clearing` (Newton) единственным движком CE-пути, а OSQP оставить только для путей, где он реально нужен, с планом их последующей миграции.**

- CE-клиринг v2 (граф v2, полоса `±q`, счёт дома) считается только Newton-движком; OSQP-ветка для CE не собирается и не вызывается.
- `vector_qp_solver`/OSQP остаётся для F-05A two-sided и F1 (ADR-048/052) без изменений — пока эти пути не мигрированы на Newton отдельной задачей.
- Условие консолидации: Newton-движок закрывает те же кейсы, что и OSQP-путь, с совпадением результатов в пределах допуска (регресс-гейт против golden-набора). Пока это не доказано на two-sided-кейсах, OSQP не удаляется.

Это фиксируется за флагами v2 (ADR-061, все по умолчанию выключены): включение `CE_V2_GRAPH` уводит CE на Newton, не трогая OSQP-путь остальных фич.

## Альтернативы

- **Оставить оба движка постоянно (статус-кво).** Отклонено как целевое состояние: дублирование и риск рассинхрона; допустимо лишь как переходный период.
- **Свести всё на OSQP.** Отклонено: возвращает внешнюю зависимость и риск рассинхрона с academic-формой на CE-пути, ради которого Newton и вводился; Newton уже совпадает с эталоном без OSQP.
- **Свести всё на Newton сразу (включая two-sided/F1).** Отклонено как немедленный шаг: требует доказать эквивалентность на всех кейсах two-sided/F1 до удаления OSQP; делается отдельной задачей после стабилизации CE v2.

## Последствия

- Один движок на CE-пути — меньше поверхности для багов и правок, единый источник цен узлов.
- До миграции two-sided/F1 в `matching` остаются два решателя — это осознанный переходный долг, а не цель.
- Нужен регресс-гейт «Newton == OSQP» на общих кейсах перед удалением OSQP.

## Обратимость

За флагами v2 (по умолчанию выключено): при выключении CE-путь возвращается к прежнему поведению. OSQP-путь не удаляется до отдельного решения, поэтому откат не требует его восстановления.
