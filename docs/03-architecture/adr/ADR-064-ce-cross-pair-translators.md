# ADR-064 — Прямые кросс-пары в CE-клиринге

> **Статус `accepted` (владелец, 2026-09-16).** Агенты должны соответствовать реальным парам стаканов внешних площадок, а не только парам вида `актив/номинал`.

## Контекст

Клиринг CE строит агентов из книг площадок, но берёт **только** пары, где котируемая валюта равна номиналу (USDT) — фильтр `quote != numeraire` в `market_data_uc.cpp:674`. Из-за этого переводчик (агент-маркет-мейкер) обозначается одной валютой `T_<актив>_<площадка>` = `<актив>/USDT`, а **прямые кросс-пары (например `ETH/BTC` на binance/okx/kraken) игнорируются** — их курс лишь косвенно синтезируется через `ETH/USDT` + `BTC/USDT` в графе номинария (ADR-056). Проверка на dev (2026-09-16): реально текут `BTC/USDT`, `ETH/USDT`, `SOL/USDT` (используются) и `ETH/BTC` (пропускается). Прямая ликвидность кросс-пар не участвует, и агенты не соответствуют вкладке «Площадки».

## Решение

**Переводчик обобщается с пары `актив/номинал` на любую пару `base/quote`.** Ребро переводчика соединяет узлы `base@venue ↔ quote@venue` (для номинальных пар `quote = numeraire`, как было; для кросс-пар — напрямую, например `ETH@binance ↔ BTC@binance`).

- **Ценовая согласованность (ключевая математика).** Потенциал узла `x[a@v]` — лог-цена актива `a` в номинале на площадке `v`, в промилле относительно опорной `P0_a`. Ребро переводчика имеет якорь `σ* = x[base@v] − x[quote@v]`. Для книги пары `base/quote` с серединой `mid_pair` это даёт `σ* = 1000·ln(mid_pair · P0_quote / P0_base)`. Практически: строим агента через существующий `BuildQuoteAgent(levels, reference_price = P0_base / P0_quote)` — тогда `anchor = 1000·ln(mid_pair / (P0_base/P0_quote))` совпадает с формулой выше. Для номинальных пар `quote = USDT`, `P0_quote = 1` ⇒ `reference_price = P0_base` (поведение не меняется, регрессия). Наклон `α` и полка `c` считаются из книги пары как есть (они в промилле).
- **Фильтр снят:** обрабатываем ВСЕ пары книги, а не только `quote == numeraire`. Порядок: сначала пары `X/USDT` (дают опорные `P0` активов), затем кросс-пары (используют уже посчитанные `P0_base`, `P0_quote`).
- **Именование:** переводчик кросс-пары — `T_<base>_<quote>_<venue>` (например `T_ETH_BTC_binance`), явно несёт ПАРУ. Номинальный переводчик остаётся узнаваемым (`quote = USDT`).
- **Арбитражёр не меняется:** он перевозит ОДИН актив между площадками (`A_<актив>_<v1><v2>`) — это по построению одна валюта, а не пара; кросс-пары его не касаются.
- **Дом/номинарий не меняются:** house-пин остаётся в узле номинария (`USDT@house_venue`, π=0, ADR-061 §5); кросс-пары добавляют лишь новые рёбра между не-номинальными узлами.

## Альтернативы

- **Оставить только пары `X/номинал` (номинарий-граф, ADR-056).** Отклонено владельцем: игнорирует прямую ликвидность кросс-пар и не соответствует парам площадок.
- **Синтезировать кросс-курс только через номинал (как сейчас).** Отклонено: теряет реальный стакан `ETH/BTC` (там может быть лучшая ликвидность/цена), и агенты не 1:1 с парами.

## Последствия

- **Контракт (аддитивно):** `CeQuoteAgent`/quote-агент в `ce.clearing.input` получает поле `quote` (котируемая валюта пары); для номинальных пар `quote = numeraire`.
- **market_data:** снятие фильтра `quote != numeraire`; построение агента на каждую пару с `reference_price = P0_base / P0_quote`.
- **matching (`ce_graph_assembler`):** ребро QUOTE соединяет `base@v ↔ quote@v` (по `quote` агента), а не жёстко `base@v ↔ numeraire@v`. Движок `ClearCe` не меняется — топология просто богаче.
- **Именование/данные:** `agent_id` кросс-пары несёт `base_quote_venue`; ключ `ce_agent_position (agent_id, asset, venue)` — `asset` = base, `venue` = площадка (пара кодируется в `agent_id`).
- Граф становится более связным (кросс-рёбра) — ранг/ядро пересчитываются; house по-прежнему замыкает номинарий.

## Обратимость

За флагом (переиспользуем `CE_V2_GRAPH` или отдельный `CE_CROSS_PAIRS`, default сохраняет прежнее поведение — только `X/номинал`). Контракт аддитивен (`quote` пуст ⇒ трактуется как номинал). `git revert` безопасен.
