# ADR-069 — Две ноги CE-арбитражёра

> **Решение владельца (2026-10-05):** CE-арбитражёр `A_<asset>_<src><dst>` держит
> и хеджирует позицию **двумя реальными ногами** — на бирже-источнике (src) и
> приёмнике (dst), по одной заявке на каждую биржу (BUY на src, SELL на dst),
> вместо одной свёрнутой позиции на одной бирже. Веса порога — `ω_i = λ_i/Λ`
> (по глубине книги, MVP-заглушка).

## Термины

- **Нога (leg)** — учётная позиция арбитражёра на ОДНОМ узле графа `asset@venue`.
  Арбитражёр возит актив src→dst, поэтому у него две ноги: `q_src` на `asset@src`
  и `q_dst` на `asset@dst`.
- **TRANSFER-ребро** — ребро графа клиринга между узлами `asset@src` и `asset@dst`
  (`ce_graph_assembler.hpp`); его поток `f` на такт меняет балансы узлов
  противоположно: `Δq_src = −f`, `Δq_dst = +f` (сохранение штук).
- **Порог band ноги** `Q_i = ω_i·c_i/A` (IN-017 §6, Предложение 2): `c_i` —
  taker-комиссия ОДНОЙ биржи ноги (bps), `A` — калибровка риск-наклона (ADR-066
  `Γ=γσ²τ`), `ω_i` — вес ноги.
- **λ_i, Λ** — ликвидность (глубина книги) венью `i` и суммарная сети
  (`ce_asset_liquidity`/α_e, F-05A; Кривые §5.1 `Λ=BGBᵀ`).

## Контекст

Базовые документы задают перенос актива между биржами как **двухногую** схему:
IN-017 §6 (Предложения 1–2) — дилер между двумя биржами реализуется per-venue
карманами `q_i`, каждый хеджируется на СВОЕЙ бирже при `|q_i| > Q_i = ω_i·c_i/A`;
«Кривые» §5 — `asset@src` и `asset@dst` суть РАЗНЫЕ узлы валютного графа, а
арбитраж = замкнутый маршрут `USDT→asset@src→asset@dst→USDT`, неттящийся матрицей
ликвидности `Λx=BGŝ`.

Текущая реализация этому противоречит. Граф клиринга УЖЕ строит оба узла и
TRANSFER-ребро, но проекция результата в агентские дельты
`ProjectAgentDeltas` (`cpp/matching/src/domain/ce_position_projection.hpp`)
**схлопывает поток ребра в ОДНУ `CeAgentDelta`** с `venue=dst` (канонический по
индексу `i<j`) и ценой узла только `src`. Ledger хранит одну позицию `c_j` на
один `venue`; risk эмитит один хедж в `breach.venue()` (`risk_uc.cpp:1358`).
Следствие (наблюдаемо на dev): арбитражёр торгует обе стороны на ОДНОЙ бирже,
кросс-венью маршрут не замыкается, кросс-спред не снимается — заработок ≈0/минус
(гоняет round-trip по одной цене минус price-impact). Это и есть «арбитражёры
ничего не зарабатывают».

## Решение

**Единый агент `A_*` (agent_kind=arbitrageur, один agent_id) с ДВУМЯ позиционными
ногами**, не два отдельных Переводчика (сохраняем идентичность арб-стратегии как
одного capital/risk-владельца, ADR-055; `rt` комиссии ADR-065 уже про две биржи
одного агента).

1. **matching** (`ProjectAgentDeltas`): на TRANSFER-ребро эмитить ДВЕ `CeAgentDelta`
   — `(agent, asset, src, Δ=−f, price=node_price(src))` и
   `(agent, asset, dst, Δ=+f, price=node_price(dst))`. Исправляется и побочный
   дефект: цена бралась только с узла src для единственной строки.
2. **ledger**: структура не меняется — `agent_positions_` по ключу
   `(agent_id, asset, venue)` уже держит две строки; `ApplyPositionDelta` и
   `detect_and_emit_band_breach_locked` уже per-key ⇒ две независимые позиции и
   **два breach** (src: short→BUY, dst: long→SELL). Каждая нога использует цену
   своего узла (`base_price`/`last_price`).
3. **risk**: без изменений — `EmitBandHedgeFromBreach` уже per-venue (`flow_id`
   включает venue, сторона из знака локальной позиции) ⇒ **два `ExecutionIntent`**.
4. **Порог**: `Q_i = ω_i·c_i/A` на КАЖДУЮ ногу, `c_i = ce_taker_fee_bps` ОДНОЙ
   биржи (**rt=1 на ногу**). Прежний `rt=2` (round-trip на свёрнутый агрегат) —
   убрать для арбитражёра: round-trip теперь естественно складывается из двух
   заявок; сохранение `rt=2` задвоило бы порог.
5. **Веса**: `ω_i = λ_i/Λ` (по глубине книги венью). Истинные `ω₁=φ₂+B, ω₂=φ₁−B`
   (IN-017 §6) требуют оценки лидерства цены `φ_i` (Gonzalo–Granger/Hasbrouck),
   которая в системе не наблюдаема → MVP-заглушка = симметричный частный случай
   статьи (`φ_i=½, B=0 ⇒ ω_i=λ_i/Λ`). Отклонение зафиксировано Conflict Note в
   `docs/04-domain/calculations/CALC-CE-ANCHOR.md` §7 и `business-rules.md`.

Контракт (`ledger.proto` `AgentPosition`/`AgentPositionDelta`) **не меняется** —
`venue` уже часть ключа; `venue=""` (route-level) выходит из употребления для
арбитражёров. Миграция существующих одноногих позиций — `ResetAgentPositions`
(однотактовый разрыв истории на вкладке Clearing).

## Альтернативы

1. **Статус-кво (одноногий хедж в dst).** Отклонено: противоречит IN-017 §6 /
   Кривые §5, не хеджирует экспозицию на src, кросс-спред не снимается — арбитражёр
   не зарабатывает.
2. **Два отдельных агента-Переводчика** вместо одного арбитражёра. Отклонено:
   ломает идентичность арб-стратегии как единого owner (ADR-055), конфликтует с
   `rt=2`-комиссией ADR-065, вводит две `agent_kind=translator` строки вместо
   экономически иной сущности.
3. **[Выбрано] Единый агент, две ноги.** Минимальный путь: контракт не меняется,
   правится одна domain-функция + источник двух breach; risk код не трогается.

## Последствия

- Хедж соответствует фактическому риску на ОБЕИХ биржах; кросс-спред снимается
  двумя заявками ⇒ арбитражёр зарабатывает `(P_dst−P_src)·q` (без комиссии).
- Контракты не меняются; `risk_uc.cpp` не меняется.
- **Money-path**: порог band арбитражёра меняется (`rt=2`→`rt=1` на ногу,
  веса `ω_i=λ_i/Λ`) ⇒ меняет момент/объём хеджа. Требует unit-теста на отсутствие
  задвоения порога и code-review money-path.
- Миграция: сброс одноногих позиций (`ResetAgentPositions`), разрыв истории на 1 такт.
- Наблюдаемость «Живые позиции»: у арбитражёра станут видны ДВЕ ноги с реальными
  сделками и знаковым заработком (панель уже поддерживает per-leg).

## Не эквивалентно IN-017 §6 (зафиксированный долг)

Предложения 1–2 IN-017 доказывают оптимальность при наличии **внутренней
бесплатной биржи** с публичной `p_int=a*`, перекладывающей излишек МЕЖДУ
карманами без внешнего хеджа. У CE-арбитражёра такого обмена НЕТ (TRANSFER-ребро
имеет `anchor=0`). Поэтому пороги `Q_i` локально корректны (та же математика
Предложения 2), но без доказанной оптимальности теоремы. Общий якорь
`a*=ω₁S¹+ω₂S²−Aq` и цены ног `b_i=Sⁱ−(A/ω_i)q_i` в CE явно не считаются
(`anchor_eff` плоский, CALC-CE-ANCHOR §7.4) — лимит каждой ноги берёт клиринговую
цену своего узла. Полная модель (внутренний обмен + `φ_i`-оценщик) — отдельная
фича/ADR (связано с открытым §A8.1 ADR-065).

## Обратимость

Высокая. Правка локализована в `ProjectAgentDeltas` (эмиссия 2 дельт вместо 1) +
пороговая формула арбитражёра в ledger; откат — вернуть схлопывание в одну строку
и `ResetAgentPositions`. Контрактных/схемных миграций нет.
