# ADR-074 — Честный симулятор исполнения

> **Статус: proposed.** Заготовка этапа 3 плана
> [F-18-remediation](../../implementation-plan/F-18-remediation.tasks.md).
> Реализует ADR-072 §B (принят, но не реализован). Содержание дорабатывает
> `trading-domain-specialist` + `cpp-service-architect` после сессии 3 с
> экспертом (вопрос: «какая модель филла приемлема для решений о деньгах»).

## Контекст

Разбор (HEAD 02eafef) и проверка на dev: band-хеджи исполняются о публичные
принты, сделанные за **230–352 секунды ДО эмиссии** (подтверждено по
`venue_fill_diagnostics.considered_trades`). REST-лента читается пачками по 100,
принты живут 3·T_read≈2мин (до 10мин) по времени чтения; LIMIT IOC исполняется
по VWAP старых принтов лучше лимита — это бесплатный опцион; MARKET берёт самые
старые принты первыми. «Maker-зона» на деле тейкерская (LIMIT IOC не стоит в
книге). Резидентные maker-заявки (`CE_BAND_MAKER_RESERVE_ENABLED`) выключены.
ADR-072 §B («только вперёд, филл по лимиту») принят, но в коде не реализован.

## Решение (предлагается)

Симулятор исполнения (`cex_ws_rest_adapter.cpp`):
- в филл идут только принты с **биржевым временем после момента эмиссии** + задержка;
- тейкер = проход по **текущему снимку книги**, не по старой ленте;
- maker = резидентная заявка с долей очереди π;
- комиссии maker и taker по площадке;
- мид и F_0 фиксируются при эмиссии и при филле;
- каждый принт расходуется один раз.

## Альтернативы

- Статус-кво (матч о старую ленту). Отклоняется: даёт бесплатный опцион,
  экранный заработок — артефакт.
- Только задержка без forward-only. Отклоняется: не убирает филлы по принтам
  старше эмиссии.

## Последствия

- Исполнение к миду переходит из плюса в минус (тест «случайной стратегии»:
  P&L/оборот = −(полуспред+комиссия)).
- Появляется реалистичная тейкер/мейкер-экономика; калибровка (этап 6) считает
  по честным числам.
- Нужен тест «случайной стратегии» как эталон (ADR + `test-architect`).

## Обратимость

Обратимо флагом выбора модели исполнения (старая лента ↔ forward-only) на период
валидации. После приёмки теста «случайной стратегии» forward-only фиксируется.

## Реализация (частичная, обратимая — forward-only)

Первый инкремент ADR-072 §B — **forward-only** за флагом `CE_SIM_FORWARD_ONLY`
(деф `0` = прежнее поведение). При `1` в `cex_ws_rest_adapter.cpp`
(`ApplyRealTradeFillLocked`) принт матчится, только если его биржевое время
`exchange_ms ≥ emit_ms + CE_SIM_FILL_DELAY_MS`, где `emit_ms` — последнее поле
`intent_id` (`ce|band|…|<ms>`). Фильтр применён в трёх циклах (cross_count,
considered-диагностика, fill) для согласованности `crosses ⟺ fill`. Принты без
биржевого времени (`exchange_ms=0`, напр. coinbase) при вкл не матчатся.
Валидация (ворота этапа 3): `CE_SIM_FORWARD_ONLY=1` → 0 филлов по принту старше
эмиссии; тест «случайной стратегии» даёт P&L/оборот ≈ −(полуспред+комиссия).
НЕ реализовано (следующие инкременты): тейкер по текущему снимку книги, резидентный
maker с долей очереди π, комиссии maker/taker, фиксация мид/F_0 на эмиссии и филле.
Решение (принять модель) — экспертная сессия 3.
