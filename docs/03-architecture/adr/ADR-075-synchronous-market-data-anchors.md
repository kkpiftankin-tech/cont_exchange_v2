# ADR-075 — Синхронные данные и age-aware якорь

> **Статус: proposed.** Заготовка этапа 4 плана
> [F-18-remediation](../../implementation-plan/F-18-remediation.tasks.md).
> Расширяет ADR-070. Содержание дорабатывает `data-schema-designer` +
> `trading-domain-specialist` после сессии 2 с экспертом (вопрос: «каких
> площадок, пар и какой свежести данных достаточно»).

## Контекст

Разбор (HEAD 02eafef): стакан Binance по паре обновляется раз в ≈25.5 с,
возраст 0–26 с; `market_data` переиспользует последнюю кривую в каждом секундном
окне и принимает кривые до 60 с. Полка (dead zone) переводчика = 0. Разница
возрастов якорей ≈20 с даёт кажущийся базис ≈3.8 б.п. — больше полки цикла 3 б.п.,
и клиринг гонит поток по **шуму устаревания** (фантомный поток).

## Решение (предлагается)

- Писать **биржевое время** снимка по площадке в `ce.clearing.input` и ClickHouse.
- Якорь строить **только из снимков не старше допуска** (допуск — решение сессии 2).
- Полка, растущая с возрастом снимка: `c_v ≥ k·σ·√возраст` (неопределённость
  устаревшей цены).
- Для основных пар — WebSocket или учащённый опрос (сократить возраст у источника).

## Альтернативы

- Статус-кво (кривые до 60 с, полка 0). Отклоняется: фантомный поток.
- Только синхронизация без age-aware полки. Отклоняется: остаточный шум на
  близких возрастах.

## Последствия

- Доля фантомного потока падает (<10%); поток запускается реальным базисом, не шумом.
- Нужно биржевое время в снимках (миграция схемы ClickHouse), связка «модуль
  потока ↔ разность возрастов».

## Обратимость

Обратимо порогом допуска возраста и флагом age-aware полки. Откат = прежний
приём кривых до 60 с. После приёмки (p90 разности возрастов ≤ допуска)
фиксируется.

## Реализация (частичная — механизм age-полки, деф-безопасно)

Домен-функция `BuildQuoteAgent` (`agent_builder.hpp`) расширена членом полки
`c += k·σ·√(age_sec)` через поля `AgentBuilderConfig{snapshot_age_ms, sigma_pm,
age_dead_zone_k}`. Деф `age_dead_zone_k=0` ⇒ член нулевой (прежнее поведение).
Unit-тест (`agent_builder_test.cpp`) проверяет дельту `+k·σ·√age` и нули при
k/σ/age=0. До 2026-10-14 к caller (`market_data_uc.cpp`) не подключено (`Book` не нёс
возраст снимка; σ из `vol_state_` требовала ревью локинга) — см. подраздел ниже. Существующий staleness-дроп кривых (`vector_stale_ms_`, на dev 60 с) уже есть.

### Подключено к caller (2026-10-14, деф-безопасно)

`MarketDataUseCases::BuildAndPublishCeClearingInput` получает время события каждой кривой
(`FlushVectorWindow` → `curve_ts_ms`, ключ `venue|SYMBOL`), `Book.ts_ms` = время кривой. При
`CE_AGE_DEAD_ZONE_K>0` для каждой книги берётся σ пары из EWMA `vol_state_` (`SigmaSnapshot`: короткий
`mu_`, раз на окно, поток окна `mu_` не держит) и в `AgentBuilderConfig` кладутся
`sigma_pm=σ·1000` (‰/√с), `snapshot_age_ms = window_close − ts` и `age_dead_zone_k`. Нет σ или
времени кривой ⇒ полка без age-члена (счётчик `no_sigma` в логе `CE clearing: age-aware полка`).
Деф `CE_AGE_DEAD_ZONE_K=0` ⇒ σ не читается, поведение и входной топик байт-в-байт как раньше.
Env: `CE_AGE_DEAD_ZONE_K` (деф 0), `CE_AGE_SIGMA_MIN_SAMPLES` (деф 20).

**Калибровка k по измерению EXP-2026-10-14.** σ пар на dev 3,5·10⁻⁵–7,7·10⁻⁵ на √с (0,035–0,077‰/√с,
`ce_asset_volatility`, совпадает с реальным движением цены); возраст якоря p50 12–16 с ⇒ член
`k·σ·√age` ≈ 0,12–0,30‰·k на агента. Измеренный фантомный базис ETH/USDT σ = 0,223‰ при сумме полок
цикла 0,30‰: при k=1 два переводчика с возрастом ~14 с дают ≈ 0,32‰ дополнительной полки — фантом в
основном поглощается. Рекомендуемый пробный диапазон k ∈ [0,5; 1,5]; критерий приёмки — доля тактов с
|базис| > суммы полок у CE ≈ доле по живым ценам (13,4 % → ≈ 2 %), без потери реальных арбитражей.
**Ограничение:** σ — EWMA по `mid` активов из ВСЕХ снимков (`ProcessSnapshot`), для кросс-пар берётся σ
символа пары (`ETHBTC`); межбиржевой шум в EWMA возможен, поэтому k подбирается по доле, а не по теории.



## Результат калибровки (2026-10-15) — k не решает проблему

Замер на живых данных (EXP-2026-10-14-clearing-diagnosis, «Калибровка k»): при возрасте якоря 12–16 с ни одно k не
отделяет фантомный базис от реального — при k=0 точность триггеров CE ≈ 25 %, полнота ≈ 42 %; при k≥0,5 реальные
возможности пропускаются целиком. Age-полка (`CE_AGE_DEAD_ZONE_K`) остаётся **предохранителем** (на dev k=1,0: система
почти не торгует, но и не гоняет фантомы). Основное лечение — п. 1 «Решения» этого ADR: клиринг должен получать якоря
со временем снимка ≤ 1–2 с (сегодня каденция основного цикла `venues` ≈ 25 с на пару).
