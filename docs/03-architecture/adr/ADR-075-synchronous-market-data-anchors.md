# ADR-075 — Синхронные данные и age-aware якорь

> **Статус: proposed.** Заготовка этапа 4 плана
> [F-18-remediation](../../implementation-plan/F-18-remediation.tasks.md).
> Расширяет ADR-070. Содержание дорабатывает `data-schema-designer` +
> `trading-domain-specialist` после сессии 2 с экспертом (вопрос: «каких
> площадок, пар и какой свежести данных достаточно»).

## Контекст

Разбор (HEAD 02eafef): стакан Binance по паре обновляется раз в ≈25.5 с,
возраст 0–26 с; `market_data` переиспользует последнюю кривую в каждом секундном
окне и принимает кривые до 60 с. Полка (dead zone) переводчика = 0. Разница
возрастов якорей ≈20 с даёт кажущийся базис ≈3.8 б.п. — больше полки цикла 3 б.п.,
и клиринг гонит поток по **шуму устаревания** (фантомный поток).

## Решение (предлагается)

- Писать **биржевое время** снимка по площадке в `ce.clearing.input` и ClickHouse.
- Якорь строить **только из снимков не старше допуска** (допуск — решение сессии 2).
- Полка, растущая с возрастом снимка: `c_v ≥ k·σ·√возраст` (неопределённость
  устаревшей цены).
- Для основных пар — WebSocket или учащённый опрос (сократить возраст у источника).

## Альтернативы

- Статус-кво (кривые до 60 с, полка 0). Отклоняется: фантомный поток.
- Только синхронизация без age-aware полки. Отклоняется: остаточный шум на
  близких возрастах.

## Последствия

- Доля фантомного потока падает (<10%); поток запускается реальным базисом, не шумом.
- Нужно биржевое время в снимках (миграция схемы ClickHouse), связка «модуль
  потока ↔ разность возрастов».

## Обратимость

Обратимо порогом допуска возраста и флагом age-aware полки. Откат = прежний
приём кривых до 60 с. После приёмки (p90 разности возрастов ≤ допуска)
фиксируется.
