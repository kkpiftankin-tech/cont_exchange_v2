# ADR-087 — Заработок агентов CE: внутренняя биржа, внешние биржи, итого

> **Статус: accepted (2026-10-28).** Определения R и U для внутренней и внешней бирж сформулированы по просьбе владельца («дайте ваши определения, чтобы мы одинаково понимали друг друга») и утверждены им в тот же день («ваши определения корректны, делайте реализацию в соответствии с вашими определениями»). Эта редакция заменяет первую (учёт по средней себестоимости с внутренним U и выходом по цене исполнения хеджа), которая отклонена владельцем: на внутренней бирже всё реализуется в такте клиринга, поэтому нереализованного там быть не может, а сумма результата по всем агентам обязана равняться нулю. Все формулы живут в одном месте — карточке [CALC-CE-AGENT-PNL](../../04-domain/calculations/CALC-CE-AGENT-PNL.md). Владеющая capability — `CAP-F18-AGENT-PNL` (feature F-18), записи изменения — `CR-F18-002`, `CR-F18-003`, `CR-F18-004`.

## Контекст

Владелец просит вкладку «PnL» показывать по каждому агенту (переводчику и связке) три группы столбцов, в каждой R (реализованный результат), U (нереализованный) и R+U: **внутренняя биржа CE**, **внешние биржи**, **итого** (внутренняя плюс внешние). Расчёт должен идти в сервисах, а не на фронте, а числа панели «Живые позиции» и вкладки «PnL» должны считаться и храниться в одном месте.

Что есть сейчас:

- Внутренняя биржа CE — клиринг, в котором агенты (переводчики и связки) обмениваются активом друг с другом по цене узла (пара «актив + площадка»). Сделка внутри клиринга исполняется в такте целиком: у неё всегда есть покупатель и продавец, комиссии нет.
- Внешние биржи — реальные площадки, куда агент выходит хеджем, когда его позиция $c$ (обещание, не отправленное наружу) выходит за полосу.
- Справедливая цена $F_0$ — цена пары до сдвига якоря (поправки цены в сторону накопленной позиции агента, ADR-072); matching считает её одну на пару, глубинно-взвешенно по биржам, и присылает вместе с дельтой переводчика. У связки собственной $F_0$ нет.
- Для оценки сделок у ledger на каждой дельте клиринга уже есть всё нужное: изменение позиции агента, цена узла (`price_used`), цена базового актива в USDT (`base_price`), справедливая цена (`fair_price`).

## Решение

1. **Три группы по каждому агенту, всё в USDT, без комиссий.** Внутренняя биржа: $R_{int}$, $U_{int}$, $R_{int}+U_{int}$. Внешние биржи (все вместе): $R_{ext}$, $U_{ext}$, $R_{ext}+U_{ext}$. Итого: $R=R_{int}+R_{ext}$, $U=U_{int}+U_{ext}$, $R+U$ — точный результат агента. Строка «все агенты» — те же суммы по агентам.

2. **Внутренняя биржа: всё реализуется в такте клиринга.** Результат сделки — выгода относительно справедливой цены пары в момент сделки: $R_{int}=\sum (F_0-p)\cdot dL$, где $dL$ — знаковое число штук (покупка плюс, продажа минус), $p$ — цена узла. Купил дешевле справедливой цены — плюс, продал дороже — плюс. $U_{int}=0$ всегда: нереализованного на внутренней бирже нет, потому что сделка исполнена целиком. Следствие, проверяемое на каждом такте: сумма $R_{int}$ по всем агентам равна нулю (у каждой сделки покупатель и продавец дают противоположные величины, цена и $F_0$ у них общие).

3. **Позиция, возникшая из внутренних сделок, хранится по справедливой стоимости входа.** Агент после сделки держит остаток $L$ (штуки базового актива, плюс — длинная позиция). Каждая единица остатка помнит $F_{in}$ — справедливую цену пары в такт, когда она возникла (для остатка из нескольких сделок — среднюю, взвешенную по штукам). Это единственная «цена входа» в модели: цена клиринга $p$ в неё не входит, её разница с $F_0$ уже учтена в $R_{int}$.

4. **Внешние биржи: закрытие позиции и остаток.** Остаток закрывается хеджем на внешней бирже (продажа закрывает длинную позицию, покупка — короткую). На закрытой части $k$ реализуется результат $R_{ext}$ из двух слагаемых: **качество исполнения** $s\,(p_f-F_0^{\text{исп}})\,q$ (цена исполнения $p_f$ против справедливой цены пары в момент исполнения; $s=+1$ для продажи, $-1$ для покупки) и **дрейф справедливой цены** $\operatorname{sign}(L)\,(F_0^{\text{закр}}-F_{in})\,k$ (на сколько сдвинулась справедливая цена с момента, когда единица позиции возникла). Вместе они дают $s\,(p_f-F_{in})\,q$. $U_{ext}=L\,(F_0^{\text{сейчас}}-F_{in})$ — ещё не захеджированный остаток по текущей справедливой цене. Пояснение к определению: дрейф реализуется при любом закрытии позиции, в том числе встречной внутренней сделкой (агент выходит в ноль без внешней заявки); иначе он терялся бы и $R+U$ не совпадал бы с результатом по кассе. Цена входа единицы позиции — $F_0$ на момент, когда позиция возникла (решение владельца), а не на момент исполнения хеджа: поэтому задержка хеджа попадает в результат внешней группы, где ей и место.

5. **Что считать покупкой, а что продажей.** Количество сделки получается из изменения позиции $\Delta c$ (тыс. USDT) и цены базового актива $P_b$ (USDT за штуку): $dL=\sigma\,\Delta c\cdot 1000/P_b$.
   - **Переводчик, $\sigma=+1$.** Поток по ребру переводчика забирает актив из его узла: агент получает актив внутри CE (покупка) и затем продаёт наружу; поэтому $c>0$ — длинная позиция, её закрывает внешняя продажа.
   - **Связка, $\sigma=-1$.** Нога источника получает $-f$ (покупка по цене узла источника), нога назначения $+f$ (продажа по цене узла назначения). Книга связки одна на агента, а не по ногам: покупка на источнике и продажа на назначении в одном такте — одна круговая сделка, её выгода $(F_0-p_{src})\,q_{src}+(p_{dst}-F_0)\,q_{dst}$ реализуется сразу. Остаток паритета ($q_{src}-q_{dst}$, у ног одинаковая стоимость, разные цены) остаётся её позицией по $F_{in}$ и лежит в её внешнем $U$.
   - **Справедливая цена связки.** Собственной $F_0$ у связки нет, поэтому её сделки оцениваются по $F_0$ переводчиков того же актива: сначала из того же такта (одна на пару), иначе по последнему известному значению не старше `CE_AGENT_PNL_FAIR_MAX_AGE_MS` (30 с); для кросс-актива — $F_0$ пары, умноженная на справедливую USDT-цену валюты котировки этого же такта. Нет свежей $F_0$ — цена сделки (выгода ноль, отклонение суммы увидит диагностика п. 9), а $U$ остатка связки не определён.
   - **Справедливая цена переводчика.** Метка $U$ и цена его хеджа берутся по $F_0$ пары (последняя дельта любого переводчика пары; $F_0$ в matching общая для пары), иначе по собственной: так метки у агентов одной пары не расходятся, пока у части из них поток в мёртвой зоне.
   - **Хедж связки.** В книгу не пишется: знак её рыночного хеджа (по знаку позиции ноги) противоположен знаку её книги, и закрывает ли он книгу, решает владелец (OQ-F18v2-31); с ADR-083 такого хеджа нет.

6. **Перевод в USDT.** Значения книги копятся в валюте котировки пары (для пар к USDT это сразу USDT). Для кросс-пар вроде ETH/BTC при выдаче умножаем на курс валюты котировки $\rho=P_b/F_0$ (USDT за единицу котировки) на момент выдачи.

7. **Где считается и что известно.** Всё в ledger на типе `Decimal`: накопление в обработчиках дельт клиринга и отчётов хеджа, выдача готовых чисел вызовом `GetAgentPnl` (по группам, итогам и видам агентов). BFF только пересылает ответ, фронт только рисует. R и U известны независимо (поля `has_data` и `u_has_data`): $R$ цены оценки не требует и известен сразу после перезапуска ledger, $U$ требует текущей справедливой цены остатка и появляется с первой дельтой после перезапуска; «нет данных» не отдаётся нулём. Контракты — [ledger-agent-pnl](../../06-api/grpc/ledger-agent-pnl.md), [agent-pnl](../../06-api/rest/agent-pnl.md).

8. **Хранение и перезапуск.** Книга агента — таблица `ce_agent_pnl_book` (одна строка на агента: остаток, справедливая стоимость входа, накопленные $R_{int}$ и $R_{ext}$, валюта котировки, последний учтённый такт, начало накопления). Книга переводчика при создании засевается его текущей позицией по $F_0$: $U=0$ в момент старта. Книга создаётся и при первом хеджевом исполнении (для позиции, накопленной до учёта), если известны $F_0$ и цена базы. Повторная доставка того же такта книгу не удваивает (сверка по последнему учтённому такту). Сброс позиций обнуляет книги. Значения прежней редакции (по средней себестоимости) в новую модель не пересчитываются: при миграции схемы они удаляются, учёт начинается заново с момента выкладки. Если при старте книги прочитать не удалось, учёт приостанавливается (`GetAgentPnl` отдаёт «нет данных», повторная загрузка раз в 30 с, `CE_AGENT_PNL_RETRY_MS`), позиции агентов работают по-прежнему. Порядок выкладки: миграция БД, затем ledger, затем BFF и фронт.

9. **Диагностика нулевой суммы.** На каждом такте ledger считает сумму и оборот выгод $\sum(F_0-p)\,dL$ по всем сделкам такта (в USDT); отклонение больше 0,001 USDT и больше 0,1 % оборота пишется предупреждением в журнал (не каждое: первое и затем каждое пятидесятое). Причины отклонения — дельта без цены, нет $F_0$ у части агентов, дом или нумерарий в такте, разные цены базы на узлах одной пары.

10. **Панель «Живые позиции», ряд для графика и вкладка «PnL» читают одни и те же числа из ledger** (решение владельца 2026-10-28). BFF не считает R и U. Колонка «заработок R / U» панели — внешняя группа записи агента из `GetAgentPnl`, внутренняя и итоговая лежат в той же строке; итоги «переводчики», «арбитражёры», «вместе» приходят из ledger (`by_kind`, `totals`). Семплер истории берёт числа из тех же строк. Вне решения и не относятся к R и U: выгода по теории $S$, базис и открытая позиция арбитражёров, количества сделок и разложение позиции на ноги — они считаются в BFF и показываются только в панели (known-gaps).

11. **Выключатель.** Переменная окружения `CE_AGENT_PNL_ENABLED` (по умолчанию 1): при 0 ledger не ведёт книги, вызов возвращает пустой список.

## Альтернативы

- **Учёт по средней себестоимости цен клиринга, с внутренним U (первая редакция).** Отклонено владельцем: внутренний U получался накопленным оборотом сделок, а не «ещё не проданным»; сумма $R$ по агентам не равнялась нулю; на внутренней бирже, где всё реализуется в такте, нереализованного быть не должно.
- **Независимые книги без выхода при хедже.** Итог точный, но внутренний и внешний U становятся крупными противоположными числами и расходятся с позицией на экране — отклонено.
- **Выгода клиринга $S$ как внутренний R.** Отклонено: это теоретическая оценка по кривым, не результат сделок; карточка запрещает складывать её с R и U.
- **Считать внутренний результат в BFF.** Отклонено: требование владельца считать в сервисах; BFF не видит внутренних сделок.
- **Цена входа единицы позиции — $F_0$ на момент исполнения хеджа.** Отклонено владельцем: задержка хеджа и дрейф справедливой цены за время ожидания должны попадать в результат внешней группы, а не пропадать.
- **Книга по каждой ноге связки отдельно.** Отклонено: покупка на источнике и продажа на назначении — одна круговая сделка.

## Последствия

**Положительные:**

- Определения совпадают с физикой внутренней биржи: всё реализуется сразу, $U_{int}=0$, $\sum R_{int}=0$ — это проверяемый инвариант (тест и диагностика такта).
- $R+U$ каждого агента равно результату по кассе (тесты сверяют с прямым пересчётом); качество исполнения и дрейф справедливой цены разделены и видны.
- Расчёт и хранение в одном месте (ledger, `Decimal`); браузер и BFF не выполняют арифметику над R и U.
- $R$ известен сразу после перезапуска ledger, не дожидаясь цены.

**Отрицательные и ограничения:**

- **Накопление начинается заново при выкладке** (значения прежней редакции удалены), и ряд `ce_agent_pnl_history` до выкладки записан по прежним формулам: на графике виден разрыв, прежние точки не пересчитываются.
- **Справедливая цена связки заимствована у переводчиков.** Если переводчиков актива в такте нет, берётся последнее известное значение; возраст отдаётся в ответе (`mark_age_ms`).
- **Позиция $c$ хранится в стоимости, книга — в штуках.** При дрейфе цены проданное количество не равно купленному, в книге остаётся «пыль» в штуках; это реальный остаток актива.
- **Частичные исполнения учитываются приближённо** (цена отчёта — накопленная средняя заявки, количество — прирост).
- **Хедж по позиции, накопленной до учёта, без известной $F_0$** (сразу после перезапуска, до первой дельты) в $R_{ext}$ не попадёт: книгу заводить не из чего.
- **Кросс-пары** пересчитываются в USDT по курсу на момент выдачи, а не на момент сделки; курс различается между агентами пары на доли процента, поэтому сумма $R_{int}$ по кросс-паре в USDT нулевая лишь с этой точностью.
- **Внутренний R связки «бумажный»**: выгода круга лежит остатком в натуре, реализация в деньги — физический перевод (ADR-084); вопрос о двойном счёте с прибылью счёта дома (ADR-068) — OQ-F18v2-28.
- Новая денежная логика в ledger: обязательное ревью (`code-reviewer`, money invariants), модульные тесты на `Decimal`.

## Обратимость

Высокая. Новый вызов, новые поля и таблица добавляются без нарушения совместимости; выключатель `CE_AGENT_PNL_ENABLED=0` останавливает накопление. Миграция схемы необратима по данным прежней редакции (они удалены), но эти значения производные и пересчитать их в новую модель нельзя по определению. Сменить правило цены связки или диагностику можно правкой одной функции и карточки CALC.

## Проверка (приёмка)

- **Пример владельца.** Покупка 1 BTC по 80 010 при $F_0=80\,000$ даёт $R_{int}=-10$; хедж SELL 0,6 BTC по 80 040 при $F_0=80\,030$ даёт $R_{ext}=24$ (6 исполнение и 18 дрейф); остаток 0,4 BTC при $F_0=80\,030$ даёт $U_{ext}=12$; итого $R=14$, $U=12$, $R+U=26$ (прямой пересчёт по кассе тоже 26).
- **Нулевая сумма.** Сумма $R_{int}$ по всем агентам замкнутого цикла «переводчик — связка — переводчик» равна нулю; $U_{int}=0$ у каждого.
- **Результат по кассе.** Для переводчика, вышедшего хеджем, $R+U$ равен кассовому результату; выход позже при другой $F_0$ даёт тот же $R_{ext}$ по закрытой позиции.
- **Круговая сделка связки.** Покупка на источнике и продажа на назначении дают $R_{int}$ по формуле п. 5, остаток паритета остаётся в $U_{ext}$.
- **Перезапуск, сброс, повтор.** После перезапуска $R$ известен сразу, $U$ — после первой цены; сброс обнуляет всё; повторная доставка такта книгу не меняет.
- **Источник.** Браузер и BFF не выполняют арифметику над R и U.
