# CALC-CE-LINK-TRANSFER — перевод связки между биржами

## 1. Смысл

Связка (арбитражёр) по теории закрывает накопленный перекос запасов между двумя биржами **физическим переводом актива**, а не рыночными заявками. Её позиция по одной бирже положительна (дефицит, нужен приход), по другой отрицательна (избыток, откуда везти). Когда положительная позиция превысила порог, ledger сбрасывает обе ноги к цели и ставит смоделированный перевод; остатки бирж меняются через несколько тактов.

## 2. Формулы

Обозначения: $c_d>0$ — позиция ноги назначения, $c_s<0$ — ноги источника (тыс. USDT); $P_s$, $P_d$ — цены актива в USDT на узлах источника и назначения (`base_price` ног); $c_{tr}$ — плата за перевод, б.п.; $k_{band}$ — коэффициент ширины полосы, тыс. USDT на б.п.; $q_{\text{пол}}$ — пол порога.

Порог перевода:

$$
\bar Z_A=\max\bigl(q_{\text{пол}},\ k_{band}\,c_{tr}\bigr)
$$

(ручная ширина ADR-081 подменяет порог заданным $q_{lim}$; при $k_{band}\le 0$ порог плоский `CE_AGENT_BAND_Q_ARBITRAGEUR`.) Перевод запускается при $c_d>\bar Z_A$ (строго). Цель и сумма:

$$
Z_{targ}=\varphi\,\bar Z_A,\qquad X=\min\bigl(c_d-Z_{targ},\ |c_s|\bigr),\qquad X\ge X_{min}
$$

Позиции: $c_d\leftarrow c_d-X$, $c_s\leftarrow c_s+X$. Штуки актива, уходящие с источника, и приход на назначение:

$$
x=\left\lfloor \frac{1000\,X}{P_s}\right\rfloor_{8},\qquad \text{приход}=x\,(1-\text{fee}),\quad \text{fee}=\frac{\text{bps}}{10^{4}}
$$

Остаток паритета (штуки, диагностика):

$$
r=1000\,X\left(\frac{1}{P_s}-\frac{1}{P_d}\right)
$$

## 3. Числовой пример

BTC, ребро `A_BTC_binance_okx`, fee симуляции 10 б.п., $k_{band}=0{,}2$, $c_{tr}=2{,}5$ б.п., $q_{\text{пол}}=1{,}0$, $\varphi=0{,}5$, $P_s=65\,000$ (binance), $P_d=65\,013$ (okx).

| Шаг | Значение |
| --- | --- |
| порог | $\bar Z_A=\max(1{,}0;\ 0{,}2\cdot 2{,}5)=1{,}0$ |
| входные позиции | $c_d=+1{,}8$ (okx), $c_s=-1{,}8$ (binance), $1{,}8>1{,}0$ — перевод запускается |
| цель, сумма | $Z_{targ}=0{,}5$, $X=\min(1{,}3;\ 1{,}8)=1{,}3$ |
| позиции после | $c_d=+0{,}5$, $c_s=-0{,}5$ |
| штуки | $x=1300/65000=0{,}02$ BTC |
| остатки через 3 такта | binance $-0{,}02$; okx $+0{,}01998$; сумма по BTC изменилась на $-0{,}00002$ = $-\text{fee}\cdot x$ |
| остаток паритета | $r=1300\,(1/65000-1/65013)\approx 4{,}0\cdot 10^{-6}$ BTC |

Граничные случаи (все покрыты тестом): $c_d=1{,}0$ — перевода нет; $c_d=1{,}8,\ c_s=-0{,}9$ — $X=0{,}9$, $c_s\to 0$; $P_s=0$ — пропуск; $c_d=1{,}02,\ \varphi=0{,}99$ — $X=0{,}03<0{,}05$, пропуск.

## 4. Инварианты

- Сумма ног связки $c_d+c_s$ перевод сохраняет.
- Сумма остатков по валюте по всем биржам при fee = 0 перевод не меняет; при fee ≠ 0 меняется на $-\text{fee}\cdot x$.
- Монитор узлового баланса: $(W\,c)_n+\text{moved}_n=0$ ($\text{moved}$ — сдвиг от переводов, `transfer_moved` ноги).
- Повтор такта (`batch_id`) и повтор `transfer_id` второго перевода не создают.
- $0\le\varphi<1$ (иначе 0,5), $X>0$, $X\ge X_{min}$, цены обеих ног положительны.

## 5. Открытое

- $k_{band}$ взят от переводчика; теория требует $\Gamma_A$ связки по дисперсии базиса за время перевода.
- Остатки бирж и очередь переводов живут в памяти ledger (перезапуск обнуляет оба); постоянный учёт нужен до боевого режима.
- Остаток паритета измеряется, ведомость по нему не ведётся (теория, блок 6).
- Плата в пороге ($c_{tr}$ = 2,5 б.п.) и плата симуляции (0) различаются осознанно (тариф клиринга 0, ADR-080).
