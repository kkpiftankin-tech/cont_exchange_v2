# CALC-CE-SYSTEM-PNL — P&L системы и инварианты

> **Статус: proposed.** Заготовка этапа 1 плана
> [F-18-remediation](../../../implementation-plan/F-18-remediation.tasks.md).
> Содержание дорабатывает `trading-domain-specialist` + `test-architect`.

## Зачем

Экранный «заработок R» (`ledger_uc.cpp:2082–2095`) = Σ s·(p_f − F_0^экр)·q, где
F_0^экр — среднее **устаревших** мидов в момент филла. Это не истинный P&L.
Истинный результат режима «без клиентов» — **MTM реальных остатков**
(переоценка по текущим мидам всех площадок). Карточка фиксирует определение и
инварианты сведения.

## Определение (предлагается)

$$\text{P\&L}_{\text{система}}(t)=\sum_{a,v}\bigl(\text{остаток}_{a,v}\cdot m_v^{a}(t)\bigr)-\text{капитал}_0$$

Разложение по агентам (сумма = P&L системы):
тариф/излишек в клиринге + исполнение к миду $A$ + перенос открытой позиции +
комиссии. Разложение одного филла переводчика (из разбора):
$s(p_f-F_0^{экр}) = \underbrace{s(p_f-m_v)}_{A}+\underbrace{s(m_v-\bar F)}_{B:\ базис}+\underbrace{s(\bar F-F_0^{экр})}_{C:\ ошибка\ F_0}$.

## Инварианты (тесты этапа 1)

- **W·c = 0** — Σ позиций агентов в каждом узле `актив@площадка` = 0
  (CE_algorithm_v2 §A6). До этапа 2 «красный» ровно для ног арбитражёров.
- `c + in_flight = I − F` на каждом статусе отчёта (нет утечки in_flight).
- `Σ P&L агентов + дом = P&L системы` (сходится до 0.01 USDT за 24ч).
