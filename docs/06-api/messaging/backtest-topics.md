# Backtest Topics (F-15 replay isolation)

Topics scoped to **backtest / replay** that must NEVER share wire-channels with
live production traffic. Same isolation pattern as the `sim.*` family
([sim-topics.md](sim-topics.md)) — codified in ADR-015.

| Topic | Schema | Producer | Consumers | Partition key | Retention |
| --- | --- | --- | --- | --- | --- |
| `backtest.execution.groups` | `fob.matching.v1.ExecutionGroup` (same wire contract as live `execution.groups`, isolated by topic) | `backtest` (F-15 replay engine) | `backtest` (`grouped_replay_results` ClickHouse sink); never any live consumer | `parentOrderId` | 7 d |

## `backtest.execution.groups`

### Purpose

Carries `ExecutionGroup` envelopes (F-09 grouped/multi-leg execution result)
generated by the F-15 replay engine when replaying historical batches that
contained grouped orders. Lives in a separate topic so:

1. **Replay traffic cannot affect production accounting.** Live ledger,
   risk, observability consumers never subscribe to `backtest.*` topics —
   any accidental subscription is a contract violation.
2. **Parity checks remain possible.** `backtest_uc` parity logic compares
   `backtest.execution.groups[batch_id]` ↔ live `execution.groups[batch_id]`
   side-by-side to detect solver/router drift.
3. **Retention isolation.** Replay runs can spike topic volume without
   affecting live retention budgets.

### Key invariants

- `event_id` (UUID) per envelope — idempotent on the ClickHouse sink.
- `parentOrderId` partition key keeps an entire combo's legs in a single
  partition, mirroring the live `execution.groups` topic.
- `meta.source = "backtest"` (NOT "matching") — consumer-side guard. Live
  consumers fail-fast if they see `source = "backtest"` (defensive coding).
