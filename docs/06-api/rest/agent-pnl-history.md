# REST: история заработка агента и поля панели «Живые позиции»

Два изменения контракта BFF (`frontend/api/server.js`) для панели «Живые позиции» на экране клиринга.

## 1. GET /api/vector-clearing/agent-pnl-history

График заработка агента во времени (открывается по клику на агента). Читает `ce_agent_pnl_history` и размечает ответ чистой функцией `buildPnlHistoryDto` (`frontend/api/agent_pnl_history.js`); ничего не пересчитывает.

### Параметры запроса

| Параметр | Обязателен | Смысл |
| --- | --- | --- |
| `agent_id` | да | идентификатор агента; пусто ⇒ `400 {"error":"agent_id_required"}` |
| `hours` | нет | окно в часах, 1…168, по умолчанию 24; выходящее за границы значение приводится к границе |

### Ответ 200

```json
{
  "agent_id": "T_BTC_binance",
  "window_hours": 24,
  "since_ms": 1792420000000,
  "first_ms": 1792430000000,
  "points": [
    { "t": 1792430000000, "r": 1.25, "u": -0.40, "total": 0.85 },
    { "t": 1792430060000, "r": 1.25, "u": -0.10, "total": 1.15 }
  ],
  "has_data": true,
  "has_surplus": true,
  "surplus_total": 41.7,
  "surplus_coverage": 0.97,
  "generatedAt": "2026-10-22T08:00:00.000Z"
}
```

| Поле | Смысл |
| --- | --- |
| `points[].t` | момент выборки, мс с эпохи; по возрастанию |
| `points[].r` | R, реализованный заработок, USDT; `null` — не определён |
| `points[].u` | U, нереализованный результат, USDT; `null` — не определён |
| `points[].total` | R + U; если одной части нет, равен имеющейся (нет U ⇒ `total = r`) |
| `points[].s` | накопленная внутри окна выгода участника в клиринге по теории, USDT (CALC-CE-CLEARING-SURPLUS); `null` — выгоды в окне нет |
| `first_ms` | момент первой точки окна; `null` без точек |
| `has_surplus`, `surplus_total`, `surplus_coverage` | есть ли выгода в окне, её сумма за окно и доля учтённых тактов (0…1) |
| `has_data` | есть ли хотя бы одна точка; иначе экран объясняет, что история копится с момента включения записи |

Ряд прореживается до 500 точек: в каждом интервале берётся последняя точка, первая и последняя точки окна сохраняются.

### Ошибки

| Код | Причина |
| --- | --- |
| 400 | не задан `agent_id` |
| 502 | ошибка PostgreSQL (`{"error":"pg_error","message":…}`) |
| 503 | PostgreSQL недоступен |

## 2. GET /api/vector-clearing/agent-positions — новые поля строки агента

Заявки и сделки теперь берутся из `child_orders` (накопленное исполнение каждой заявки, включая дозаполнение резидентных лимитов ADR-067), а не из `venue_fill_diagnostics`, которая фиксирует только первый такт заявки и занижает исполнение. Разметка — `frontend/api/hedge_orders_view.js` (`buildHedgeMap`) и `frontend/api/trade_stats_math.js` (`combineTradeStatsByVenue`).

| Поле | Смысл |
| --- | --- |
| `hedge_symbol`, `hedge_side`, `hedge_venue`, `hedge_sent`, `hedge_filled`, `hedge_status`, `hedge_ms` | самая свежая заявка агента (как раньше); `hedge_symbol` в виде `BASE/QUOTE` (`BTC/USDT`), по нему панель выбирает строку валюты; `hedge_status`: `NEW`, `PARTIALLY_FILLED`, `FILLED`, `EXPIRED`, `REJECTED` (в БД `PENDING` ⇒ `NEW`, `CANCELLED` ⇒ `EXPIRED`) |
| `hedge_by_venue` | новое: последняя заявка агента на каждой бирже `{ venue: { symbol, side, sent, filled, status, ms } }`; арбитражёр хеджирует обе ноги, и панель показывает заявку в строке ноги своей биржи |
| `trade_by_venue` | новое: сделки агента по биржам `{ venue: { traded_base, traded_quote, trade_fills } }` (знаковые: покупка +, продажа −); на экране база и квота показаны в одном столбце «сделки» |
| `traded_base`, `traded_quote`, `trade_fills` | итог по агенту (количества по `child_orders` с момента сброса статистики), без изменений смысла |
| `realized_usdt`, `unrealized_usdt`, `pnl_usdt` | **с 2026-10-28 (ADR-087 п. 10): внешняя группа R, U, R+U из ledger (`GetAgentPnl`)**, а не расчёт BFF по `child_orders`; `null`, если соответствующая часть неизвестна или ledger недоступен: `realized_usdt` и `unrealized_usdt` независимы (R известен без текущей цены, U — только с ней), `pnl_usdt` задан только при обоих. Накапливаются с отметки внедрения учёта или последнего сброса позиций |
| `pnl_internal`, `pnl_total`, `pnl_since_ms` | новое: внутренняя и итоговая группы того же агента (`{has_data, u_has_data, r, u, r_plus_u}`) и начало накопления, мс; те же числа, что на вкладке «PnL» |
| `pnl_totals` (корень ответа) | новое: итоги заработка из ledger `{ translator, arbitrageur, all }`, каждый — `{internal, external, total, ...}`; панель их показывает, не складывает; `null`, если ledger недоступен |
| `surplus_usdt`, `surplus_coverage` | новое (ADR-083): выгода участника в клиринге по теории, накопленная с момента сброса статистики (USDT), и доля учтённых тактов; нет данных — поля отсутствуют. Оценка относительно кривой агента, не деньги в кассе |

Старые клиенты не ломаются: прежние поля сохранены, новые добавлены.

## Экран

Панель «Живые позиции»: двухъярусная шапка — слева «Внутренняя биржа CE — позиция агента» (нога, было, дельта, стало), справа «Внешняя биржа — хедж и результат» (отправлено, исполнено, сделки, заработок R / U). «Отправлено» и «исполнено» стоят в строке той валюты, которую торгует заявка (по BTC/USDT — в строке BTC); у арбитражёра — в строке ноги по бирже заявки. Под таблицами — объяснение R и U простыми словами. Клик по агенту открывает окно с графиком (окна 1 ч, 6 ч, 24 ч, 7 дн; обновление раз в 30 с) и далее прежним разбором. Под графиком три чекбокса «показать»: R, U, R + U (по умолчанию R и R + U; выбор запоминается в браузере). Ось значений подгоняется под отмеченные ряды и не обязана включать ноль, поэтому малый R рядом с большим U не сплющивается в прямую: достаточно оставить одну галочку. Пунктир нуля показан, только если ноль попадает в диапазон отмеченных рядов. Четвёртый ряд — «S выгода» (накопленная за окно выгода в клиринге по теории); по умолчанию скрыт. У агента без внешних сделок (связка после ADR-083) нет R и U: график открывается на выгоде S, остальные галочки неактивны. Все ряды приходят из BFF готовыми (`r`, `u`, `total`, `s`), браузер ничего не считает.
