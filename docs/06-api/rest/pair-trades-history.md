# REST: GET /api/vector-clearing/pair-trades-history

График «Сделки на внешних биржах по парам» на вкладке «PnL» (`/hedge-pnl-live`): по каждой паре валют накопленный объём базовой валюты и цены покупки и продажи (во второй валюте пары) по состоявшимся хедж-заявкам агентов CE. Маршрут BFF (`frontend/api/server.js`): SQL-агрегат `loadPairTradesRows` по `child_orders` и чистая функция `buildPairTradesDto` (`frontend/api/pair_trades_history.js`). Все числа посчитаны в BFF, браузер только рисует. Формулы и граничные случаи — [CALC-CE-PAIR-TRADES](../../04-domain/calculations/CALC-CE-PAIR-TRADES.md). Ledger при чтении не вызывается.

## Параметры запроса

| Параметр | Обязателен | Смысл |
| --- | --- | --- |
| `hours` | нет | окно в часах: по умолчанию 24 (и при нуле или нечисле), не больше 168, не меньше 1; от окна зависит размер интервала (до 1 ч включительно — 1 мин; до 6 ч — 5 мин; до 24 ч — 15 мин; больше суток — 1 ч) |

## Ответ 200

```json
{
  "window_hours": 24,
  "bucket_ms": 900000,
  "since_ms": 1793109600000,
  "first_ms": 1793114100000,
  "fee": { "maker_bps": 2, "taker_bps": 10, "source": "config" },
  "pairs": [
    {
      "pair": "BTC/USDT",
      "base": "BTC",
      "quote": "USDT",
      "fills": 812,
      "totals": { "buy_qty": 6.02, "sell_qty": 6.01, "total_qty": 12.03, "net_qty": 0.01, "buy_price": 80720.5, "buy_price_fee": 80785.0, "buy_fee": 388.3, "sell_price": 80772.0, "sell_price_fee": 80708.0, "sell_fee": 388.0 },
      "points": [
        {
          "t": 1793114100000,
          "buy_qty": 0.4, "sell_qty": 0.25,
          "buy_price": 80030.0, "buy_price_fee": 80094.03, "sell_price": 80100.0, "sell_price_fee": 80063.17,
          "cum_buy_qty": 0.4, "cum_sell_qty": 0.25, "cum_total_qty": 0.65, "cum_net_qty": 0.15
        }
      ]
    }
  ],
  "known_pairs": [
    { "pair": "BTC/USDT", "base": "BTC", "quote": "USDT", "in_window": true, "fills": 812, "last_trade_ms": 1793114160000 },
    { "pair": "SOL/BTC", "base": "SOL", "quote": "BTC", "in_window": false, "fills": 0, "last_trade_ms": 1793000000000 }
  ],
  "has_data": true,
  "generatedAt": "2026-10-28T14:00:00.000Z"
}
```

| Поле | Смысл |
| --- | --- |
| `pairs[]` | пары с исполнениями в окне (исполнено больше нуля по цене больше нуля), по убыванию числа заявок, затем по имени; пары без исполнений нет |
| `pairs[].pair`, `base`, `quote` | пара `БАЗА/ВТОРАЯ`; база — валюта, объём которой считается, вторая валюта — единицы цены (USDT для BTC/USDT, BTC для ETH/BTC) |
| `pairs[].fills` | число исполненных заявок пары в окне |
| `pairs[].totals` | итоги пары за окно: купленное, проданное, общий и нетто объём (базовая валюта), средневзвешенные цены покупки и продажи (`null`, если стороны не было), цена покупки с комиссией `buy_price_fee` и расчётная комиссия покупок `buy_fee` (вторая валюта), цена продажи за вычетом комиссии `sell_price_fee` и расчётная комиссия продаж `sell_fee` |
| `fee` | расчётные ставки комиссии, по которым посчитаны `buy_price_fee`, `buy_fee`, `sell_price_fee` и `sell_fee`: `maker_bps` (лимитные заявки) и `taker_bps` (рыночные), б.п.; `source`: `config` — обе ставки с экрана «Клиринг», `mixed` — одна с экрана, другая по умолчанию, `default` — обе по умолчанию; ставки текущие (история пересчитывается при их смене). Реальная комиссия бирж в сделках не записана; если ставок нет, `buy_price_fee`, `buy_fee`, `sell_price_fee` и `sell_fee` равны `null`. Комиссия используется только для линий графика |
| `points[].t` | начало интервала, мс с эпохи; по возрастанию; интервалы без исполнений в ответ не входят |
| `points[].buy_qty`, `sell_qty` | купленный и проданный за интервал объём базовой валюты |
| `points[].buy_price_fee` | цена покупки с комиссией: `buy_price` плюс расчётная комиссия на единицу базовой валюты ([CALC-CE-PAIR-TRADES](../../04-domain/calculations/CALC-CE-PAIR-TRADES.md) §2.1); `null`, если в интервале нет покупок |
| `points[].sell_price_fee` | цена продажи за вычетом комиссии: `sell_price` минус расчётная комиссия на единицу базовой валюты (CALC-CE-PAIR-TRADES §2.1); `null`, если в интервале нет продаж |
| `points[].buy_price`, `sell_price` | средневзвешенные по объёму цены исполнения за интервал во второй валюте пары, все внешние биржи вместе; `null` — в интервале нет сделок этой стороны (не ноль) |
| `points[].cum_buy_qty`, `cum_sell_qty` | накопленные от начала окна покупки и продажи |
| `points[].cum_total_qty`, `cum_net_qty` | накопленный общий объём (покупки + продажи) и нетто (покупки − продажи) |
| `bucket_ms`, `since_ms`, `first_ms` | размер интервала, начало окна, момент первой точки (`null` без данных) |
| `known_pairs[]` | все пары, по которым были исполненные хедж-заявки за последние 7 суток, независимо от окна: сначала пары окна в порядке `pairs[]`, затем остальные по давности последней сделки (новее выше, без даты в конце). Нужен, чтобы чекбокс пары без сделок в окне не пропадал из списка (CR-F18-009). Аддитивное поле; прежние потребители его не читают |
| `known_pairs[].in_window`, `fills` | есть ли у пары исполнения в окне и сколько (у пар вне окна `false` и 0) |
| `known_pairs[].last_trade_ms` | момент создания последней исполненной заявки пары за 7 суток, мс с эпохи; `null`, если неизвестен. Список считается отдельным запросом по индексу `idx_child_orders_created` (около 190 тыс. подходящих строк, на dev 0,26 с на тёплом кэше PostgreSQL), кэш 10 минут, один запрос на всех ожидающих. Ожидание ограничено 3 с: при задержке или сбое отдаётся прежний список (в крайнем случае только пары окна), а запрос дорабатывает в фоне и обновляет кэш; график от него не зависит. Для пары окна значение — более поздняя из двух величин: кэш и начало последнего интервала окна (оценка снизу, точность до интервала) |
| `has_data` | есть ли хотя бы одна пара с исполнениями в окне; иначе экран пишет, что сделок за окно нет, но список `known_pairs` всё равно показывает пары и дату их последней сделки |

Ответ кэшируется в BFF на 30 с на значение окна (не больше 8 последних окон); запрос за 7 суток читает около миллиона строк и занимает несколько секунд, поэтому параллельные вызовы делят один запрос (список известных пар кэшируется отдельно, см. `known_pairs`).

## Ошибки

| Код | Причина |
| --- | --- |
| 502 | ошибка PostgreSQL или потеря пула во время запроса (`{"error":"pg_error","message":…}`), в том числе таймаут запроса 25 с (`pair_trades_timeout`) |
| 503 | PostgreSQL недоступен (`{"error":"postgres_unavailable"}`) |

## Экран

На вкладке «PnL» под графиком «Заработок во времени» — блок «Сделки на внешних биржах по парам»: чекбоксы всех известных пар (по умолчанию отмечены все пары со сделками в окне; пара без сделок в окне неактивна, подписана «нет сделок за окно, последняя <дата>»; кнопки «все» и «снять»), окна 1 ч, 6 ч, 24 ч, 7 дн, переключатель объёма (общий, нетто, покупки и продажи отдельно) и галочки цен покупки и продажи. Для каждой отмеченной пары свой график с двумя осями: слева накопленный объём базовой валюты, справа цены (пунктир). Подсказка под курсором показывает объём и цены точки. Линия объёма ступенчатая, от нуля в начале окна до его конца; ось времени охватывает окно запроса (`since_ms` … `generatedAt`). Линия цены соединяет точки, где цена есть, и рвётся при простое длиннее четырёх интервалов; одиночная точка цены рисуется точкой. Чекбокс «+ комиссия к цене покупки» подставляет в линию покупки готовое поле `buy_price_fee`, чекбокс «− комиссия с цены продажи» — в линию продажи готовое поле `sell_price_fee`; чекбоксы независимы. Браузер выбирает готовые поля точки и ничего не считает.
