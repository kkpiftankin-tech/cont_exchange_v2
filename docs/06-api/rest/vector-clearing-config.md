# REST API: настройки клиринга, ширина полосы хеджа (ADR-081)

Маршрут BFF `frontend/api` (порт 8090): `GET` читает, `POST` записывает строку `f05a_clearing_config` (id = 1); сервисы `ledger`, `matching`, `market_data`, `venues` перечитывают её сами (живая настройка, до 3 с). Здесь описаны только поля ширины полосы хеджа; остальные поля (окно батча, комиссия, skew, способ наклона, `ce_band_fee_k`, `ce_maker_fee_bps`) — как раньше.

Авторизации на маршруте пока нет (как у остальных настроек клиринга; появится с F-16 и F-01). Из-за этого на dev, где веб-интерфейс опубликован в интернет через Tailscale Funnel, маршрут доступен извне (см. ADR-081, «Последствия»).

Защита от подделки запроса из браузера: `POST` принимается только с `Content-Type: application/json`, а при наличии `Origin` его хост должен совпадать с хостом запроса или входить в переменную `OPERATOR_ALLOWED_ORIGINS` (имена хостов через запятую). Иначе `415 unsupported_media_type` или `403 bad_origin`. Запрос без `Origin` (curl) проходит — это не авторизация.

**Режим модели порогов (ADR-088).** Смена `ce_hmodel_mode` пишется отдельным действием `ce_hmodel_mode_change` (прежнее → новое, актор, `confirmed_after_fuse`) в той же транзакции; прежнее значение читается под блокировкой строки, поэтому одновременное срабатывание предохранителя ledger не даёт записи без аудита. Автопредохранитель ledger сам переводит `on → shadow` (действие `ce_hmodel_fuse_trip`, актор `ledger:auto-fuse`) — значение в `GET` может измениться без оператора. Актор из `X-User-Id` с зарезервированным префиксом (`ledger:`, `system:`, `bff:`, `auto:`, `matching:`, `market_data:`, `venues:`, `risk:`) записывается как `unverified:<значение>`: запись оператора нельзя выдать за действие автоматики. Частичный `POST` с одним `ce_hmodel_mode` перезапишет комиссии, skew и способ наклона значениями по умолчанию: отправляйте полный объект из `GET`.

Аудит: каждое изменение полей полосы записывается в таблицу `operator_audit_log` (время, `X-User-Id` или `unknown`, адрес клиента, `User-Agent`, режим до и после, изменившиеся поля с прежним и новым значением) в одной транзакции с изменением настроек и дублируется в лог BFF. Если запись аудита не удалась, изменение не применяется. Изменение основных полей (комиссии хеджа `ce_maker_fee_bps`/`ce_taker_fee_bps` по ADR-089, `ce_band_fee_k`, `ce_inv_skew_*`, `slope_method`, `batch_window_ms`, `stale_level_ms`) пишется отдельной записью с действием `ce_clearing_config_change` (кто, прежнее и новое значение каждого изменившегося поля) — независимо от полос; молчаливый сброс поля умолчанием при частичном `POST` тоже виден как изменение. Прежние значения читаются под консультативной блокировкой, запись журнала, основная запись и поля полосы — одна транзакция, дубль в лог — после `COMMIT`.

## Поля

| Поле | Тип | Смысл | Допустимо |
| --- | --- | --- | --- |
| `ce_band_mode` | строка, только в ответе | режим: `manual` (вручную), `volatility` (авто по волатильности), `fee` (от комиссии) | вычисляется: `manual` важнее `volatility` |
| `ce_band_manual` | булево | включает ручную ширину | true / false |
| `ce_band_manual_q_lim` | число, тыс. USDT | Z̄lim: вход в хедж пассивной лимитной заявкой | 0,1 ≤ значение ≤ 1000 |
| `ce_band_manual_q_mkt` | число, тыс. USDT | Z̄mkt: переход к рыночной заявке | Z̄lim ≤ значение ≤ 1000 |
| `ce_band_gamma_mode` | булево | автоматический режим по волатильности (ADR-066) | true / false |
| `ce_band_q_floor` | число, тыс. USDT | пол ширины | 0 ≤ значение ≤ 1000 |
| `ce_band_sigma_ref` | число | опорная волатильность σ: при равной σ ширина равна плоской | 0 < значение ≤ 1 |
| `ce_band_vol_ratio_min`, `ce_band_vol_ratio_max` | число | границы множителя волатильности | 0 < min ≤ max ≤ 1000 |
| `ce_band_arb_scale` | число | множитель порога выхода арбитражёров (переводчиков не касается, в ручном режиме не используется) | 0,1 ≤ значение ≤ 20 |
| `ce_hmodel_mode` | строка или `null` | режим модели порогов хеджа (ADR-088, условие 1): `off` / `shadow` / `on`. В ответе `null` = «не задан» (ledger считает `shadow`); поля нет, если колонки нет в БД. В теле: не прислан, `null` или `''` — не меняется (сбросить в `NULL` через API нельзя); регистр и пробелы нормализуются; другое значение — `400 band_invalid`. Эффективный режим в ledger = меньший из потолка окружения `CE_HMODEL_MODE`, этого значения и предохранителя, поэтому запись `on` рабочий режим не включает при низком потолке; смена действует до ≈ 6 с | `off` / `shadow` / `on` |
| `ce_hmodel_confirm_after_fuse` | булево, только в теле | подтверждение включения `on` в течение `HMODEL_FUSE_COOLDOWN_MIN` (деф. 30) минут после срабатывания предохранителя ledger; без него `on` в это окно даёт `409 hmodel_fuse_cooldown` (`last_trip_at`). Фиксируется в аудите (`confirmed_after_fuse`) | true / false |
| `ce_maker_fee_bps` | число, bps | комиссия мейкера на внешней бирже БЕЗ спреда; стандарт 10 (ADR-089); ledger читает значение ≤ 0 как «не задано» | 0 ≤ значение ≤ 1000 |
| `ce_taker_fee_bps` | число, bps | комиссия тейкера на внешней бирже БЕЗ спреда; стандарт 10; для ledger значение ≤ 0 — «не задано» (запасное 10), для market_data −1 — комиссия стакана, 0 — линейные кривые (применяется только при `CE_COMMISSION_IN_POLKA=1`, который включать нельзя) | −1 ≤ значение ≤ 1000 |

Поля полосы, которых нет в теле `POST`, не меняются (остальные поля маршрута перезаписываются значениями из тела или значениями по умолчанию, как раньше). Невалидное значение даёт `400` с телом `{"error":"band_invalid","message":"…"}`; ни основные настройки, ни поля полосы при этом не записываются. Основные настройки, поля полосы и аудит применяются одной транзакцией. Если колонок полосы или таблицы аудита в базе ещё нет (старый том без миграции), `GET` колонки просто не возвращает, а `POST` с полями полосы отвечает `502 pg_error` с общим сообщением (подробности только в логе BFF) и ничего не применяет.

**Важно:** основные поля (`batch_window_ms`, `stale_level_ms`, обе комиссии, `ce_inv_skew_*`, `slope_method`, `ce_band_fee_k`) в `POST` перезаписываются значениями из тела либо умолчаниями — менять одну комиссию нужно, отправляя полный объект из `GET` с исправленным полем.

Формулы и правило выбора режима — [ADR-081](../../03-architecture/adr/ADR-081-ce-band-width-manual-and-volatility-modes.md); хранение — [f05a-clearing-config-band](../../07-data/f05a-clearing-config-band.md).
