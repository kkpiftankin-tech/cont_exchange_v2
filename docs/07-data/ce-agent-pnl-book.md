# Data: ce_agent_pnl_book (книга агента CE по справедливой цене)

## Назначение

Хранит состояние книги агента: остаток позиции в штуках базового актива, среднюю справедливую стоимость его входа и два накопленных реализованных результата — внутренней биржи и внешних бирж. Из книги и текущей справедливой цены ledger считает R, U и R+U внутренней, внешних бирж и итого ([CALC-CE-AGENT-PNL](../04-domain/calculations/CALC-CE-AGENT-PNL.md)). Таблица нужна, чтобы книга переживала перезапуск ledger: без неё накопленные R обнулялись бы при каждой выкладке.

## Owner

- **Writer: ledger.** `PostgresAgentPositionRepository::SaveBooks` пишет **абсолютное состояние** изменённых книг одним пакетным запросом `INSERT … ON CONFLICT (agent_id) DO UPDATE` в конце `ApplyPositionDelta` (на такт) и после хедж-исполнения, под тем же `mu_`, что и расчёт. Идемпотентность не нужна: состояние абсолютное, повтор безвреден, сбой лечится следующим тактом. `WHERE … IS DISTINCT FROM EXCLUDED` не пишет неизменённые книги.
- **Reader: ledger** (`LoadBooks` при старте, `LoadAgentPositionsFromRepo`). BFF и фронт из таблицы не читают: числа приходят через `GetAgentPnl` (ADR-087 п. 8).
- Сброс: `ResetAgentPositions` удаляет строки книг сбрасываемых агентов (`ResetPnl`).
- История не хранится; ряд во времени остаётся в `ce_agent_pnl_history` (BFF).

## PostgreSQL (OLTP)

```sql
CREATE TABLE IF NOT EXISTS ce_agent_pnl_book (
    agent_id      TEXT PRIMARY KEY,
    agent_kind    TEXT NOT NULL CHECK (agent_kind IN ('translator', 'arbitrageur')),
    qty           NUMERIC(38, 18) NOT NULL DEFAULT 0,
    avg_fair      NUMERIC(38, 18) NOT NULL DEFAULT 0 CHECK (avg_fair >= 0),
    edge          NUMERIC(38, 18) NOT NULL DEFAULT 0,
    ext_realized  NUMERIC(38, 18) NOT NULL DEFAULT 0,
    quote         TEXT NOT NULL DEFAULT '',
    last_batch_id TEXT,
    since_ms      BIGINT NOT NULL CHECK (since_ms > 0),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT ce_agent_pnl_book_flat_chk CHECK (qty <> 0 OR avg_fair = 0)
) WITH (fillfactor = 70);
```

| Поле | Смысл | Единицы |
| --- | --- | --- |
| `agent_id` | агент (имя ребра графа: `T_BTC_binance`, `A_BTC_binancekraken`); у связки обе ноги в одной книге | — |
| `agent_kind` | `translator` или `arbitrageur` | — |
| `qty` | остаток $L$: штуки базового актива, плюс — длинная позиция | штуки |
| `avg_fair` | средняя справедливая стоимость входа $F_{in}$ открытого остатка; 0 при $L=0$ | валюта котировки за штуку |
| `edge` | накопленный $R_{int}$ = $\sum (F_0-p)\,dL$ по внутренним сделкам | валюта котировки |
| `ext_realized` | накопленный $R_{ext}$: дрейф справедливой цены при закрытии позиции плюс качество исполнения хеджей | валюта котировки |
| `quote` | валюта котировки значений книги (`USDT`, `BTC`); пусто — не известна; нужна, чтобы $R$ был известен сразу после перезапуска, без ожидания цены | — |
| `last_batch_id` | последний учтённый такт клиринга: повторная доставка того же такта книгу не удваивает | — |
| `since_ms` | начало накопления (создание строки), unix мс | мс |

Инварианты строки: при $L=0$ справедливая стоимость входа 0 (`CHECK`); вид агента непустой. Нарушение `CHECK` одной строки валит весь пакет, поэтому ledger нормализует строки перед записью и не пишет книги с неизвестным видом.

Индексов, кроме первичного ключа, не нужно: `LoadBooks` читает не более нескольких десятков строк при старте, `GetAgentPnl` берёт данные из памяти. `fillfactor = 70` — строки обновляются на каждом такте, место нужно для обновлений на месте (HOT).

## Нагрузка и транзакции

Запись книг — один многострочный `INSERT … ON CONFLICT` на такт (25–60 агентов, такт ≈ 1 с), а не по запросу на агента: построчная запись добавила бы к существующему коммиту на каждую ногу в `ApplyDelta` ещё столько же. Позиция и книга пишутся в разных транзакциях; сбой между ними оставляет книгу на такт позади, что само исправляется следующей дельтой агента (погрешность ограничена одним тактом).

## Миграция

Идемпотентный блок (создание таблицы и `DO`-блок) лежит в `infra/postgres/init.sql` и выполняется `ledger` сам один раз на процесс (`EnsurePnlSchema`, одна транзакция с `lock_timeout` 5 с); на живой БД рекомендуется применить его вручную **до** выкладки ledger:

```bash
ssh nik@ubuntu-dev "docker exec -i infra-postgres-1 psql -U cex -d cex" < infra/postgres/init.sql
```

**Переход с модели A (учёт по средней себестоимости, колонки `avg_price`, `realized`) на модель C′.** Шаги `DO`-блока независимы и каждый идемпотентен (проверка по `pg_attribute`, не по `information_schema`): (1) если есть колонка `avg_price` — берётся `ACCESS EXCLUSIVE`, страж перепроверяется (параллельный прогон `psql` и ledger не выполнит переход дважды), затем `RENAME avg_price TO avg_fair` и `DELETE FROM ce_agent_pnl_book`; (2) если есть `realized` и нет `edge` — `RENAME realized TO edge`; (3) если есть ограничение `ce_agent_pnl_book_avg_price_check` — оно переименовывается в `..._avg_fair_check` (`CHECK` переименование колонки переживает, `flat_chk` остаётся); (4) колонки `ext_realized` и `quote` добавляются, только если их нет (`ADD COLUMN IF NOT EXISTS` берёт блокировку даже при наличии колонки, на каждом старте её не делаем). Значения модели A в C′ не пересчитываются (другое определение R и U), поэтому строки удаляются, а книги заводятся заново первой дельтой клиринга по текущей позиции агента; накопление R и U начинается с момента выкладки. На свежем томе таблица создаётся сразу в новом виде. Таблица производная (источник — поток дельт клиринга и хедж-отчёты), внешних ключей, представлений и триггеров на неё нет; писатель и читатель один — ledger, и до загрузки книг (`pnl_ready_=false`) он в таблицу не пишет. Колонки `ext_*`, `rvf_base` таблицы `ce_agent_position` остаются на живых томах (`NOT NULL DEFAULT 0`) без изменений и не используются; `DROP COLUMN` — отдельным решением после того, как откат на модель A станет не нужен.

Ручной прогон `init.sql` не обязателен: ledger мигрирует сам при старте. Если применяется вручную, то при остановленном ledger (иначе старый процесс модели A получает `column "avg_price" does not exist` на каждом такте).

Проверено 2026-10-28 в транзакции с откатом во временных схемах на dev: том модели A (строки удалены, колонки и ограничения переименованы, `flat_chk` цела), повторный прогон (строка новой модели сохранена), свежий том.

Откат: `CE_AGENT_PNL_ENABLED=0` останавливает накопление; таблицу можно оставить. Откат на бинарник модели A: `DROP TABLE ce_agent_pnl_book` (таблица производная; старый бинарник пересоздаст её в прежнем виде, обратное переименование не нужно).

Если миграция не удалась (например, истёк `lock_timeout`), учёт заработка приостанавливается: `LoadBooks` возвращает признак неуспеха, ledger не считает, что книг нет, не пересевает их по текущей позиции и не пишет в таблицу (иначе перезаписал бы сохранённые книги); `GetAgentPnl` отдаёт «нет данных». Позиции агентов работают по-прежнему. Повторная попытка схемы — не чаще раза в 30 с, повторная загрузка книг — по таймеру `CE_AGENT_PNL_RETRY_MS` (деф. 30 с). Окно простоя в учёт не попадает.

## Retention и сброс

Только текущее состояние, одна строка на агента. Строки удаляет сброс позиций; иных чисток нет.
