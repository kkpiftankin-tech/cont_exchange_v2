## Реплика

Владелец, 2026-10-28: «Во вкладке PnL нужно отображать реализованный и нереализованный PnL для внутренней и внешних бирж для каждого агента. Итого колонки R, U, R+U — для внутренней биржи; R, U, R+U — для внешних бирж; R, U, R+U — для суммарно [внутренней и внешних] бирж. Вычисления должны производиться в соответствующих сервисах, а не внутри фронта». Уточнение на вопрос о смысле внутренней группы: «R — то, что агент заработал на внутренней бирже, продавая и покупая активы; U — то, что потенциально заработал, но ещё не продал другим агентам».

## Runtime (для реплик по экрану)

Вкладка «PnL» (`/hedge-pnl-live`) до изменения показывала только хедж-PnL по символам и биржам (ClickHouse `execution_reports`), без разреза по агентам. R и U внешней стороны агента были только в панели «Живые позиции» (U считал BFF по `child_orders`); внутренней стороны в системе не было вовсе.

## Решения

- Смысл внутренней группы — по определению владельца; правила учёта (средняя себестоимость, выход при хедже по F_0 момента исполнения, единая цена оценки, внешний U только на несопоставленном объёме) — решения реализации по ревью формул, вынесены на подтверждение в OQ-F18v2-26…29.
- Панель «Живые позиции» и ряд для графика не менялись; внешний U во вкладке намеренно отличается от U панели (ADR-087 п. 6, п. 10).
- После перезапуска ledger R панели «Живые позиции» вырос (например, T_BTC_binance 72 → 8 411): ledger загрузил из PG накопленное `realized_vs_fair` с остатком, который сброс 2026-10-28 06:40 UTC не обнулил. Внешний R новой вкладки считается от отметки миграции и этим не затронут. Нормализует сброс позиций — решение владельца.
