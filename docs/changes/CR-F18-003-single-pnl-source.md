## Реплика

Владелец, 2026-10-28: «Данные по позициям должны рассчитываться и храниться в одном месте для панели и вкладки».

## Runtime (для реплик по экрану)

После выкладки CR-F18-002 у одного агента на двух экранах стояли разные R и U: вкладка «PnL» читала ledger (`GetAgentPnl`), панель «Живые позиции» считала R/U в BFF по `child_orders` и `realized_vs_fair`, а итоги «переводчики / арбитражёры / вместе» складывал браузер. Следствие, замеченное на dev: после перезапуска ledger R панели вырос с 72 до 8 411 (T_BTC_binance), потому что панель показывала накопленное значение из PG с невыровненным остатком, а вкладка считала от отметки внедрения учёта.

## Решения

- Ряд `ce_agent_pnl_history` до выкладки записан по прежней формуле; не пересчитывается, на графике виден разрыв.
- Вне объёма (не R/U): выгода $S$, базис и открытая позиция арбитражёров, разложение на ноги, количества сделок — остаются в BFF; запись в `known-gaps.md`.
