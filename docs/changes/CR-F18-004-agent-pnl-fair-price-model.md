## Реплика

Владелец, 2026-10-28 (по цепочке): «кажется, на внутренней бирже суммарный R по всем агентам должен быть равен нулю»; «почему на внутренней бирже возникает U — кажется, на внутренней бирже всегда всё реализуется»; «дайте ваши собственные определения R, U, R+U для внутренней биржи и для внешней биржи, чтобы мы с вами одинаково понимали друг друга»; после определений: «ваши определения корректны, делайте реализацию в соответствии с вашими определениями».

## Runtime (для реплик по экрану)

После CR-F18-002/003 вкладка «PnL» и панель «Живые позиции» показывали внутренний U (накопленный оборот сделок против цены оценки) и внутренний R с выходом по цене исполнения хеджа. На dev (2026-10-28): сумма внутреннего R по агентам +82,6 при обороте 4 252 (≈2 %), внутренний U ≠ 0 у агентов с неисполненным хеджем, после перезапуска ledger все группы «нет данных», пока агент не получит дельту с ценой.

## Определения (утверждены владельцем)

Внутренняя биржа: всё реализуется в такте клиринга; $R_{int}=\sum (F_0-p)\,dL$, $U_{int}=0$, сумма $R_{int}$ по агентам равна нулю. Внешние биржи: позиция хранится по справедливой стоимости входа $F_{in}$; $R_{ext}$ — качество исполнения хеджа плюс дрейф справедливой цены закрытой части; $U_{ext}=L\,(F_0^{\text{сейчас}}-F_{in})$. Итого: $R=R_{int}+R_{ext}$, $U=U_{ext}$. Подтверждено: внешний R считается от $F_0$ на момент возникновения позиции; $U_{int}\equiv 0$. Пример: покупка 1 BTC по 80 010 при $F_0=80\,000$ и хедж `SELL` 0,6 по 80 040 при $F_0=80\,030$ дают $R=14$, $U=12$, $R+U=26$.

Уточнение реализации (к определению): дрейф закрытой части реализуется при любом закрытии позиции, в том числе встречной внутренней сделкой, иначе он терялся бы и $R+U$ не совпадал бы с кассой.

## Решения и риски

- Накопление R и U начинается заново с момента выкладки (значения модели A удалены миграцией, пересчёту не подлежат); ряд `ce_agent_pnl_history` до выкладки записан по прежним формулам — на графике виден разрыв.
- Порядок выкладки: миграция БД (выполняется ledger сам), ledger, frontend-api (с пересборкой образа: копия proto), frontend-web.
- Справедливая цена связки берётся у переводчиков того же актива (OQ-F18v2-29 остаётся открытым для подтверждения).
- Откат на бинарник модели A: `DROP TABLE ce_agent_pnl_book` (производная; старый ledger пересоздаст её в прежнем виде), `CE_AGENT_PNL_ENABLED=0` останавливает накопление без отката. Откат одного ledger без BFF безопасен: U пропадёт, неверных чисел нет.
- Хедж ноги связки в книгу не пишется (OQ-F18v2-31); открыты также OQ-F18v2-32 (R кросс-пар в USDT на момент сделки) и OQ-F18v2-33 (политика устаревания справедливой цены).
