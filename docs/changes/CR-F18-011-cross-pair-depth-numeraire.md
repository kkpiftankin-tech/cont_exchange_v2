## Реплика

Владелец, 2026-10-29: «Важно понять почему сейчас позиция не пробивает полосу и нет сделок по этим парам: ETH/BTC, SOL/BTC, а по другим парам есть» → после расследования и вопроса «Получается это просто ошибка?» — «Вариант А».

## Runtime (для реплик по экрану)

Вкладка «PnL», блок «Сделки на внешних биржах по парам»: ETH/BTC неактивна за 24 ч (последняя сделка 28.10 05:01 по часам экрана), SOL/BTC — 26.10 09:39. На dev 2026-10-29: `ce-clearing` показывает глубину кросс-рёбер 0,0001…0,034 против 171…6553 у USDT-рёбер; суммарный $|f|$ за такт у кросс-переводчиков 0,0034, у USDT-переводчиков 4,11, у арбитражёров 3,59 (тыс. USDT); позиции кросс-агентов колеблются на ±0,05 тыс. USDT за 30 с и до полосы 3,6 не доходят; с 2026-10-28 12:56 UTC пробоев полосы по кросс-агентам нет, у USDT-агентов по 2–4 тысячи.

## Решение (владелец: вариант A)

- Причина: глубина α кросс-пары строится в единицах котируемой валюты (BTC), а клиринг считает поток в номинале (USDT) без ценовых весов; пересчёта не было (ADR-064: «как есть, в промилле» верно для полки, не для глубины).
- Поправка: $\alpha_{value}=\alpha\cdot P_{0,q}$ при сборке агента в `market_data` (константа окна, не цена узла: иначе функционал клиринга неквадратичен); для пар с котировкой в номинале множитель 1.
- Флаг `CE_CROSS_DEPTH_NUMERAIRE`, по умолчанию 0: поведение побитно прежнее; включение на стенде — после замера (откат: флаг 0 и пересоздание `market_data`).
- Проверка размерности независимо: `trading-domain-specialist` (вердикт «в разных единицах», код: `agent_builder.hpp`, `market_data_uc.cpp`, `ce_graph_assembler.hpp`, `ce_position_projection.hpp`).
- Вторая причина неправдоподобных соотношений глубин после приведения — отдельный вопрос OQ-F18v2-38; не входит в это изменение.
- ADR: дополнение к ADR-064 (правка алгоритма клиринга, CLAUDE.md §1.6).

## Результат пробы и вывод

Пробное включение на dev 2026-10-29 08:13:26–08:15:59 UTC (2,5 минуты) дало поток кросс-рёбер в сотни тысяч раз больше прежнего и позиции агентов до −10,5 млн USDT; флаг возвращён в 0, поведение вернулось к прежнему. Вариант A «как есть» небезопасен: без барьера или предела для кросс-рёбер включать его нельзя.

Причина (механизм): замкнутый треугольник ETH → BTC → USDT → ETH внутри биржи с проводимостью порядка сотен тыс. USDT на ‰ и несогласованностью цен 1–3 б.п. при нулевой полке; подробности — ADR-064, дополнение, и OQ-F18v2-38. Нужно решение владельца по барьеру или пределу для кросс-рёбер; после него — повторная проба на реплее входа клиринга (офлайн), а не на живом стенде.
