## Реплика

Владелец, 2026-10-29, с вложением `porogi-hedzha5.html`: «Проанализировать прикреплённый файл… Реализовать расчёт порога позиций в соответствии с прикреплённым файлом. В ходе реализации по результатам экспериментов и тестов не забывать формировать данные для эксперта по трейдингу».

## Решение

- Модель порогов — чистый доменный модуль ledger, порт расчётного ядра страницы; эталонные значения сняты с ядра страницы (`tools/hedge-threshold-model/`).
- Режим `CE_HMODEL_MODE`: `off` (по умолчанию) / `shadow` (считает и сохраняет, на заявки не влияет) / `on`. На dev после выкладки — `shadow`; включение рабочего режима — решение владельца по выжимке эксперта (ADR-088).
- Данные для эксперта: `docs/experiments/EXP-2026-10-29-hedge-threshold-model.md` и вопросы `OQ-F18v2-39…44`.

## Проверка (правая ветвь)

- **Порт против страницы.** `hedge_threshold_model_test`: 170 проверок, из них 29 эталонных случаев `golden.json` (значения сняты с ядра страницы) с точностью $10^{-6}$; под ASan/UBSan локально и на dev.
- **Подключение в ledger.** `ce_hedge_model_wiring_test`, 37 проверок (T1–T12): `off` не заполняет поле и не меняет эмиссию; `shadow` считает 15,971 / 20,215 и не меняет заявки; `on` — рыночный барьер над $z_{mkt}$, мейкер-зона с ограничением заявок в пути; нет волатильности; оценка потока; сброс; связка; полуспред по книге; прижатая позиция без дрейфа (режим шума); устойчивый поток (режим дрейфа); удержание порогов при исчерпанном бюджете. Регрессия A7 (`ce_band_hedge_a7_test`) — OK.
- **BFF.** `hedge_model_dto`, `band_config`, `pair_trades_history` — тесты пройдены; декодирование нового поля копией proto в собранном образе проверено (ответ закодирован по контракту, прочитан копией BFF).
- **Ревью.** `code-reviewer`: найден блокирующий дефект B1 (оценка дрейфа свободным членом регрессии шумела на порядки при прижатой позиции) — исправлен, плюс удержание порогов при исчерпанном бюджете, защита от NaN/inf, усечение истории; повторное ревью дельты — блокирующих нет. При проверке теста найдены ещё две погрешности оценки (вес первой минуты, ложный дрейф от погрешности среднего) — исправлены (`CE_HMODEL_MU_Z`). `security-reviewer` (аудит операторских действий, CR-F18-012) — гонка и неполный аудит исправлены, остальное в `known-gaps.md`.
- **Не запускалось.** Рабочий режим `on` на общем стенде (запрещён до PG-переключателя с аудитом и автопредохранителя); интеграционный тест транзакции маршрута настроек с PG; отображение модельных порогов на экране «Клиринг».
- **Экран «Клиринг».** Блок «Пороги хеджа: действующие и по модели» (AC-F18v2-37): `HedgeModelThresholds.test.js` (8 проверок) и существующие тесты экрана — 81 тест в 8 наборах пройден; показ только читает `z_lim`, `z_mkt`, `hmodel` из ответа BFF.
- **Теневой режим на dev и данные эксперту.** См. [EXP-2026-10-29-hedge-threshold-model](../experiments/EXP-2026-10-29-hedge-threshold-model.md).
