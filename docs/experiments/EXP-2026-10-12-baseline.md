# EXP-2026-10-12-baseline

**О прогоне.** Базовый замер (до каких-либо исправлений): зафиксировать
состояние системы «как есть» перед серией правок. Read-only, окно 2026-10-12,
живой клиринг на dev, один повтор (для первой фиксации сравнение не нужно).

**Результат для бизнеса (P&L).** Прибыль/убыток системы по переоценке остатков
ещё не считается (следующий шаг плана). На экране realized P&L: у роли
«переводчик» — то в плюс, то в минус (ожидаемо); у роли «арбитражёр» —
стабильно ноль. Это, вероятнее всего, не значит, что арбитражёр реально не
зарабатывает — похоже, что часть его результата (справедливая оценка второй
ноги сделки) просто ещё не записывается.

**Риск и исполнение — два подтверждённых дефекта на живых данных:**

- **Хедж по устаревшей цене.** Решение о хедже принимается по рыночным
  котировкам, которые на момент сделки уже устарели на **230–352 секунды**
  (почти 4–6 минут) — у каждого проверенного агента: пример цифр — один
  агент 343 с, другой 324 с, третий 310 с. Для алгоритмической торговли это
  существенный риск исполнения по невыгодной, уже неактуальной цене.
- **Дублирование сделки между внутренними ролями.** Объём и направление
  покупок/продаж у «переводчика» и «арбитражёра» на одной и той же площадке
  в один и тот же час практически совпадают (пример: на одной бирже в 14:00
  обе роли продали ≈1.7 единицы в одну сторону; на другой — купили ≈1.3–1.4).
  То есть две внутренние роли по факту дублируют одну и ту же рыночную
  экспозицию, а не действуют как независимые или взаимно компенсирующие
  друг друга позиции.

**Проверки целостности.**
- Скрытая, никем не захеджированная позиция по (актив, биржа): **все без
  исключения** проверенные пары актив/биржа (16 из 16) нарушают — то есть
  проверка сейчас не проходит нигде. Худший случай: на одной бирже по BTC
  пять внутренних агентов наторговали суммарно 119.5 (валовый оборот), но
  друг друга они перекрывают настолько плохо, что чистая нескомпенсированная
  позиция составляет 103.3 — то есть почти весь объём остался
  незахеджированным внутри системы. Похожая картина по SOL на двух других
  биржах: −42.3 и −38.4.
- Сверка жизненного цикла хедж-заявок и сумма P&L участников = P&L системы —
  ещё не инструментированы.

**Вывод.** Оба дефекта (устаревшая цена при хедже, дублирование между
ролями) подтверждены на живых данных. Эта точка зафиксирована как база для
сравнения. Дальше по плану: учёт P&L, тест на скрытую позицию как
регрессионный, затем устранение обоих дефектов. Решение инженерной команды:
не калибровать экономику модели, пока эти два дефекта не закрыты — иначе
калибровка будет подгоняться под заведомо искажённые данные.

**Вопросы для эксперта по трейдингу.** Нет (прогон фиксирует дефекты
исполнения/учёта, инженерный план уже определён; концептуальных вопросов не
возникло).
