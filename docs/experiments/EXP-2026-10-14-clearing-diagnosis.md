# EXP-2026-10-14-clearing-diagnosis

**О прогоне.** Диагностика, почему арбитражный круг между биржами выглядит
замкнутым в теории, но реальные сделки и состояние системы искажены. Read-only
замер + два коротких контролируемых вмешательства (см. ниже). Окно 2026-10-14
≈19:20–19:35 UTC, живой клиринг на dev.

## 1. Ложные сигналы из-за рассинхронизации данных между биржами

Для пары ETH/USDT, 948 сравнений между площадками: котировки, которые видит
система, на момент решения уже устарели — медианная задержка 12–16 секунд,
максимум 32 с (Binance/OKX/Kraken), **96 секунд у Coinbase**.

Из-за этой рассинхронизации (одна биржа даёт котировку свежее, другая —
старше) система видит **фантомную** разницу цен между биржами там, где её
на самом деле почти нет: истинная волатильность разницы цен между биржами
σ=0,110 ‰, то, что видит система, — σ=0,210 ‰, а сама фантомная добавка —
σ=0,223 ‰ (то есть **примерно вдвое больше настоящей разницы цен**). Доля
моментов, когда разница цен выглядит достаточно большой, чтобы быть выгодной
сделкой (>0,3 ‰): на самом деле **2,2 %** времени, система считает так
**13,4 %** времени — то есть ложно срабатывает примерно в 6 раз чаще, чем
есть реальная возможность (по отдельным парам бирж ещё хуже: Coinbase–Kraken
3,2 %→24,7 %, Coinbase–OKX 5,1 %→23,4 %).

## 2. Проверка целостности одного клирингового решения

На одном конкретном клиринговом решении (сделанном под отладкой) проверено:
расхождение входящего и исходящего потока по каждой точке — **ровно ноль**
(учёт сходится без потерь). Размер сделки реагирует на разницу цен
пропорционально, с настраиваемым коэффициентом чувствительности. Активно 81 %
торговых связей роли «переводчик» и 39 % связей внутреннего перевода. Потоки
образуют замкнутые циклы (пример: ≈40 USDT прошли по кругу через цепочку из
трёх внутренних агентов). Передача результата клиринга в учёт балансов —
без потерь (расхождение 0,03–0,01 %).

**Вывод по этому пункту: сам механизм клиринга в рамках одного решения
работает математически корректно** — проблема не в нём, а в данных, которые
в него поступают (см. пункт 1), и в том, что происходит при исполнении
(см. пункт 3).

## 3. Внутренние роли дублируют друг друга на открытом рынке

За 60 минут: сделки хеджирования на открытом рынке у роли «арбитражёр» и
роли «переводчик» по валовому и чистому объёму — BTC 7,7/−0,08 тыс. USDT
против 8,1/−0,09 тыс.; ETH 295/−29,6 против 310/−17,5; SOL 5495/+101,7 против
7285/+65,7. Знак и масштаб совпадают — то есть обе роли по факту выходят на
рынок с похожей сделкой, хотя по замыслу арбитражёр должен был переводить
актив между биржами напрямую, без сделки на открытом рынке.

## Проверки целостности

Скрытая, никем не захеджированная позиция по (актив, биржа): **не в
порядке** — нарушено на 15 из 16 пар актив/биржа, максимум 61,1 тыс. USDT
(ETH на Kraken −60,3 тыс., BTC на Coinbase −57,1 тыс.).

## Что было опробовано как исправление

**Попытка 1 — запас на возраст котировок при расчёте порога сделки.**
Четырёхминутные окна до/после: до правки — активных арбитражных связей 2,8
из 24 (второй контрольный замер: 2,7 из 24), доля циклов вообще без потока
34 % (55 % во втором замере), средний поток 1360 USDT (3414 USDT). После
правки: **0,5 из 24 связей, 87 % циклов без потока, средний поток 469
USDT.** Разброс между двумя замерами «до» (≈2,5×) и короткие окна означают,
что это не строгое статистическое доказательство, но направление понятно:
правка резко снижает число срабатываний.

**Попытка 2 — арбитражёр больше не выходит на открытый рынок, хеджируется
только внутренним переводом актива (с повышенной агрессивностью перевода).**
10 минут до / 11 минут после:

| Метрика | До | После |
|---|---|---|
| Рыночные хедж-сделки арбитражёров | 269 шт, 314,2 тыс. USDT | **0** |
| Рыночные хедж-сделки переводчиков | 256 шт, 415,1 тыс. USDT | 35 шт, 5,2 тыс. USDT |
| Циклов клиринга вовсе без потока | 87 % | 97 % |
| Активных арбитражных связей (из 24) | 0,5 | 0,1 |
| Пар актив/биржа со скрытой позицией (из 16) / максимум | 16 / 46,5 тыс. USDT | 15 / 46,5 тыс. USDT |
| Суммарный размер открытых позиций арбитражёров | 365,7 тыс. USDT | 322,1 тыс. USDT |

Важное совпадение: доля циклов без потока после правки (97 %) почти точно
равна доле времени, когда реальная (не фантомная) разница цен между биржами
ниже порога сделки (97,8 %). То есть после отключения рыночного хеджа
арбитражёра система реагирует примерно только на настоящие возможности, а
не на фантомные. Рыночные хедж-сделки переводчиков при этом тоже упали
почти в 80 раз — значит, большая часть их активности тоже была реакцией на
тот же фантомный сигнал, а не на реальный рынок. Скрытая позиция по-прежнему
не в порядке: старые, уже открытые позиции сами по себе не закрываются без
потока сделок — пока поток почти остановлен, они просто зависают, а не
гасятся.

## Можно ли подобрать удачное значение запаса на возраст котировок?

Отдельная калибровка (2026-10-15, 6,5 минуты, ETH/USDT и SOL/USDT на 4
биржах, 1110 сравнений на пару; истинная волатильность разницы цен между
биржами 0,098/0,089 ‰ за √с). «Реально выгодная возможность» = настоящая
разница цен между биржами больше 0,30 ‰ (порог сделки): так было 5,9 %
времени для ETH, 7,7 % для SOL.

| Запас (k) | ETH: сигналов системы / из них ложных / реальных возможностей пропущено | SOL: сигналов / ложных / пропущено |
|---|---|---|
| 0,0 (без запаса) | 9,8 % / 7,3 % / 3,3 % | 15,3 % / 9,8 % / 2,3 % |
| 0,5 | 0,7 % / 0,7 % / 5,9 % | 3,7 % / 2,7 % / 6,8 % |
| 1,0 | 0,1 % / 0,1 % / 5,9 % | 0,0 % / 0,0 % / 7,7 % |

Без запаса система ловит лишь около 42 % реальных возможностей (по ETH), и
при этом три из четырёх её сигналов — ложные. Уже при запасе 0,5 сигналы
почти все ложные, а реальные возможности пропускаются почти целиком. При
запасе 1,0 система «засыпает» — подавляет и шум, и настоящий сигнал
одновременно (это и видно ночью: активность хеджей переводчиков падает с
ожидаемых ~2000 тыс. USDT/ч до 40–100 сделок/ч).

**Вывод.** Подбором размера запаса отделить фантомный сигнал от настоящего
**нельзя**: сам фантомный сигнал по масштабу (0,3 ‰) почти не отличим от
настоящей разницы цен при текущей рассинхронизации данных (12–96 с). Запас
на возраст котировок — это защитный предохранитель, который гасит риск
ценой упущенных возможностей, а не устранение причины. Устранение причины —
сделать данные, на которых принимается решение, синхронными и свежими
(задержка 1–2 секунды вместо текущих 12–96).
