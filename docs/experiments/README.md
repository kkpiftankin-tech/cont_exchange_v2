## Правило языка (обязательное с 2026-10-27)

Основной текст каждой выжимки — **только термины алготрейдинга**: P&L,
позиция/риск, исполнение (сделки/проскальзывание/истёкшие заявки),
волатильность, спред, базис между площадками, издержки хеджа. Эксперт не
обязан знать внутреннее устройство CE, чтобы прочитать вывод.

Запрещены в основном тексте (разрешены только в блоке `[для инженера]` в
конце файла): имена ENV-флагов (`CE_...`, `VENUES_...`), номер ADR как
единственное объяснение изменения, внутренние обозначения модели (`W·c`,
`γ_A`, «узел», «причина N») и SQL/имена таблиц/колонок. Если по ходу нужно
сослаться на конкретную правку — опиши словами, что она меняет в поведении,
а флаг/ADR дай в скобках как техническую деталь.

Короткий словарь (для тех, кто пишет выжимки руками, не только `/experiment`):

| Внутреннее имя | Что это на языке трейдинга |
|---|---|
| `W·c=0` | Сумма внутренних позиций по (актив, биржа) должна быть нулевой — иначе биржа незаметно для себя копит нехеджированный риск |
| `c+in_flight=I−F` | Сверка жизненного цикла хедж-заявок: позиция + заявки в процессе = выставлено − исполнено (ничего не потеряно/не задвоено) |
| «причина 1» (возраст пересекающих принтов) | Задержка рыночных данных относительно момента хеджа — хедж мог быть выставлен по уже устаревшей цене |
| «причина 3» (нетто T vs A по площадке) | Проверка, торгуют ли внутренние роли (переводчик/арбитражёр) с рынком или друг против друга на одной бирже |
| `γ_A`, `σ`, `τ` и т.п. | Внутренние параметры калибровки — не нужны эксперту без расшифровки; расшифровку дай словами при первом употреблении |

**Записи до 2026-10-27** (`EXP-2026-10-12..10-26-*.md`) писались до этого
правила и местами используют внутренние имена как основной язык — не
переписываются задним числом (это исторический срез, не текущая
инструкция). Новые выжимки — только по правилу выше.

## Как формируется (команда `/experiment`)

Журнал формируется **командой** [`/experiment`](../../.claude/skills/experiment/SKILL.md)
(не вручную по памяти): она прогоняет генератор
[`Testing/ce_experiment_summary.sh`](../../Testing/ce_experiment_summary.sh) на
dev, кладёт `EXP-<id>.md` и **дописывает строку в `journal.md`**. Генератор
собирает **каркас** из живого dev (профиль, риск, W·c=0, исполнение, причины 1/3)
и готовую строку журнала; человек добавляет только **«Вывод»**.

```bash
/experiment <гипотеза> | <что менялось> | <окно 6h> | <id>
```

Ручной запуск генератора (без раскладки в репозиторий):

```bash
ssh nik@ubuntu-dev "cd /home/nik/cont_exchange_v2 && \
  RUN_ID=run1 WINDOW='6 hours' HYP='...' CHANGE='...' bash Testing/ce_experiment_summary.sh"
```

Поля MTM/σ и инварианты 4.2/4.3 помечаются `pending` до их инструментации.
Глубокий анализ (перцентили σ, модели) — по желанию в тот же `EXP-<id>.md`.

## Состав

- `journal.md` — реестр: одна строка на прогон (дата · ID · гипотеза ·
  изменение · результат · решение). Дописывается `/experiment`.
- `_template.md` — форма выжимки (поля, которые собирает генератор).
- `EXP-*.md` — выжимки прогонов (по одной на прогон).

## Правила

- Один прогон → одна выжимка (`/experiment`) → одна строка в `journal.md`.
- Числа — с 95% ДИ, где есть повторы. Без прозы «кажется/вероятно».
- Каждая выжимка самодостаточна: паспорт даёт воспроизводимость (run_id, SHA,
  окно, флаги, гипотеза, изменение).
- Каркас — генератором; ручные правки — «Вывод» и (по желанию) анализ.
