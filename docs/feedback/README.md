# docs/feedback — журнал замечаний с фронта

Рабочий цикл: посмотрели систему (веб-интерфейс или CLI) → записали замечания
в `inbox.md` → разобрали командой `/triage` (навык `.claude/skills/triage/`) →
исполнили минимально достаточным набором агентов
(`.claude/rules/agent-routing.md`) → результат ушёл в `FB-<дата>.md`.

- `inbox.md` — черновик, куда записываются свежие замечания перед разбором.
  После `/triage` соответствующие строки переносятся в `FB-<дата>.md`, а
  `inbox.md` остаётся пустым шаблоном для следующей проверки.
- `FB-<ГГГГ-ММ-ДД>.md` — журнал одной проверки: что нашли, какого класса,
  какие агенты подключались и почему, что изменили, какие карточки
  `docs/04-domain/calculations/CALC-*` обновили.

Это не замена `docs/10-testing/` (формальные тест-планы) и не замена
`docs/00-methodology/postmortems/` (post-mortem по инцидентам) — это именно
рабочий журнал повседневных замечаний по интерфейсу/поведению/числам,
привязанный к тому, что уже делал ассистент в текущей сессии, а не к
формальному релизному циклу.

См. также `docs/04-domain/calculations/README.md` — уровень L3 «вычисление»,
куда чаще всего ведут замечания про «число на экране не сходится».
