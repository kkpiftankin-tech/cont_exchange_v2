## Use Case разбиение

Исходный IN-005 описывает F-12 как одну фичу с несколькими сценариями (happy path, rejection + fallback, error scenarios). Решение: вместо одного use case разбито на **5 use cases**, по одному на каждый явный сценарий, для соответствия CLAUDE.md §26a (один UC = один scenario sequence):

| Decision | Rationale |
| --- | --- |
| `UC-F12-01-auto-hedge-after-batch` | Primary auto-flow (IN-005 §2 happy path) |
| `UC-F12-02-manual-operator-hedge` | Manual override (IN-005 §9 POST `/hedge/intents/manual`) |
| `UC-F12-03-partial-fill-retry` | Partial fill + retry (IN-005 §5 reconciliation, §10.1 U2) |
| `UC-F12-04-rejection-fallback` | Venue rejection + fallback (IN-005 §3, §10.1 U4) |
| `UC-F12-05-timeout-underfilled-reconciliation` | Timeout / overfill / risk-reject (IN-005 §4, §10.1 U3/U5) |

Старый stub `UC-F12-01-execute-hedge/` удалён в пользу более гранулярных UC. Соответственно service-level sequence `SEQ-F12-UC-F12-01-services.md` удалён и заменён на три новых, покрывающих happy/fallback/error пути.

## Conflict Notes (зарегистрированные в артефактах)

1. **No `cpp/venue_execution_adapter/` service.** Реализация распределена внутри `cpp/venues/src/`. См. `feature.yaml#knownIssues:no-venue-execution-adapter-service`, ADR-012.
2. **No `execution_planning` service.** Только абстрактный интерфейс `IExecutionPlanningUseCases`. См. ADR-013.
3. **No PostgreSQL DDL** для `hedgeflows`, `child_orders`. T-F12-201, T-F12-202.
4. **No ClickHouse DDL** для `execution_reports`. T-F12-203.
5. **No `RiskService.PreHedgeCheck` RPC** в `risk.proto`. T-F12-101.
6. **Legacy topic `execution.reports`** существует параллельно с каноническим `execution.venue` (per IN-005 §9). T-F12-103.
7. **`LedgerService.ApplyExecutionReport`** только логирует, не считает HedgePnL. T-F12-601.
8. **`venue_symbol` маппинг** реализован простой override-таблицей, не использует `VenueSnapshot.tick_size/lot_size/fee`.
