  - id: DELTA-1
    title: Явная роль Observability Reporting (read-side only, никогда не пишет в execution.intents)
    target:
      - docs/02-system/features/F-12-execution-hedge/feature.yaml (architecture section)
      - docs/05-components/observability-reporting/overview.md (extend)
    description: >
      v2.0-final определяет Observability Reporting как чистый
      "read-side" компонент: subscribes Kafka (execution.venue,
      risk.alerts) → обновляет PG/CH; читает PG/CH → serves Admin UI
      через REST API/SSE. Единственное исключение: Manual Override и
      Policy Config проксируются через OBS в API Matching Backend /
      Venue Execution Adapter.

      Conflict Note: в текущем MVP роль "Observability Reporting"
      исполняется frontend-api (Node.js), а cpp/observability — это
      минимальный Kafka logger. Полноценный OBS-сервис с PG/CH access
      + REST/SSE — отдельный компонент будущего, описан в IN-009
      но не имплементирован.

  - id: DELTA-2
    title: Refresh mode + data sources matrix per UI screen (Section 7.3)
    target: docs/02-system/features/F-12-execution-hedge/feature.yaml#uxScreens
    description: >
      Каждый из 6 UI экранов получает явный режим обновления:
      - HedgeFlow Monitor → polling ~2s, source: PG.hedgeflows+child_orders
      - Execution Live Feed → SSE/long-poll real-time, source: Kafka execution.venue
      - Hedge PnL Dashboard → polling/batch refresh, source: ClickHouse execution_reports
      - Reconciliation Alerts → polling ~5s, source: PG.hedgeflows(UNDERFILLED)+risk.alerts
      - Manual Override → REST POST → execution.intents (write-path)
      - Policy Config → REST GET/PUT → solverconfig

  - id: DELTA-3
    title: Step-by-step "what operator sees" timeline (Section 7.2)
    target: docs/02-system/features/F-12-execution-hedge/feature.yaml (operatorTimeline section)
    description: >
      10 шагов от ExecutionIntent publish до UNDERFILLED alert.
      На каждом шаге явно указано, какое поле UI обновляется
      (например: "INSERT hedgeflows → HedgeFlow Monitor: строка со
      статусом OPEN"). Полезно для QA test cases и UX flow design.

  - id: DELTA-4
    title: Architecture mini-diagram (Section 7.4)

      rate limiting сосредоточены в OBS-слое.
