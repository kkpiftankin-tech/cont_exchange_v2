## Coverage

mapped at the feature.yaml level but the dedicated docs files
(use-cases, sequence diagrams, test plan, data docs) will be created
by a follow-up docs PR before any code is written, per the
docs-before-code rule.

## Conflicts

None against existing docs at this time. F-20 references F-11 and
F-12 as **pure consumers** — no schema, topic, or service in those
features needs to change. The `execution.venue` topic schema gets
**additive** new fields (`simMode`, `simSessionId`, etc.); existing
consumers (Ledger, market_data CH ingest) ignore unknown fields by
construction (Protobuf reserved/unknown semantics).

The only architectural choice that needs an ADR before impl starts:
whether `sim.execution.venue` is a separate topic (cleaner isolation)
or whether `simMode=true` flag on the shared `execution.venue` topic
is enough (simpler routing). Spec §1.2 lists both as available;
default position in this fragment-map is "ship both during MVP and
deprecate one after operator feedback."
