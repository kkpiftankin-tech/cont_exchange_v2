## Conflict Notes (зафиксированы при регистрации, не разрешены — решение владельца)

1. **`change-routing.md` vs `agent-routing.md`.** Документ предписывает
   заменить `.claude/rules/agent-routing.md` новым `change-routing.md` (Этап
   5, п.4: «agent-routing.md удалить после переноса триггеров»). Текущий
   `agent-routing.md` (8 778 байт) уже содержит рабочие классы S/M/L/XL,
   триггеры эскалации и — после правок этой же сессии — обязательное правило
   «находка агента не остаётся только в ответе». Прямого конфликта по сути
   нет (документ сам говорит «триггеры эскалации текущего agent-routing.md
   §2 сохраняются поверх класса», §3.6), но до Этапа 5 оба файла не должны
   противоречить друг другу молча — обсудить порядок переноса явно на Этапе 5,
   не раньше.
2. **`docs/changes/CR-*.md` vs `docs/feedback/FB-*.md`.** Документ вводит
   CR как новый тип артефакта для M/L/XL реплик (§4.8), заводимый из
   `source: ui`. В проекте уже есть `docs/feedback/` (`inbox.md` → `/triage`
   → `FB-*.md`), построенный в этой же сессии ранее. Документ в §6.3
   упоминает «`/triage` — обёртка», предполагая переиспользование, но не
   уточняет судьбу уже существующих `FB-*.md`. Решение — на Этапе 4, не
   молча.
3. **Пересечение валидаторов.** `tools/consistency/check.py` (C-01…C-17)
   частично дублирует существующие `tools/traceability-checker`,
   `tools/feature-yaml-checker`, `tools/in013-checker`, `tools/link-audit.py`,
   `tools/docs-code-drift`. Документ не говорит явно «заменить» или
   «обернуть» — решение нужно на Этапе 2, с явным выбором, не задвоением
   CI-проверок.

Эти три пункта — не блокеры регистрации документа (ingested-as-plan,
документ сам предполагает поэтапное исполнение с подтверждением), но
обязательны к явному решению на названных этапах, не к молчаливому выбору
по ходу кода.
